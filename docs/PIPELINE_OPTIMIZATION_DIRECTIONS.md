# 管線最佳化的兩個方向（以及避免過擬合）

狀態：規劃文件。**尚未執行任何一條**，這份文件只是把兩個方向分開，並訂下分開記錄的規則。

對象：`qbr/` 考題建立管線。相關：[`../qbr/AGENTS.md`](../qbr/AGENTS.md)、
[`../qbr/ENGINE_STRATEGY.md`](../qbr/ENGINE_STRATEGY.md)。

---

## 為什麼要分成兩個方向

兩個方向都會讓「這一卷讀得更好」，但它們**對通用性的作用相反**：

| | 方向一：橫向展開 | 方向二：縱向最佳化 |
|---|---|---|
| 做什麼 | 繼續拆不同類科 | 針對某個科目的原則做最佳化 |
| 目標 | 讓**通用腳本**更通用 | 讓**這個科目**更準 |
| 成功的樣子 | 新類科不修程式就能跑 | 這個科目的錯誤率下降 |
| 副作用的風險 | 慢，可能一直找不到盲點 | **快，而且會把通用腳本過擬合掉** |
| 錯誤的徵兆 | 每拆一個類科都要加一條規則 | 修好 A 科目，B 科目退步 |

**合併記錄這兩者是最危險的做法**，因為方向二的成果看起來像「管線整體變好了」，
於是它會被當成通用改進累積下去，直到某一天某個沒測過的科目整卷失敗 ——
而那時候已經很難指出是哪一條「改進」造成的。

所以：**分開記錄，分開驗收，分開回退。**

---

## 方向一：橫向展開 —— 找通用性的盲點

**做法**：對每一個新類科，跑既有的 `batch_run` + `batch_package`，**先不改任何程式**，
然後看它壞在哪裡。

**量什麼**：

```sh
.venv/bin/python scripts/batch_run.py     --category <新類科> --work /tmp/work
.venv/bin/python scripts/measure_corpus.py       # 全語料分類
.venv/bin/python scripts/measure_skeleton.py     # 骨架通用性（兩引擎）
.venv/bin/python scripts/compare_skeleton.py
.venv/bin/python scripts/survey_categories.py
```

**判準**：

- **新類科不修程式就能跑完** → 通用性成立。
- **新類科需要一條新規則** → 先問那條規則是**紙張的性質**還是**這個科目的內容**。
  - 是紙張的性質（版面、字型、欄數、標記樣式）→ 可能真的是通用規則的漏洞，可以進通用腳本，
    **但必須在已跑過的類科上重跑驗收**（見下）。
  - 是這個科目的內容（某個專有名詞、某種題型、某個公式寫法）→ **這是方向二**，不要放進通用腳本。

**已完成的橫向量測**：整個語料的骨架通用性 —— **3,516 / 3,516 兩個引擎一致**。
在那個量測的範圍內，「骨架」不是需要逐科調的東西。

**還不知道的**：真正的盲點通常不在骨架，而在**少數、昂貴、且不容易抽樣的**紙張性質上
（例如某科特有的雙欄＋跨頁圖片、某科特有的更正答案格式）。
所以方向一的工作是**擴大抽樣**，不是**加規則**。

---

## 方向二：縱向最佳化 —— 針對特定科目的原則

**做法**：對一個科目，找出它系統性出錯的那**一類**，寫下**原則**，而不是寫下這個科目的例外。

**這條線最容易被做壞。** 三種做壞的方式：

1. **把例外寫成規則。** 「這一題的答案是 D」不是規則。規則必須能回答「為什麼」，
   而且理由必須是這張紙的性質。
2. **把調整寫成通用。** 放寬一個門檻讓 A 科目過了，B 科目就開始收進不該收的東西。
   門檻要**離兩群都遠**，而且要**掃描，不要推導**。
3. **用科目名稱當條件。** `if category == "藥師(一)":` 是過擬合的定義。
   若真的只有某科如此，那它應該是一條**以量測為條件的規則**
   （「當一頁有兩套私用區字型家族且其中一套的長度等於選項數時…」），不是以科目名稱為條件。

**合規的縱向修改長相**：

- 條件是**紙張的性質**，不是科目名稱。
- **兩個引擎都成立。**
- 附上**負對照**：另一條規則會丟掉什麼。
- 在**沒被調過的科目**上重跑，證明沒有退步。

## 兩者共用的驗收閘門

任何修改（橫向或縱向）在合併前都要過這四關：

| 關卡 | 指令 / 依據 | 失敗代表 |
|---|---|---|
| 1. 全套測試 | `qbr/.venv/bin/python -m pytest tests/ -q` | 動到了什麼 |
| 2. 整卷 golden | `tests/test_merge_golden.py`（80 題逐欄） | 讀同一張紙的結果變了 |
| 3. 骨架通用性 | `scripts/measure_skeleton.py` + `compare_skeleton.py` | 通用性退步（**這一關專門抓過擬合**） |
| 4. 外部標準 | 人工切題庫（**不是自己產生的資料**） | 真的錯了；外部標準的**漏掉是錯，沒收錄不是錯** |

**第 3 關是方向二的安全網，也是這份文件存在的理由。** 一個「針對某科」的修改若讓骨架
通用性從 3,516/3,516 掉下來，它就是過擬合，不管那個科目變得多好。

---

## 記錄規則

- 方向一的成果寫進**通用文件**（`qbr/AGENTS.md`、`README.md`）。
- 方向二的成果寫進**科目專屬文件**（`qbr/reports/` 下一份以科目命名的報告），
  並在裡面明說「這是針對性最佳化，不是通用規則」。
- **任何修改都要能回答「它會讓哪個已經在跑的科目變差」**。答不出來，就是還沒量。

---

## 未解

1. **第 3 關目前只有「骨架」一個維度。** 骨架一致不代表圖片、註記、更正答案也一致 ——
   那些還沒有等價的全語料量測。
2. **科目專屬報告還沒有目錄。** 第一個方向二的修改出現時，要一起建立。
3. **「兩群都遠」的門檻目前靠人工檢視分佈。** 沒有自動檢查阻止一個門檻被放到兩群中間。
