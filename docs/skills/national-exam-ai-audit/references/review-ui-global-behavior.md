# Review UI 全局行為契約

本檔是 Review UI 的系統級互動契約。題目、答案、題組與圖片仍有各自權責，
但搜尋、排序、刷新、工作階段穩定性與進度標示必須採用同一套規則。

## 1. 查詢分層

每次清單查詢依序套用：

1. 模式權責：`question`、`answer`、`group`、`visual` 只取該頁負責的資料。
2. 資料範圍：類科、科目、年份、考次。
3. 工作狀態：系統、人工、AI 或該模式的審核狀態。
4. 文字搜尋：搜尋有效題幹、全部選項、答案、人工校正版、人工註記、AI 疑點與識別鍵。

只要搜尋框非空，文字搜尋預設跨越第 3 層的狀態頻道，但保留第 1、2 層。
因此搜尋簡體字時，不會因「未看過」「AI 有疑點」「答案未看過」或其他狀態下拉選單漏掉
同一模式、同一資料範圍中的已看題。圖片模式的跨狀態搜尋仍只搜尋圖片權責範圍；
題組模式仍只搜尋題組候選，不得把所有題目混入。

搜尋必須以人工校正版覆蓋 MinerU 原文後的有效內容為主，同時保留原文與歷史註記為可搜尋證據。
題幹可搜尋但選項不可搜尋、或題目模式可搜尋但其他模式不可搜尋，都視為回歸錯誤。

## 2. 刷新排序

伺服器每次真正查詢／刷新後，清單使用一致的優先序：

1. 該模式尚未看且有可處理異常。
2. 該模式尚未看、目前無異常。
3. 該模式已看但仍待修、阻擋或保留疑問。
4. 該模式已完成。

同一層內才依類科、科目、年份、考次、題號排序。明確選擇「已看過」等狀態時，
下拉選單的範圍先於排序；排序不能把範圍外資料插回來。

各模式的「已看」定義不可混用：

- 題目：最新題目人工事件不是 `unreviewed/reset_review`。
- 答案：答案表內可核題目已完成答案人工事件。
- 題組：題組人工狀態已確認題組或非題組。
- 圖片：人工狀態是有圖正確、圖片錯要改、沒有圖，或已有人工補圖。

## 3. 工作階段穩定性

人工按下通過、阻擋、保留疑問、答案判定、題組判定或圖片判定後：

- 立即更新目前列的徽章與內容；
- 自動前進到下一筆；
- 不立刻把剛處理的列從瀏覽器清單移除，也不在背景重新排序；
- 允許按上一題回看剛才的判定；
- 顯示「本輪已更新；刷新後重排」。

只有頁面刷新、按「刷新並重排」、更改範圍／狀態條件或重新輸入搜尋時，才重新向伺服器取清單。
刷新不得用 `focusKey` 把篩選外的已看題強塞回頂端。跨模式快照不得用不同條件的舊結果暫時覆蓋畫面。

## 4. 每題流程狀態

左側每個項目除來源、系統、AI、人工徽章外，必須顯示一個單一流程標籤：

- 題目待人工／題目待處理／答案待人工／題答已通過／待同步正式庫／正式可用；
- 答案待人工／答案有異常／答案已看；
- 題組待人工／題組已判定；
- 圖片待人工／圖片待修／圖片已判定。

流程標籤是有效事件投影，不是另一份可寫狀態。Agent 不得直接寫入流程標籤。

## 5. 寫入與 Agent 邊界

- 搜尋、排序、徽章與清單穩定性是 UI 投影，不得修改 candidate 或人工事件。
- 人工事件與 AI 回饋／學習事件維持 append-only。
- AI 只能寫 advisory；只有人工操作或明確核准的 repair gate 能改變人工狀態。
- Agent 自動化必須讀取同一有效內容與同一狀態投影；不得另建一套「模型認為已完成」的平行狀態。
- 未來自動通過若獲准，也必須留下規則版本、證據、輸入指紋與可回復事件，並沿用本檔的刷新排序與流程狀態。

## 6. 變更驗證

每次修改 Review UI 至少驗證：

1. 四種模式在全部／未看／已看等狀態下的刷新排序。
2. 搜尋題幹、A-D 選項、人工校正版與註記；搜尋時跨狀態但不跨權責。
3. 完成人工動作後列仍留在原位，上一題可回看；手動刷新後才移動或消失。
4. 清單流程標籤與右側細節、SQL 最新事件一致。
5. 快取鍵包含模式與完整查詢條件；不得顯示其他頻道的舊快照。
6. 既有人工校正、補圖、解除綁定與 `reset_review` 的資料優先序不受影響。
