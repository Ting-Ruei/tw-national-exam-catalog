## 6.1 驗收標準（已決定 2026-09-20）

### 決定

> **驗收標準 = 出貨的每一個欄位，都必須被第二個引擎在它自己的讀數裡，於同一個邊界找到。**
> **找不到的欄位，就是必須看人（或看模型）的清單；而「找不到的數量」就是驗收數字。**

**不是**「兩引擎的文字相同」。那個標準從來就不可達成，而且理由已量過：引擎 A 有字級、引擎 B 沒有
（上下標）；引擎 B 把選項記號與每一個折行放在自己一列，A 沒有（`ENGINE_STRATEGY.md` §4.1）。
**一個不可達成的標準不是嚴格，是沒有數字。** 可達成的標準才會產生「還要看多少題」。

### 為什麼是「每個欄位」而不是「整卷文字」

我把 120 卷用「整卷文字相似度」量過，結論只有一個：**它永遠不會是綠的**。

| 量法 | 結果 |
|---|---|
| 40 卷 `extract.compare`（整卷 blob） | 31 `TEXT_DISAGREEMENT`、9 `STRUCTURAL_DISAGREEMENT`、**0 `EXACT`** |
| 80 卷「B 領讀再切題」逐欄比對 | 14.21% 欄位「無法解釋」——**幾乎全部是同一個儀器性質** |
| 120 卷「B 領讀」精修後 | 9.06% 仍「無法解釋」，集中在 **110 / 9,320 題** |

那 9% 不是紙本的爭議，是 **B 領讀切題比較差**：B 把記號放自己一列，所以 B 領讀的選項
每一格都錯開一格（量到 558 題）。**把儀器能力差異算成缺陷，就是過去的規則爆炸。**

### 可執行版本（量到 160 卷，`qbr/src/qbr/continuation.py`）

把「選項自己的文字範圍」當成單位，而不是把「整卷文字」當成單位：
一條選項從它的記號到下一個開頭的東西（記號或題號），中間全部是它的續文，
可以跨好幾列（引擎 B 常把一個選項拆成三、四列）。

| 量測 | 數字 |
|---|---|
| 讀取的題數 | 12,840（160 卷） |
| 引擎 A 自己看到「選項被截斷」 | 658 |
| 引擎 B 自己看到 | 2,207 |
| **兩個引擎都看到** | **385 欄位 / 265 題（2.06%）** |
| 被截斷的卷 | **72 / 160 卷** |

**「兩個引擎都看到」才是可用的門檻。** 單一引擎的 658／2,207 差一個量級，因為兩個引擎的
折行切法不同；**但同時被兩個獨立儀器看到的，不是任何一個的切法造成的。**
用單一引擎會得到兩個不好的結果：2,207 會淹掉審題的人，658 會漏掉一半的真案例。

> **我自己的臨時腳本量到 631／9,157／463，模組量到 658／2,207／385——兩個都真的，但不是同一件事。**
> 差別在「出貨欄位」怎麼取得：臨時腳本用 `analyse_items`，模組用 `segment_best`。
> **模組現在是權威**（它有負向對照、有測試），文件跟它。一個指標有兩個數字，就是有兩個可以
> 不一致的地方——所以我沒有保留舊數字當「另一個說法」，只留這一段說明為什麼它們不同。

### 這個標準已經抓到一個真缺陷（不是假說）

`quality_status=pass`、`disputes=None`、`dispute_severity=None`。

**這是目前為止找到最大的單一未標記缺陷類別**——比 `option-shape`（437）大，而且
`option-shape` 至少會被標記。

### 機制（在 `repair.py` 裡讀出來的，不是猜的）

`segment_questions` 有一個「折行測試」，但**只給題幹的錨點用**
（`_looks_like_a_wrap`，`repair.py:776`）：一條不開頭的短行，若前一句沒結束，就算前題的續行。
選項**沒有**對應的測試：`repair.py:1006` 之後，一旦選項已開始，
任何不是選項記號的行都落到 `current["stem"].append(line)`。
所以**選項的續行被交給題幹，而選項被留在折行處**。

## 6.2 這個缺陷已修（2026-09-21），並且量到下降

### 做了什麼

三段的第一段（**偵測**）就是修復本身，而且不需要第二、三段——因為把續行交回選項，
缺陷就在**出貨之前**消失，不是先標記再讓人審。我加了 `_continues_an_option`（`repair.py`），
與題幹的 `_looks_like_a_wrap` 同構：一條不開頭、不是頁尾／節標題／metadata／純標點、
有文字的行，在選項已開始之後算**最後一個選項**的續行（`join_lines`，與題幹用同一條接字規則）。

**刻意不是**長度測試（題幹那條用 `<= 14`，因為題幹的折行是短語）。選項的續行常常很長：
兩個引擎都看到的案例裡有一個 24 字的尾巴。加上長度上限會擋掉大多数真的損失。

### 量測工具本身錯了三次（記在這裡，因為它是最容易再犯的錯）

我寫的 `verify_option_continuation.py` 前兩版都給出假答案：

| 版本 | 測什麼 | 為何是假的 |
|---|---|---|
| v1（原版） | 對**每個引擎自己的讀數**都算 loss | 出貨欄位由 A 產生，再用 A 的讀數驗 A 的輸出——**同義反覆**，修復後回報 0 |

| v3（現行） | A 把**欄位+漏字印成連續一段** | 兩個引擎獨立同意紙本在那裡續下去，而出貨欄位停住 |

v2 的 1,784 出現在**已修**版本上，這是抓到它的方式。**一個壞掉的量測工具看起來像一個壞掉的產品。**

### 剩下的 1 筆不是缺陷，是升級

### 三段順序的更正

第 6.1 節說「先偵測、再標記、再驗收」。實際做下去發現**當修復等於偵測時，不需要新增 dispute kind**：
選項不再被截斷，就沒有東西可以標記。`option-continuation-loss` 這個 kind **刻意沒有加**——
加一個永遠不會出現的 kind 就是死程式碼（`engine-disagreement` 就是前例）。
驗收數字仍然要報（就是本節的 344 → 1），因為它是**可下降的數字**。

### 標準的三段（照這個順序做，不要跳）

| 段 | 做什麼 | 為何是這個順序 |
|---|---|---|
| **1. 偵測** | 在 `repair.py` 為**選項本體**加上與題幹同構的折行測試 | **已做（6.2）**：修好後續行歸位，不需要再標記 |
| **2. 標記** | 新的 dispute kind，例如 `option-continuation-loss` | **刻意沒做**：偵測即修復時，這個 kind 永遠不會出現 |
| **3. 驗收** | 報「兩引擎都看到」的欄位數 | **已可下降**：344 → 1（6.2），這是給人看的數字 |

### 這條標準自己的負向對照

一個新規則必須在舊碼上失敗，否則它什麼都沒證明。所以：

- **新測試必須在未修改的 `repair.py` 上失敗**（目前 q7 的選項 A 會被截斷）。
- **同時要在兩個引擎上都失敗**：只在 A 上成立的規則就是 overfitted（`ENGINE_STRATEGY.md` §4.3）。
- **不能把「B 領讀比較差」算成缺陷**：那是儀器性質，量測時必須用「同一讀數內的選項文字範圍」，
  不是「B 領讀的切法」。我在這一輪犯了這個錯四次（14.21% → 9.06% → 2.34% → 2.06%），
  **每一次都是量測工具重製了它要量的缺陷。**

### 與模型的分工（這條標準不取消那一條，它給模型一個可判的問題）

「兩引擎都看到」是**確定性的**，所以它先跑、免費、可重現。它把清單縮到 265 題／160 卷。
**模型不需要看全部 78,690 題，只需要看兩個儀器互相不同意的那些。**

而且這個問題是**封閉的、有可核對答案的**——正是本專案已經證明模型可靠的那一種工作
（不是「找缺陷」，那量過只有 12–16% 精確率）。我實測了（`scripts/ask_option_continuation.py`）：

| 引擎 | 判為「是」（同意兩引擎） | 還原出的漏字 | 時間 |
|---|---|---|---|
| **`qwen3.8-flash-next`**（DGX 8888） | **10 / 10** | 與 ground truth **逐字相同**，只有拉丁詞旁多餘空白 | 1.1–2.9 s/題 |
| **`ornith-1.5-mtplx-35b`**（18120） | **10 / 10** | 同上 | 2.4–11.2 s/題 |

## 6.3 題數不符：三個缺陷，不是六份壞卷（2026-09-21）

六份 `醫師(二)` 卷長期被 S3 以 `count-mismatch` 擋下（讀成 2 / 15 / 56 / 67 / 71 題，滿分 80），
看起來像六個互不相關的病。實際上是**三個缺陷**，現在都修好了。
完整報告：`qbr/reports/count_mismatch_three_causes.md`。

### 缺陷 A：一個字被讀成兩個（`extract.py`）

這些卷的排版程式把一段文字**畫兩次**（偽粗體，位移約 0.24pt）。
`read_spans` 把一條視覺線上的 span 首尾相接，交界上的字就出現兩次：

```
span 1  x=[215.40, 435.35]  '…尤其是貧血。血液'
span 2  x=[424.32, 545.27]  '液中沒有發現對抗紅血球'   ← 把「液」又畫了一次
首尾相接 → 血液液中
```

**判定這是缺陷不是特性的依據**：PyMuPDF 原生 `get_text("text")` 和引擎 B（poppler）
讀同一段都得到 `血液中`（**各 1 次**），只有 `read_spans` 得到 `血液液中`。
兩個獨立的讀法早就同意，只有我們不同意。

**為什麼會擋掉整份卷**：同一件事也發生在**題號**上——`34` + `4` → `344`，
而題號規則是「必須是前一題的後繼」，`344` 不是 → 這一題被拒 → 從此整份卷崩掉。
`1031_醫學(四)` 因此讀成 2 題。

**修法**：兩條幾何規則，各帶一個文字條件（`extract.py`）：

| 規則 | 幾何 | 文字條件 |
|---|---|---|
| `_covered_prefix_length` | 後一個 span 由前一個的**右方**開始，且與它的尾端重疊 | 被覆蓋的字元已在文字裡 |
| `_is_a_redraw` | 後一個 span **落在前一個裡面** | `text in previous`（證明已在文字裡） |

兩條都只丟掉「已經在文字裡」的字元，所以不可能遺失東西。
**必要護欄：`right[0] <= left[0]` → 不處理。** 試題表頭是被畫四次的同一段，
每次往左一點；少了這個護欄，表頭 `科目名稱：臨床血液學與血庫` 會被讀成
`科目名稱科目名稱科目名稱科目名稱：臨床血液學與血庫庫學`——**刪掉了真字元**。
刪掉真字元比留下重複更糟，所以這條寫成測試。

量到：自創的重複字對（全 841 卷，原生引擎完全沒有的）**595 → 257**。

### 缺陷 B：以「數字＋年」開頭的題幹被當成表頭（`repair.py`）

`is_year_line` 的判準是 `^NNN年`，所以 `56 年老女性…`、`76 年底時…` 全被當成試題表頭
→ 視為 chrome 跳過 → 整份卷從那裡斷掉。

另一條 `_is_year_running_head` 看起來在收拾這個，但量出來：

| | 數量 |
|---|---|
| 被它擋下的行 | 381 |
| 其中真表頭 | 352 |
| **其中真表頭的數字正好是「後繼」**（＝這條規則必要的次數） | **0** |
| 其中真題幹（＝它誤擋的次數） | **29** |

**352 個真表頭，後繼規則本來就會全部擋掉。** 這條規則的必要貢獻是 0、誤擋是 29，
所以它不是被收緊，是被**刪除**：一條規則、一個地方（兩條做同一件事的規則就是兩個
可以不一致的地方，而它們確實不一致）。

**修法**：讓「表頭」看**年後面接什麼**。真表頭是考試自己的名字（`115年第一次專門職業…`），
年後接場次或考試種類（`第`、`專`）；以年開頭的題幹，年後接的是它的主詞（`老`、`齡`、`金`…）。
全庫 `NNN年…` 行中是表頭的 **2,186 條，全部** 年後接 `第`/`專`；其餘 19 行全部是題幹。
另外把比對改成 **NFKC 折疊**，因為有些卷印的是 `年`（U+F98E），和 `年`（U+5E74）不同碼位。

量到（全 3,516 卷）：**19 卷改變、總題數 230,287 → 230,868（+581）、減少 0 卷**，
每一份都落到完整題數（`43→100`、`7→80`、`76→80`、`31→40` …）。

### 為什麼要拆成兩個原因

| 卷 | 缺陷 A | 缺陷 B | 缺陷 C |
|---|---|---|---|
| `1001_醫學(三)` / `1031_醫學(三)` / `1031_醫學(六)` / `1031_醫學(四)` | ✓ |  | 1001 另需 C |
| `1002_醫學(五)` / `1012_醫學(五)` | ✓ | ✓ |  |

**單獨修 A 不夠，單獨修 B 也不夠**（實測：A alone 改變 0 卷、B alone 改變 7 卷、
both 改變 19 卷）。一份卷可以斷在同一個地方，卻疊了好幾層原因。

### 缺陷 C：答案卷少算一題（`golden_path.py`）

`1001_醫學(三)` 修好 A、B 後**仍然沒進佇列**：閘門報
`count-mismatch:items=80 expected=79(answer-sheet)`。
`_sheet_question_count` 原本取「解析出表格的最高題號」，但**表格承載不了這個資訊**：
第 80 題是 `#` ＋ 備註「一律給分」，而送分題在表格裡**沒有任何字母可以放**，
所以它從表格消失了。

量到（全部 4,833 張答案卷）：**每一張都自己印 `題數：NN題`**；舊法與它不同者 **79 張**，
而**79 張全部是「正好少一」**（`79/80`、`49/50`、`99/100`…）——一個形狀的原因只有一個。

修法：讀**卷自己印的那一句**（`題數：NN題`），它是卷對自己長度的陳述，也是**印刷形式**，
所以對沒見過的卷也成立。舊法保留為退路（不印題數的卷仍用表格的兩界）。
效果：`expected=79` → **80、`verdict: publish`**；全庫**增加 1 卷、減少 0 卷**。

**教訓：**「題目讀對了」不是「卷出來了」。我把「六份卷都讀成 80 題」當成「六份都修好了」，
但 `1001_醫學(三)` 從來沒進佇列——**只有重建佇列、逐卷核對題數才看得到。**

### 這一節的教訓

第一版的修法只處理「一個字的重疊」，忽略「整段被重畫」。它讓總數看起來變好
（6,389 → 4,887），但**六份卷毫髮無傷**——只看總數就會得到「有改善」的錯誤結論。
抓到它的方式是**去看那六份卷的 span 幾何**（`34` + `4` 落在同一個框裡），不是看聚合數字。
**聚合數字可以掩蓋機制。**

## 7.5 修復迴圈（把人的 block 變成規則；2026-09-21 建，已跑三圈）

使用者描述的迴圈，實作在 `qbr/scripts/repair_loop.py`。**它是單向的**：

```
人標 block ─► 既有偵測器能解釋嗎？
                ├─ 能 ─► 不是缺口（是偵測結果沒在畫面上被看到）
                └─ 不能 ─► 這才是要建規則的地方
                            ─► 新規則上線 ─► 全庫重掃
                                  ─► 有人判斷過的 → reset_review（附加，不覆寫）
                                      沒人判斷過的 → 不動
```

**為什麼不能反向跑。** 一條題目被重開，只因為某個偵測器在它上面觸發。人的沉默不是核准，
人的核准不會在沒有可機檢理由下被翻掉，而 `needs_review`（「我無法判斷」）**不是輸入**——
無法從「我不確定」長出一條規則。

```bash
cd qbr
.venv/bin/python scripts/repair_loop.py --queue data/review-queues/live
```

### 新規則要過的門檻：block 率，不是命中數

「它抓到幾題」不是判準。判準是「它抓到的題目裡，人真的認為有問題的比例」。基準線是這個題庫
的 block 率（298 題已判 / 16 block = **5.4%**）。

| 規則 | 候選題數 | 已判 | block | block 率 | 決定 |
|---|---|---|---|---|---|
| `substituted-script` | 164 | 4 | 4 | **100%** | 建 |
| `flattened-offset` | 174 | 6 | 6 | **100%** | 建（見 §7.5 末）|
| Kangxi radical 未折疊 | 2,293 | 71 | 3 | 4.2% | **拒絕（低於基準線）** |
| 提到圖但圖不在自己身上 | 887 | 7 | 1 | 14.3% | **擱著（樣本太小，且翻掉 6 題已接受）** |

第三條拒絕的理由是決定性的：它會把 **63 題已經被人類接受**的題目翻成「需重看」，
換來 2 題本來就 block 的。第四條把「提到圖」與「需要圖」混為一談。

**不是「不確定所以不做」，是量完之後決定不做。** 數字在這裡，下一個人可以重跑。

### 使用者的觀察：不是每種題型都一樣難（2026-09-22）

原話：「**全正常文字的題目，現有的管線引擎很完美**，但是對於上下標、科學符號、表格形態被
誤認為文字、數學符號以「圖型」穿插在文字中，就會出現很大的問題」。

這跟量測一致，而且把缺陷分成了兩類——它們要求的**修正方式不同**：

| 形狀 | 例子 | 為何純文字規則做不到 |
|---|---|---|
| 上下標被壓平 | `C=80e-0.35t` | 讀完之後跟紙本本來就印平的**是同一字串** |
| 表格被誤認為文字 | 表格欄位串成一行題幹 | 行列關係在 page 上，不在字串裡 |
| 數學符號以圖形穿插 | 公式是圖片物件 | 圖片不是文字，OCR 也讀不出層次 |
| 科學符號 | `PO₄³⁻`、`t₁/₂` | 同上（無 Unicode 上標形式的字元）|

**共同點：証據都是幾何／位置，不是字義。** 所以修正一律是同一形狀：
在**還有頁面的地方**把幾何留下來（像 `lost_glyphs`、像 `flattened_offsets`），
帶到題目上，再由 `disputes.py` 讀。**不要**等讀成文字再讓模型猜——那是把量得到的
變成不可核對的。

這也是為什麼「表格」與「圖形數學符號」這兩個還沒建的類別，**不會**從文字規則長出來，
而要先量它們在 page 上的幾何（欄列、圖片物件與題目 band 的關係），再決定要不要建。

### 兩次「規則太窄」的實例（都是同一個陷阱）

1. **`⻑` U+2ED1 那個缺陷**——從第一個例子寫出來的規則，差一點拒絕第二個。
2. **`substituted-script` 的漢字鄰居條件**——舊註解說「要求漢字鄰居，因為考卷合法印英文與希臘文」。
   **那個理由是假的**：英文是 `LATIN`、希臘文是 `GREEK`，本來就在原生清單裡，從來沒有被鄰居條件擋過。
   它實際擋掉的是 1,042 處裡的 **567 處（54%）真缺陷**，包括選項整串是 `ћќѝўџ` 的那 555 處
   ——整個題庫壞得最徹底的題目。修正後：157 → 164 題、475 → 1,042 處、3 → 4 個人類 block，
   而**已接受的仍然是 0 題**。

### 不是每個 block 都是管線的錯——但「不是管線的錯」這句話也要有證據

第三圈剩下的 7 題（`111020:305 q059–q073`，藥動學計算）我先用手看紙本，結論是「沒有抽字缺陷」。
**那個結論錯了。**

把同樣 7 題送進 `ask_about_blocks.py`（Splash，`reasoning_effort=none`）之後，模型指出紙本幾何上的
事實：同一張紙、同一題，兩個並排的指數

```
size=5.5 y=550.08  '-2t'     → 轉成上標 ⁻²ᵗ
size=5.5 y=550.08  '-0.5t'   → 留成平的
```

存下的是 `Cₚ＝10e⁻²ᵗ＋2.5e-0.5t`。機制在 `extract.py`：`_mappable_offset` 要求**每一個字元**都有上標
形式，而 `.` 沒有，所以**整個 run 留在平的**，旁邊沒有小數點的兄弟卻轉上標了。這是一個**可機檢**的
缺陷（同一條式子內部不一致），不是內容爭議。

**教訓：手看紙本得出的「不是缺陷」，與模型寫下「哪裡錯、怎麼修」是兩種不同的證據。**
前者是印象，後者是可回頭查的紀錄——這也是 `question_ai_findings.jsonl` 存在的理由。
「不是抽取缺陷」的判定要跟「是缺陷」一樣有依據，不能因為它比較省事就免舉證。

模型是**輔助**，不是判決：它沒有寫入任何人類決定，`rule_worthy` 也只是建議。規則仍然
只由 `disputes.py` 的區塊率決定（上表）。但「模型說的話可以推翻手動結論」這件事必須寫下來，
否則下一個人會重犯同一個錯。

### 這條規則後來真的寫出來了（2026-09-22）：`flattened-offset`

上一段的結論「這是一個**可機檢**的缺陷」當時只對一半：它可機檢，但**不能靠文字機檢**。
一旦讀完，`e-0.35t`（本來是上標、被印平了）與 `e-0.35t`（紙本本來就印平的）是**同一個字串**。
證據在**頁面的幾何**上，而 `disputes.py` 依設計不碰 PDF。

所以做法跟 `lost-glyphs` 一樣：**在還有頁面的地方把證據留下來**。
`extract.refused_offsets()` 讀幾何，回傳「位置是上下標、但 offset 表拼不出來」的 run；
它隨題目一路帶到審核畫面（`flattened_offsets`），`disputes.py` 據此報 `flattened-offset`。

順手拆了一件事：`_offset_direction`（幾何說它在哪裡）與 `_offset_kind`（表能不能拼出來）
原本是**同一個答案**，於是「拼不出來」時整個方向一起被丟掉——而那個方向正是證據。
拆開後轉換行為完全不變（318 個測試不動），但方向可以回報。

**量測（全庫 79,090 題）**

| | 題數 |
|---|---|
| 規則命中 | 174 |
| 其中有人判過 | 6（block 6、accept 0）|
| **block 率** | **100%**（基準線 5.4%）|
| 翻掉已 accept 的 | 0 |

命中集中在 `藥師(一) 藥劑學與生物藥劑學` 36、`醫事放射師 醫學物理學與輻射安全` 19、
`醫事放射師 核子醫學診療原理與技術學` 16——**這就是「規則要不要限定考科」的證據**。

**第一版錯了 67 倍，原因要留著。** 第一版只要求「含數字＋擋住的是標點」，
全庫回 **1,806 題**：題目自己的**題號**（`4.`）也在小字、也偏移、`.` 也擋得住。
缺少的條件是「**必須接在東西後面**」（host）——實測 `1062_物理治療師_心肺疾病與小兒物理治療學`：
39 個誤報**全部在行首**、0 個接在東西後面；而真正的被壓平公式全部接在左邊的 span 後面
（`-1.5t` 接在 `= 70e` 之後、`1/2` 接在 `t` 之後）。
**行首的數字是那一行的標籤；上下標是算式的一部分，而算式左邊一定有東西。**
這是幾何，不是語意，所以屬於 extractor。補上後 1,806 → 174，且 174 題全是藥動學公式。

**一個類別的考別/考科分佈是它的一部分。** `ask_about_blocks.py --report` 現在對每個類別印出

（舊紀錄在 `category` 欄位存在之前寫的，是 append-only、**不改寫**，所以是報告時解析）。
考別也存進每一筆新 finding（`category` 欄位）。

## 7.6 AI 審查紀錄（模型說「哪裡錯、怎麼修」；2026-09-21 建）

使用者的要求：**地端 AI 在為題目抓錯時，要寫下它認為哪裡錯了以及怎麼修**，因為有些題目的錯誤
非常奇怪，屬於國考題的意外；有 AI 審核的紀錄，之後才能對少數個體單獨探討。

實作：`qbr/src/qbr/ai_findings.py`（記錄格式）＋ `qbr/scripts/ask_about_blocks.py`（問與讀）。
紀錄流是 `review-ui/question_ai_findings.jsonl`，**在 `review-ui/` 裡面**——因為只有那個目錄的
具名事件流會被重建攜帶、被 `deploy_station.sh` 保護、被備份迴圈帶走。放在旁邊會**靜默消失**。

**它 append-only 到連改寫函式都沒有**（沒有 `update`/`save`/`rewrite`），而且沒有 `action`、
沒有 `reviewer`——這才是「它不是人類決定」的保證，不是它放哪個目錄。紀錄存**原文證據與原文提示詞**，
因為「沒有證據的筆記只是摘要」，而這個專案的規則是「看不到的證據不是證據」。

### 引擎：Splash（8088），全庫都送它

用**量測**選的，不是用大小選的。在 `108030:305 q076` 上 Splash 報了 `FIGURE_MISSING`，而 ornith 說
NONE；在 `q049` 上它指出康熙部首——那正是決定性掃描**明確判定無害**的東西。一個引擎回答全部也有
紀錄上的理由：兩個引擎回答同一題，就是兩份會互相矛盾的筆記，而且沒有規則說哪一份對。

| 設定 | 每題耗時 |
|---|---|
| 思考開啟（預設） | 21–54 秒（吃 1,164–3,262 reasoning token） |
| `reasoning_effort=none` | **3–5 秒**，找到同樣的缺陷 |
| 並發 1 / 4 / 8 | 4.9 / **2.0** / 1.95 秒 |

全庫 79,090 題約 **44 小時**，可中斷續跑（`--resume` 只跳過**已經有 finding** 的題目，所以失敗的
呼叫會被重試而不是被跳過）。

```bash
cd qbr
# 只問人 block 而沒有偵測器解釋的題目
.venv/bin/python scripts/ask_about_blocks.py --queue data/review-queues/live
# 全庫（使用者的規則：管線跑完後，全部題目都要給模型看一次）
.venv/bin/python scripts/ask_about_blocks.py --queue data/review-queues/live --all \
    --concurrency 4 --resume
# 讀回來
.venv/bin/python scripts/ask_about_blocks.py --queue data/review-queues/live --report
```

### 兩個一定要記住的實作陷阱

1. **思考必須關掉。** 18120 上思考開著時，引擎把 8000/8000 token 全花在推理、回傳**空字串**。
   而且**每個引擎的開關拼法不同**：Splash 用 `reasoning_effort`，MTPLX 用
   `chat_template_kwargs.enable_thinking`，而它會**靜默忽略**另一個拼法——「關掉思考」的執行
   其實一直在思考，就是這樣發生的。所以開關存在引擎的定義裡（`ENDPOINTS`），不是存在呼叫端。
2. **解析器要在代碼是錯的時候也留住筆記。** `where`/`fix` 才是價值，代碼只是索引。Splash 會把缺陷
   代碼寫進 `verdict` 欄位（`"verdict":"FIGURE_MISSING"`），要求 verdict 必須是三個字之一
   會丟掉**三分之二的正確 finding**。現在：verdict 欄位裡的 `NONE` 算 OK、其他代碼算 DEFECT，
   不認識的就留成 `what_reported` 而 `what=None`。60 題的實跑：**0 題無法解析**。

### 提示詞可以被調整，而且調整要看得到

迴圈的重點就是批次之間要調提示詞，所以兩個相隔一小時的紀錄可能在回答不同的問題。`prompt_version`
（提示詞的雜湊）存在每一筆紀錄上，讓版本變成一個**欄位**而不是要人去 diff 存的文字。

`--learned` 把前幾批已經確認／已排除的形狀帶進下一批。它寫成「**已經知道的事**」，**不是**
「去找 X」——差別是關鍵：叫你找 X 的提示詞會讓你找到 X，不管它在不在。實測：告訴模型什麼已經
settled 之後，60 筆裡有 32 筆寫「已列為既知形狀」而不再重報。

```bash
.venv/bin/python scripts/ask_about_blocks.py --queue data/review-queues/live \
    --learned "substituted-script=文字層存的是別國字元，已由 disputes.py 偵測" \
    --learned "FIGURE_MISSING=若選項本身是圖片則是圖片選項、不是缺陷"
```

**這一條修掉了一個我自己造成的誤報。** 圖片選項題（選項文字空的、但有 `option_key` 的圖）在提示詞
沒說「這是圖片選項」時，模型每一次都會報「選項遺失」——從它看得到的東西來說是對的，但這個專案
早就判定那不是缺陷。實測 `105020:305:11 q052`/`q053`：Splash 把它們叫做 `rule_worthy` 的缺陷，
補上圖片證據後兩題都回 `NOT_EXTRACTION/NONE`。提示詞現在用 `image_refs`（介面用的同一個欄位）組出來。

#### 全庫掃描不能用「人已經標記過」的問句（2026-09-22 修）

提示詞是為迴圈寫的，那裡每一題**真的**都被人 block 過，所以它寫「這一題已經被人類標記為有問題」。
`--all` 把**全庫**送進同一句话之後，那句話對每一列都是**假的**，而且假在最貴的方向上：它斷定
缺陷存在、並要求把它說出來。實測：我先跑的 3 題 corpus 就是這樣回來的。一個對 79,090 題都這樣說
的掃描，是一台製造 finding 的機器，而且它會**以成功的樣子失敗**。

所以 population 現在是一個參數：`blocked`（迴圈的問法）與 `corpus`（明說「這一題**沒有**被人類
標記過」，且「**沒有發現異常是正常的答案**」）。**沉默不夠**——一個本來就在問「哪裡錯了」的提示詞，
你不講清楚它就會自己補一個。

兩個必須處理而不是記下來的後果：

1. **framing 算進 `prompt_version`。** 人被 block 的題目與隨機一列的 finding 是不同的主張、
   不同的錯誤率；兩者若同一個雜湊，最會被拿來對照的那兩組看起來就像同一次一致的量測。
2. **framing 在收集列的地方決定，不是呼叫端重讀 `--all`。** 那兩者可以不一致，而紀錄應該記
   題目**實際**是怎麼來的。`make_record` 預設是迴圈的那一種，既有的呼叫端不會靜默把自己的
   finding 改標成 corpus finding。

負向對照：把 corpus 的問句與版本雜湊改回去，
`test_the_corpus_pass_does_not_claim_a_human_flagged_the_question` 就會紅。

#### 提示詞把「機器視角」當成「答案」送出（2026-09-22 修）

使用者觀察：「**某些年份的答案看起來是錯的**」。先去量才知道那是兩種東西混在一起。

第一圈全庫掃描回來的 28 筆 `ANSWER_DISAGREES`，拆開之後只有 11 筆是真的答案爭議：

| 成因 | 數量 | 是什麼 |
|---|---|---|
| 送分被當成四個答案 | 15 | `accepted_values=[A,B,C,D]` 被印成 `答案：A、B、C、D` |
| 「或」並列被當成多選 | 4 | `B或C` 被印成 `答案：B、C` |
| 真的答案爭議 | 11 | 模型不同意答案卷（例如疫苗屬第一級而非第二級） |

**這 19 筆不是紙本的缺陷，是提示詞的。** 一題被判「送分」（一律給分）時，儲存上把每個選項都放進
`accepted_values`，好讓答案比對不會失敗——那是**機器的視角**；人在畫面上看到的是 `送分`。
`review_queue.py` 早就把這陷阱寫在 display 那一側（「一個看到 `A,B,C,D` 的人學到的是更正答案的
相反」），而它從提示詞那一側又來了一次。模型拿到一個假前提，然後做了完全正確的事：指出單選題
不可能有四個答案。

模型是對的。**是我們給它的東西錯了。** 這跟圖片選項是同一個形狀（見上一節）：模型只能就它看到的
東西回答，所以「它看到了什麼」是提示詞的責任。

修法：`is_special_correction` 與 `或` 決定讀法，且**送分要連理由一起送**
（「選項 A、B、C、D 都算對，這不是有四個答案」）。一般的答案仍然只是字母——修正不可以
幫每一個答案加裝飾。真正的多選答案 `BC` 保持 `BC`。

**還有：`prompt_version` 本來看不到這個修正。** `answer_of` 是**行為**不是提示詞文字，
只雜湊提示詞字串的話，修改前後的紀錄會宣稱同一個 prompt generation——而那正是最會被拿來
對照的兩組。所以讀法變成一個具名常數（`ANSWER_READING`）一起進雜湊，測試釘住「改它就要
改版本」。這也適用於以後：**只要「模型被展示了什麼」改變，就是新的 prompt generation。**

全庫 79,090 題裡有 393 題特殊更正、769 題 `或` 答案，所以受影響的題目有限；正在跑的那一輪
用的是舊提示詞、也誠實地帶著舊版本，跑完後重問這批即可。

## 8. 讀這份文件的三個陷阱

1. **「S2 通過」不等於「兩個引擎一致」。** 它等於分段連續性。看第 6 節。
2. **「有圖」要看 `image_refs`，不要看 `has_visual_asset`。** 後者寫死 `False`，永遠是假的。
3. **`group_position` 從 0 開始。** `0` 是組頭，不是缺號；用 `range(1, …)` 檢查會得到
   908 組全部「不連續」的假缺陷（我犯過）。
