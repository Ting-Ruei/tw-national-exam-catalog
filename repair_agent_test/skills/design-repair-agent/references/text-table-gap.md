# 「文字型表格」怎麼處理

> 設計者問題（Q14）：「以文字排列成表格的形式（因為讀取可能會被壓平成文字），這種問題要怎麼處理？」
> 對應 [`qa-log.md`](qa-log.md) **Q14**。這是與 [`crosspage-crop.md`](crosspage-crop.md)（Q13）
> **同一個病的另一個症狀**，也是 [`vector-figure-gap.md`](vector-figure-gap.md)（D4）的**第三個出口**。

## 0. 一句話

**「文字型表格」＝文字層看起來是文字，但欄位的意義只存在於排版裡。**
純文字讀法把它壓成一串 → 欄位對不起來 → **失去意義**。
**唯一正解是截圖**——設計者自己在註解裡寫了 **16 次**「用截圖解決」。

## 2. 現況：機制已經有，但不夠

`vision.TABLE_LINES_RULE` 請讀法**逐字引出表格自己的行**（一行一個字串，`CYP2D6 10 1`
而不是三格 `CYP2D6`／`10`／`1`），`quoted_lines_region` 再把那些行**在紙上量出來的行**裡定位，
切成 `paper-table` 裁切。**這條路已在跑**。

| 事實 | 數字 |
|---|---|
| AI 讀法回報 `table_lines`（≥2 行）的題 | **60** |
| 已有 `paper-table` 裁切的題 | **32** |
| **沒有表裁切** | **28** |

## 3. 剩下 28 題的三個成因（實測，用官方 PDF 判別）

| 成因 | 題數 | 說明 |
|---|---|---|
| **表格在別頁** | **18** | 表格與題幹不同頁 → **就是 Q13 的跨頁病** |
| **表格是內嵌圖（`xref=0`）** | **4** | 表不是文字，是 PDF 內嵌點陣圖 → **就是 D4 缺陷 B** |
| **完全無裁切** | 6 | 讀法回報了表、但這一題一張圖都沒有 |

**親眼驗證的內嵌圖表案例**（`moex:104090:305:33:1:question:q028`，1042_藥師(一)_藥劑學）：

```
A. 官方 PDF p3：get_images: 0，get_image_info: 1
   → xref=0 內嵌圖 bbox [40.6, 629.9, 270.1, 702.7]   ← 就是那張錠劑處方表
   → 文字層只有 "28.藥廠研發以下的錠片處方…" 與選項，表格本身完全不在文字層
B. 站上 shipped 裁切 `q028_embedded-image.png`：圖是對的（表在裡面），
   但 label 是 embedded-image 不是 paper-table → 「行定位」那條路沒走到它
```

`1021_藥師_藥劑學` q046、`1071_藥師_藥劑學` q036 同一形狀。

## 4. 建議（三層，依成本排序）

### 第一層：先修 D14（`image_bytes_of` 的 `no-xref`）

**一次解三個出口**：跨頁（Q13）＋內嵌圖表格（4 題）＋向量圖（1.3%）。
`image_bytes_of` 是**所有抽圖的唯一出口**，第一行 `if not xref: return None, "no-xref"`
把內嵌圖（`xref=0`，falsy）擋掉了。修法：改成以 bbox **渲染裁切**（`page.get_pixmap(clip=...)`）。
**負對照**：`1001_藥師_藥劑學` p1 的 9 條分隔線（短邊 1.0pt）不得被切成圖。

### 第二層：表裁切走「圖」而不是「行」

現行 `quoted_lines_region` 的輸入是**文字層的行**；表格若是內嵌圖就找不到。
應該讓讀法說「這裡有一張表」＋它看得到的最少辨識字，由 `get_image_info(xrefs=True)` 的 bbox 去裁
——**與第一層同一條修法**。

### 第三層：**不要把「是不是表格」做成偵測器**

`vision.py` 的長註解已明確拒絕此路線（設計者 2026-09-24 原話：「你一直擴充腳本又會overfitting」）。
**表格是語意 → 讀法說，程式只定位。** 這條紀律不能破。

## 8. 更正（2026-09-27，本輪推翻 §3「內嵌圖 4 題」與 §4「第一層」）

> **協定：append-only。上面 §3／§4／§7 原文不刪，這一節是更正。**

**推翻的事實**：§3 說「表格是內嵌圖（`xref=0`）4 題 → 就是 D4 缺陷 B」，
§4 第一層說「先修 `image_bytes_of` 的 `no-xref`，一次解三個出口」，
§7 說「三個症狀是同一條路（`image_bytes_of` 那一行）的三個出口」。
**這三句的前提是錯的：**

1. `qbr/src/qbr/extract.py::image_bytes_of` **是死碼，production 零呼叫者**
   （`git log --all -S` 只有引入的那一個 commit，引入時就沒有呼叫者）。
2. 生產抽圖走 **渲染**：`crop_run_figures.py` → `vision.crop_figure` → `vision.crop_region`
   → `page.get_pixmap(clip=...)`。所以 `xref=0` 的內嵌圖**本來就裁得到**，
   §3 的 q028 `q028_embedded-image.png`「圖是對的」正好證明這一點。
3. 因此「內嵌圖表格裁不到」**不是 `xref=0` 造成的**。
   §4 第一層「修 `no-xref` 一次解三個出口」**作廢**：改那一行不會改變任何裁圖。

**§3 那 4 題真正的形狀**：表格是內嵌圖，圖**有**被裁（label 是 `embedded-image`），
只是沒被標成 `paper-table`——是**標籤／走哪條路**的問題，不是「拿不到 bytes」。

**§7「一條路的三個出口」改寫為**：跨頁（Q13，已修）、內嵌圖表格（走渲染、已裁）、
向量圖（1.3%）是**三條不同的路**，只是症狀看起來像。把它們綁在同一行是錯誤的簡化。

**本輪真正的根因**（與表格無關，但會讓「有無選項」整卷翻掉）：
`repair.option_alphabet` 取了所有 private-use family 的 **union**，
兩 family 的卷（667 篇）選項家族被排到 `B`／`E`，`skeleton` 找不到 `A` → 全卷 0 選項。
詳見 `references/vector-figure-gap.md` §8 與 `references/qa-log.md` 本輪條目。
