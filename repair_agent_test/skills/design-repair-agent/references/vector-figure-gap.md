## 1. 為什麼要分開量「向量圖」與「內嵌圖」

管線的 `extract_images_a()`（`qbr/src/qbr/extract.py:950`）用
`page.get_image_info(xrefs=True)` 拿 bbox。這條路**看得到兩種東西**：

- **真有 XObject 的點陣圖** → `xref` 是真正的物件編號。
- **內嵌圖（inline image）**，PDF 的 `BI ... ID ... EI` 運算子 → **沒有 XObject、沒有 xref，
  `xrefs=True` 回 `xref=0`**。

而**完全看不到**第三種：

- **向量繪圖**（`re`／`l`／`c` 路徑）→ 只在 `page.get_drawings()` 裡，`get_image_info()` 什麼都不回。

所以「圖不見了」有三個獨立成因，要三支探針才量得完：

| 成因 | 看得到嗎 | 探針 |
|---|---|---|
| 向量繪圖 | `get_drawings` 看得到，`get_image_info` 看不到 | `measure_vector_figure_gap.py` |
| 內嵌圖 bbox | `get_image_info` 看得到，但 `xref=0` 切不出來 | `measure_inline_image_gap.py` |
| 真有 XObject 的點陣圖 | 兩條路都看得到，**正常** | （對照組） |

## 2. 缺陷 A：畫出來的圖（向量）

### 判準（逐物件，不是整頁聯集）

一個向量物件要算「有形」必須**同時**滿足：

- 短邊 ≥ **8 pt**（分隔線的短邊 < 4）
- 面積 ≥ **100 pt²**（分隔線的面積 ≤ 63）
- 面積 ≤ **頁面積的 50%**（內容外框／底圖佔 84%）
- **不是裸矩形**（`items == ["re"]` 的填色塊是框架或遮罩，不是畫出來的圖）
- 一頁要有 ≥ **3** 個這種物件

## 3. 缺陷 B：內嵌圖看得到、切不出來

### 成因（讀出來的，不是猜的）

`qbr/src/qbr/extract.py::image_bytes_of()` 第一行：

```python
if not xref:
    return None, "no-xref"
```

`xref=0` 是 falsy。內嵌圖的 `xref` 恰好就是 `0`。
所以 **bbox 正確、圖卻拿不到**。

### 實測（`1032_藥師(一)_藥理學與藥物化學` p10）

```
extract_images_a 在 p10：
  xref=0 box=(47,27)-(196,126)   209x139    ← Q44 的化學結構式
  xref=0 box=(47,128)-(172,214)  175x122
  xref=0 box=(47,216)-(173,320)  177x145

image_bytes_of(P, 0) → (None, 'no-xref')
image_bytes_of(P, 0) → (None, 'no-xref')
image_bytes_of(P, 0) → (None, 'no-xref')
```

### 結果（先剔除雜點——**我第一次量錯了，這是更正**）

第一次量到「154,128 張內嵌圖切不出來」，那是**錯的**。加上尺寸篩選後：

```
內嵌圖總數                     154,128
  ├ 真圖（≥400pt² 且短邊≥8pt）      151
  └ 雜點（<400pt²，99.9%）      153,977
```

一頁最多一萬五千個內嵌圖，**全部 < 50 pt²**（最大 35 pt²，即 6×6pt），
而同一頁的十一張真圖每張都 > 3,000 pt²。**這是 PDF 產生器的產物，不是圖。**

（那個「154,128 張」看起來像世界末日。**負對照救了這個數字。**）

### 修正後的規模

| 指標 | 數 | JSON 鍵 |
|---|---|---|
| 有真內嵌圖、且切不出來的篇數 | **53 / 989（5.36%）** | `papers_with_real_inline_figure` |
| 真內嵌圖張數 | **151** | `figure_shots_inline_real` |
| 其中真的拿不到 bytes 的 | **151（100%）** | `figure_shots_inline_bytes_unavailable` |
| 受影響題數（整篇計，**上界**） | **4,360 / 79,090（5.51%）** | `queue_questions_in_real_inline_papers` |
| 只有雜點、沒有真圖的篇數 | 79（**不算缺口**） | `papers_tiny_only` |
| 雜點張數 | 153,977 | `figure_shots_inline_tiny` |

**「真圖 151 張，bytes 拿不到 151 張」→ 失敗率是 100%，不是「有些會失敗」。**
這是因為 `xref=0` 是結構性的，不是個案。

### 「整篇計」是上界，要說清楚

候選 JSONL **沒有頁碼欄位**（`flattened_offsets` 是 `None`），
所以我**沒有一個題目對應到哪一頁**的可靠鍵。`4,360` 是「這些篇裡的題全部」，
**不是**「這 151 張圖所屬的那些題」。

**這是未量，不是已量。** 要量準，需要 `golden_path` 匯出時把「題 → 頁」寫進候選，
或改讀 `package.py::build_question` 的來源區塊。**這是後續工作，不是這支探針能回答的。**

## 5. 修法（兩條不同，不要合併）

**A（向量圖）**：新增第三條抽圖路徑，判準是**紙張性質**（路徑幾何），不是語意：

- 用 `page.get_drawings()` 找出「有形物件」的聯集 bbox（判準同 §2）
- 以該 bbox 對頁面做**渲染裁切**（`page.get_pixmap(clip=...)`，建議 300 dpi）

**B（內嵌圖）**：`image_bytes_of` 的 `no-xref` 分支要**改成渲染裁切**，不是放棄：

- bbox 已經有了（`get_image_info` 正確，實測 `(47,27)-(196,126)`）
- 沒有 xref 就拿不到原始位元，但**渲染同一塊區域**得到的是同一張圖
- 這條路同時涵蓋 A——**一條路徑修兩個缺陷**

**C（表格）**：先量「表格內容真的掉了幾張」，再決定要不要處理。文字可重建的表格不算缺口。

**負對照（每個修法都要附）**：
`1001_藥師_藥劑學` p1 的 9 條分隔線**必須不被修法切成圖**。
若修法把分隔線框起來，它就重現了第一版判準的錯。

## 6. 這份量測改變了什麼

**D4 原本被想像成「向量圖的巨大缺口」。實測不是。**

- 向量圖缺口是 **1.3%**（不是 20%、不是 50%）
- 但**管線真正漏圖的總量是 5.5%**，主因是內嵌圖的 `xref=0`，**不是**向量圖
- 兩者的修法可以合併成一條「以 bbox 渲染裁切」的路徑

→ **優先序要改**：修 `image_bytes_of` 的 `no-xref` 分支，
比新增「向量圖支援」更划算，而且它一次解掉兩個缺陷。

**設計者原本的擔心「PDF 內部還有向量」是真的，但它是小問題；
真正的大問題是「管線看得到圖的位置、卻拿不到圖」。**

6. 渲染裁切的品質（300 dpi 對化學結構式夠不夠）未量。
