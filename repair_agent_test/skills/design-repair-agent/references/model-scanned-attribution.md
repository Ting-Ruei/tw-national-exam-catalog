## 4. 掃描件 GT 的方法學（本輪建立，未來仍可用）

掃描件沒有文字層，所以 GT 必須來自**另一個獨立引擎**：

**macOS Vision OCR**（Apple 內建框架，零安裝，獨立於 PP-DocLayout 與 MinerU）：

```
probes/macos_vision_ocr.swift  +  probes/build_macos_vision_ocr.sh
  → probes/bin/macOS_vision_ocr     （輸入 PNG，輸出 x0 y0 x1 y1 text，像素座標）
```

**兩個獨立 GT，必須一致才算**：

1. **位置歸屬**：Vision OCR 讀題號 marker → 推出題目的垂直 span → 看預測框落在哪個 span。
2. **引用歸屬**：題幹寫「如圖N」、圖說寫「圖N」→ caption 屬於**引用它的題**。

**⚠️ 量測陷阱（已踩過並修好）**：**圖N ≠ 題號N**。基本電學卷的實測：

| 圖 | 所在題 |
|---|---|
| 圖一 | 題一 |
| 圖二 | **題三** |
| 圖三 | **題四** |
| 圖四 | **題五** |

把兩者當同一個數字，歸屬會全錯。

**marker 支援**：中文數字（`一二三四五六七八九十` ＋ `、`）與阿拉伯數字（`1.` / `1 ` / 單獨一行 `1`），含 `cjk_to_int`。

### 修好的兩個 bug

1. `render_point_scale` 在共用 tmp 目錄取第一個 `page*.png` → **多頁永遠回 page-1**。改成每頁各自 `mkdtemp`。
2. 殘留 `cleanup` 變數 → `NameError: name 'cleanup' is not defined`。

## 7. 量測缺陷一：數位頁的題號偵測（把 0.715 變成 0.984）

**症狀**：71 筆失敗**幾乎全部 `markers=[]`**——不是 PP-DocLayout 歸屬錯，是**我的題號偵測完全失敗**。

**根因**：原本的 `MARKER` regex 要求**句點**（`^\s*(\d{1,3})\s*[.．、]`），且左緣過濾寫死 `left > 36`。實測卷用了：

- **CJK 題號**（`二、`，L34）→ **完全沒有處理**
- **單獨數字行**（`1`、`2`、`3`，L41）→ 被 `left > 36` 拒絕

**修法**：讓數位工具的 marker 偵測與掃描工具**對齊**。五種形式全部支援（**每一種都實測過**）：

| 形式 | 出處 | 樣本 |
|---|---|---|
| `30.病患因為...` | 數字黏在題幹上 | 1152 物理治療師 |
| `22.` | 只有數字與句點 | 1072 藥師 |
| `1 世界衛生組織` | 數字、空白、題幹 | 護理師 1081（掃描） |
| `二、` | CJK 題號 | 1051 諮商心理師 |
| `1` | 單獨一行的裸數字 | 1051 諮商心理師 |

**⚠️ 一個我自己造成的回歸**：第一次修的時候我寫成「句點**後面要有空白**」，結果 `30.病患`（句點直接接字）全部漏抓 → **1152 卷從 1.000 掉到 0.000**。

**正確寫法**：句點是**前綴**，不是「前綴＋文字」：

```python
MARKER = re.compile(r"^\s*(\d{1,3})\s*[.．、]")       # 句點是前綴
SPACED = re.compile(r"^\s*(\d{1,3})\s+\S")           # 數字＋空白＋字
BARE_NUMBER = re.compile(r"^\s*(\d{1,3})\s*$")       # 裸數字
CJK_MARKER = re.compile(r"^\s*([一二三四五六七八九十]{1,3})\s*、")
MARKER_MAX_X = 45.0                                   # 見下
```

**左緣門檻 45pt 的由來（實測值）**：題號在 28pt（1152／1072）、41pt（1051 裸數字）；選項文字在 39pt、選項**數字**（`9α`／`16α`）在 51pt。45pt 收得進所有真題號，擋得住選項數字。

**回歸驗證**：1152 → 1.000、1072 → 1.000（兩個都回到原值才繼續）。

## 8. 量測缺陷二：續頁（把 0.984 變成 1.000）

**症狀**：`醫事檢驗師 1121` p13 **`markers=[]`**（整頁只有 3 個選項標籤與 3 張圖，題幹在前一頁），導致：

1. 這一頁的 3 張圖**歸屬到空**
2. 下一頁 p14 的 carry-in **也斷了**（因為 p13 沒有 marker 可回傳）

**修法**（兩處）：

1. **續頁＝整頁屬於前題**：`question_spans` 在 `carry_in` 有值且 `markers` 為空時，回傳**單一 span 覆蓋整頁**。
2. **carry-in 要向前回溯**：`last_marker_number(pdf, page, lookback=3)` —— 圖可以出現在題幹**兩頁之後**（1121 就是：題幹在 p12，圖在 p13 與 p14）。

**結果**：1121 p13/p14 歸屬 → **1.000**（4/4 框，range_coverage 0.954）。

## 9. 量測缺陷三：GT 的盲點（**向量圖看不到**）

**症狀**：最後 2 筆「錯」在 `1051_藥師(一)_藥物分析與生藥學` p5，偵測器找到 3 個圖，GT 只認 1 個。

**視覺確認**（第二引擎）：偵測器找到的是

| 圖 | 形式 | GT 看得到？ |
|---|---|---|
| Voriconazole（化學結構） | **向量繪圖** | ❌ |
| Naphthalene（化學結構） | **向量繪圖** | ❌ |
| Aspirin（化學結構） | 點陣圖物件 | ✅ |

**根因**：GT 來自 `pdftohtml -xml`，它只報**點陣圖片物件**。作者用 Word/繪圖工具畫的**向量圖**（化學結構、電路、曲線）——**GT 完全看不到**。

**所以這 2 筆不是偵測器誤報，是 GT 的盲點。GT 對，偵測器也對，是我的指標錯了。**

### 盲點有多大？（`probes/measure_gt_blindspot.py`，新工具）

拿 `pdfimages` 說「沒有圖」的頁，問 PP-DocLayout 有沒有看到圖：

| 樣本 | `pdfimages` 空頁 | 偵測器說有圖 | 盲點率 |
|---|---:|---:|---:|
| 300 頁 | 300 | 3 | **1.0%** |

**→ 盲點小（1%），所以「歸屬 0.992」這個數字可信。**

（3 筆之中：`1052_護理師` p2 與 `1102_醫事檢驗師` p2 是圖；`1041_護理師` p2 是 `table@0.39`。）

### 但盲點在**產品**上可能更大——而且已經在主線程式裡

**`qbr/src/qbr/extract.py` 的兩條抽圖路徑都只看點陣圖**：

| 函式 | 機制 | 看得到向量圖？ |
|---|---|---|
| `extract_images_a` | PyMuPDF `page.get_image_info()` | ❌ |
| `extract_images_b` | poppler `pdftotext -bbox` 的 `<image>` | ❌ |

`rg "get_drawings\|drawings\|vector"` 在 `extract.py`／`vision.py`／`crop_run_figures.py` → **0 命中**。

**我的判斷（非事實）**：這是一個**未被量化的管線缺口**——**可能有一批考題的圖從來沒被抽出來過**，因為它們是向量圖。而向量圖正是**化學／藥學／電路**這些科目的主力形式。這個缺口**還沒量**（需要：全庫多少頁有向量繪圖但無點陣圖 → 其中多少落在題目 span 內）。

**這正好是業主「管線引擎從一開始就設計成搭配模型審查」的第一個具體落點。**

## 10. 「下標字形」陷阱（我一度把真圖也濾掉）

`職能治療師 1051` p7 的「圖」其實是 **`PCO₂`／`PO₂` 的下標字元被畫成獨立小圖**（各 ~22×13pt）。`cluster(gap=3)` 把十個黏成 24pt 高的假圖。

**我第一次的修法是錯的**：用**墨跡密度**過濾（真圖是稠密的）——但**線條圖（電路、化學結構）大部分是白的**，密度也低 → **把真圖也濾掉**（1152 掉到 0.667、1072 掉到 0.091）。

**正確修法**：在**叢集之前**過濾**物件大小**，不是叢集之後過濾密度。

```python
big = [b for b in images if min(b[2]-b[0], b[3]-b[1]) >= min_pt]   # 先濾物件
figures = cluster(big)                                              # 再叢集
```

**實測值**：真圖以較大的物件進來（462×34pt 的橫條、107pt 高的化學結構）；下標字形是 ~13pt 的小物件。

**回歸驗證**：1152 → 1.000、1072 → 1.000、下標字形頁 → `true_figures: 0`。
