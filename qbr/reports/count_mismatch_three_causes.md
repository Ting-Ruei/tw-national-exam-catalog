# 六份「題數不符」的卷，其實是讀取器的三個缺陷

> 任務 4 的調查報告。六份 `醫師(二)` 卷長期被 S3 以 `count-mismatch` 擋下，
> 看起來像六份互不相關的壞卷（2 題、15 題、56 題、67 題、71 題），
> 實際上是**三個缺陷**：
>
> - **缺陷 A**：一個字被紙張畫了兩次，我們的讀取器也讀了兩次。
> - **缺陷 B**：一條「以數字＋年開頭的題幹」被當成試題表頭丟掉。
> - **缺陷 C**：答案卷把送分題從表格裡丢掉了，所以「題數」少算一題。
>
> 三個都已修好、都已量到、都在舊碼上有負向對照。
> 六份卷現在全部讀成 **80/80 且進入佇列**。
>
> **本報告第一版有一個錯誤**：它說六份都修好了，但 `1001_醫學(三)` 當時
> **從來沒有進入佇列**——修 A 讓它的題目讀對，卻沒讓它通過閘門。
> 那是缺陷 C，在重建佇列、逐卷核對題數時才發現。詳細見「缺陷 C」一節。

## 為什麼這件事重要（不是「多修了六份卷」）

`count-mismatch` 是**擋下**，不是**污染**：被擋的卷不會出貨，所以沒有人審到壞資料。
但擋下的代價是那六份卷**完全不在題庫裡**——六份 80 題的卷，等於 480 題從缺。

更關鍵的是：缺陷 A 不只影響這六份。它**污染了出貨佇列的文字**
（`血液液中`、`下列列`、`濃濃度`），而且**沒有任何既有檢查看得到**——
`quality_status=pass`、`disputes=None`。這是本管線第三次遇到同一件事：
**一個壞掉的讀取器，看起來和一個壞掉的產品一模一樣。**

## 缺陷 A：一個字被讀成兩個

### 症狀（出貨佇列裡的樣子）

```
1131_醫事檢驗師_臨床血液學與血庫學 q001（修正前）
  出貨：…尤其是貧血。血液液中沒有發現對抗紅血球的特殊抗體…則此病人最可能罹患下列列何種疾病？
  紙本：…尤其是貧血。血液中沒有發現對抗紅血球的特殊抗體…則此病人最可能罹患下列何種疾病？
```

### 根因

`read_spans`（`extract.py`）把一條視覺線上的每個 span **首尾相接**。
但這些卷的排版程式把一段文字**畫兩次**，位移約 0.24pt（偽粗體），
所以一個字會出現在兩個 span 的交界上：

```
span 1  x=[215.40, 435.35]  '…尤其是貧血。血液'
span 2  x=[424.32, 545.27]  '液中沒有發現對抗紅血球'
                    ^^^^^^ 424.32 是 span 1 裡「液」的左緣
                           第二個 span 又把「液」畫了一次
```

首尾相接 → `血液` + `液中` = `血液液中`。

### 這不是紙張的性質，是我們自己的缺陷

| 讀法 | 同一段的輸出 | 相鄰重複字對（全卷） |
|---|---|---|
| PyMuPDF 原生 `get_text("text")` | `血液中`（**1 次**） | 0 |
| 引擎 B（poppler） | `血液中`（**1 次**） | 0 |
| 本專案 `read_spans`（修正前） | `血液液中` | 39 |

**兩個獨立的讀法早就同意正確答案，只有我們不同意。** 這是判定「是缺陷、不是特性」的依據。

### 為什麼會擋下整份卷

同樣的雙重描繪也發生在**題號**上：

```
1031_醫師(二)_醫學(四) q34
  span `34` x=[47.16, 58.17]
  span `4`  x=[52.68, 58.17]    ← 在 34 的框裡面
  首尾相接 → `344`
```

題號規則是「必須是前一題的後繼」（`seen_number != last_number + 1` → 拒絕）。
`344` 不是後繼 → 這一題被拒絕 → **從這裡開始整份卷崩掉**。

`1031_醫學(四)` 因此被讀成 **2 題（滿分 80）**、`1012_醫學(五)` 15 題、`1002_醫學(五)` 56 題。
六份看起來像六個不同的病，其實是同一個讀取器。

### 修法：兩條幾何規則，各帶一個文字條件

在 `extract.py`：

| 規則 | 幾何 | 文字條件 |
|---|---|---|
| `_covered_prefix_length` | 後一個 span **由前一個的右方開始**，且與其尾端重疊 | 被覆蓋的字元已在文字裡（推論，不猜） |
| `_is_a_redraw` | 後一個 span **落在前一個裡面** | `text in previous`（證明已在文字裡） |

兩條都**只丟掉「已經在文字裡」的字元**，所以不可能遺失東西。

**必須有的護欄：`right[0] <= left[0]` → 不處理。**
試題表頭 `科目名稱：臨床血液學與血庫` 是被畫四次的同一段（x0 33.96/33.96/34.20/34.20，
每次往左一點）。少了這個護欄的第一版把表頭讀成
`科目名稱科目名稱科目名稱科目名稱：臨床血液學與血庫庫學`——**刪掉了真字元**。
**刪掉真字元比留下重複更糟**，所以這一條被寫成測試。

### 量到的效果

| | 修正前 | 修正後 |
|---|---|---|
| 自創的重複字對（全 841 卷，原生引擎完全沒有的） | **595** | **257** |
| `1031_醫師(二)_醫學(四)` 題數 | 2 | 33 →（配合缺陷 B）80 |
| `1031_醫學(三)` / `醫學(六)` | 71 / 67 | 80 / 80 |

## 缺陷 B：以「數字＋年」開頭的題幹被當成表頭

### 症狀

```
1002_醫師(二)_醫學(五) q56
  紙本：56  年老女性發生肱骨頸部骨折時的敘述，何者正確？
  讀到：第 55 題之後就停了，共 56 題（滿分 80）
```

### 根因：兩條「表頭」規則，其中一條誤擋

| 規則 | 位置 | 判準 | 實測 |
|---|---|---|---|
| `is_year_line` | `repair.py` | `^NNN年`（就只這樣） | 命中 2,205；真表頭 2,186、**真題幹 19** |
| `_is_year_running_head` | `repair.py` | NFKC 折疊後看 `年` 後面 | 擋下 381 行；真表頭 352、**真題幹 29** |

`is_year_line` 的判準是 `^NNN年`，所以 `56 年老女性…`、`7 年齡介於65～79歲…`、
`12 年金給付水準…` 全部被當成表頭 → 被視為 chrome 跳過 → 整份卷從那裡斷掉。

### `_is_year_running_head` 是多餘的（量出來的，不是猜的）

| | 數量 |
|---|---|
| 被它擋下的行 | 381 |
| 其中真表頭 | 352 |
| **其中真表頭的數字正好是「後繼」**（＝這條規則必要的次數） | **0** |
| 其中真題幹（＝它誤擋的次數） | **29** |

**352 個真表頭，後繼規則（successor rule）本來就會全部擋掉。**
所以這條規則的**必要貢獻是 0，誤擋是 29**。它不是被收緊，是被**刪除**：
一條規則、一個地方。這正是專案規範「改進要用取代，不是分岔」——
兩條做同一件事的規則，就是兩個可以不一致的地方（而它們確實不一致）。

### 修法：讓「表頭」看「年後面接什麼」

真表頭是**考試自己的名字**：`115年第一次專門職業及技術人員…`，年後面接的是
場次或考試種類（`第`、`專`）。以年開頭的題幹，年後面接的是**它的主詞**（`老`、`齡`、`金`…）。

| | |
|---|---|
| 全庫 `NNN年…` 行中是表頭的 | **2,186** |
| 其中年後接 `第` 或 `專` 的 | **2,186（全部）** |
| 其餘 19 行 | **全部是題幹** |

所以判準是「年後面那兩個字」，這不是在描述某一卷的內容，而是在描述**印刷形式印了什麼**，
因此對沒見過的卷也成立。另外把比對改成 **NFKC 折疊**，因為這些卷有些地方印 `年`（U+F98E）
——和 `年`（U+5E74）是不同碼位，只有 NFKC 會把它們合起來。

### 量到的效果（全 3,516 卷，前後對照）

| | |
|---|---|
| 題數改變的卷 | **19** |
| 總題數 | 230,287 → **230,868（+581）** |
| 題數減少的卷 | **0** |

每一份修好的卷都**落到一個完整的題數**上：

| 卷 | 修正前 | 修正後 |
|---|---|---|
| `1092_法醫師_一般醫學` | 43 | **100** |
| `1001_聽力師_電生理聽力學` | 7 | **80** |
| `1052_聽力師_行為聽力學` | 76 | **80** |
| `1002_醫師(二)_醫學(五)` | 56 | **80** |
| `1062_諮商心理師_諮商與心理治療實務與專業倫理` | 31 | **40** |

## 兩個缺陷的關係（為什麼六份卷要拆成兩個原因）

六份被擋的 `醫師(二)` 卷裡：

| 卷 | 缺陷 A | 缺陷 B | 缺陷 C（答案卷少算） |
|---|---|---|---|
| `1001_醫學(三)` | ✓ |  | **✓** |
| `1031_醫學(三)` | ✓ |  |  |
| `1031_醫學(六)` | ✓ |  |  |
| `1031_醫學(四)` | ✓ |  |  |
| `1002_醫學(五)` | ✓ | ✓ |  |
| `1012_醫學(五)` | ✓ | ✓ |  |

**單獨修 A 不夠，單獨修 B 也不夠**——`1002` 和 `1012` 需要兩個都修才會變成 80，
而 `1001_醫學(三)` 需要第三個（見下）。一份卷斷在同一個地方，原因可能疊了好幾層。

> **更正（重要）**：本報告第一版把 `1001_醫學(三)` 寫成「A 已修好」，那是**錯的**：
> 修 A 之後它的**題目**讀成 80 題，但它**從來沒有進入佇列**，因為它的**答案卷**讓
> `expected` 算成 **79**，閘門仍以 `count-mismatch:items=80 expected=79(answer-sheet)` 擋下。
> 我是在重建佇列、逐卷核對題數時才發現的——**「題目讀對了」不等於「卷出來了」**。
> 這是缺陷 C。

## 缺陷 C：答案卷少算一題（`golden_path.py`）

### 症狀

```
1001_醫師(二)_醫學(三)（100 年第 1 次）
  答案卷印：題數： 80題
  閘門說 ：count-mismatch:items=80 expected=79(answer-sheet)
  結果  ：整份卷被擋下，80 題從缺
```

### 根因：閘門把「題數」從**解析出的表格**回推，而不是讀**卷自己印的那一句**

`_sheet_question_count` 原本取「表格的最高題號」。但表格承載不了這個資訊：

```
題號 61 62 63 … 80
答案 B # A C … #      ← 第 80 題是 '#n```

`parse_answer_table` 遇到 `#` 會**跳過該欄**（等頁尾備註解釋），而**送分題在表格裡
沒有任何字母可以放**（`備註：第80題一律給分`）——所以它從表格消失了。

### 量到的形狀（不是抽樣，是全部 4,833 張答案卷）

| | 數量 |
|---|---|
| 語料裡的答案卷 | **4,833** |
| **每一張都印 `題數：NN題`** | **4,833（100%）** |
| 舊法（表格最高題號）與「卷自己印的」相同 | 4,754 |
| 不同 | **79** |
| 其中**正好少一題**（`79/80`、`49/50`、`39/40`、`99/100`…） | **79（全部）** |

**79 個不一致全部是「正好少一」，一個形狀的原因只有一個。**
另外 18 張（含在 79 內）因為兩界不從 1 開始而回 0（完全不說話）。

### 修法：讀卷**自己印的**那一句話

`題數：NN題` 是**卷對自己長度的陳述**，和閱卷的人用的是同一句。
它同時是**印刷形式**（不是某一張紙的內容），所以對沒見過的卷也成立。

舊法**保留**為退路（不印題數的卷仍用表格的兩界，含「從 1 開始」的護欄），
因為刪掉它會讓「不印題數的卷」失去檢查。

### 量到的效果

| | |
|---|---|
| `1001_醫師(二)_醫學(三)` 閘門 | `count-mismatch:items=80 expected=79` → **`expected=80`、`verdict: publish`** |
| 會**增加**題數的卷 | **1**（就是這一卷，80 題） |
| 會**減少**題數的卷 | **0** |
| 已出貨佇列中「宣告題數 ≠ 現行題數」的卷 | **0**（967 卷比對，其餘 21 卷語料不在） |

最後一列是重要的負向對照：這條修改對**已經正確的卷完全沒有作用**，
它不是「讓數字變好看」，它是「把一卷被誤擋的卷放回去」。

### 這一節的教訓

**「題目讀對了」不等於「卷出來了」。**
我把「六份卷都讀成 80 題」當成「六份卷都修好了」，但 `1001_醫學(三)` 從來沒進佇列。
抓到它的方式只有一個：**重建佇列，然後逐卷核對題數**，
不是看「抽取器回報的題數」——那正是它一直以來都對的那個數字。

## 為什麼一開始沒被發現（量測方法的教訓）

我第一版的修法**只處理「一個字的重疊」**，忽略了「整段被重畫」。
它讓總數看起來變好（6,389 → 4,887），但**六份卷份毫髮無傷**——
如果我只看總數就收工，會得到一個「有改善」的錯誤結論。

抓到它的方式是**去看那六份卷的 span 幾何**（`34` + `4` 落在同一個框裡），
而不是看聚合數字。這和 `option_continuation_fix.md` 裡
「量測工具自己錯了兩次」是同一課：**聚合數字可以掩蓋機制。**

## 負向對照（一個不能失敗的規則什麼都沒證明）

| 對照 | 結果 |
|---|---|
| 缺陷 A 的 3 條正向測試在舊碼上 | **紅**（`'344' == '34'`、`'33'` 應為 `'3'`） |
| 缺陷 B 的 2 條測試在舊碼上 | **紅**（`[1]` 應為 `[1, 2, 3]`） |
| 缺陷 A 的護欄測試（偽粗體表頭） | 舊碼與新碼都**綠**（這條是防止我修壞） |
| 缺陷 B 的真重複／真後繼案例 | 舊碼與新碼都**綠** |
| 全部 3,516 卷 | 修 B 時**沒有任何一卷題數減少** |

## 重跑管線

改動的是**抽取邊界**（`extract.py`），所以出貨佇列必須重建才會看到修好的文字：

```sh

for c in 醫事檢驗師 醫事放射師 物理治療師 藥師 "藥師(一)" "藥師(二)" "醫師(一)" "醫師(二)"; do
  d=$(echo "$c" | tr -d '()')
  .venv/bin/python scripts/batch_package.py --category "$c" --work "/tmp/qbr-rebuild2/${d}"
done
.venv/bin/python scripts/build_review_queue.py \
  --work /tmp/qbr-rebuild2/{醫事檢驗師,醫事放射師,物理治療師,藥師,藥師一,藥師二,醫師一,醫師二} \
  --out /tmp/qbr-rebuild2-queue --carry-from qbr/data/review-queues/live
```

# 附錄：`qbr/data/` 的保存與備份

## 為什麼 `qbr/data/` 被 gitignore

`.gitignore` 第 22–30 行：

```
qbr/data/        # 產物與語料副本
qbr/runs/        # 每次執行的輸出
qbr/tmp/
qbr/.venv/
deploy/qbr-review/.env
```

理由是**體積與性質**：`qbr/data/` 現在 3.8GB，其中絕大多數是**可重建的產物**，
而 git 不適合放 GB 級的二進位產物（每次都存一份完整歷史）。

## 裡面三種東西，保存價值完全不同

| 目錄 | 大小 | 性質 | 丟掉會怎樣 |
|---|---|---|---|
| `data/review-queues/live/review-ui/crops/` | 837M | **可重建**（PDF 裁圖） | 重跑 `crop_run_figures.py` 就好 |
| `data/review-queues/live/review-ui/candidates.jsonl` | 186M | **可重建**（重跑封裝） | 重跑 `batch_package.py` 就好 |
| `data/review-queues/*/review-ui/question_review_events.jsonl` | 64K × 5 | **不可重建** | **丟掉就真的丟掉了** |
| `data/runs/` | 1.2G | 逐卷的執行日誌與中間產物 | 重跑即可 |

### 唯一不可重建的是人類審核事件

`question_review_events.jsonl` 是**人類做的判斷**：某人在某個時間看了某一題、決定了什麼。
這個東西**沒有第二個來源**——重跑管線只會產生機器讀到的文字，不會產生人的決定。

而且它的設計是**只能追加**（append-only）：

- 文字變了 → 寫一筆新的 `reset_review` 事件，**保留舊的那一筆**（舊決定是對舊文字做的，不是錯的）。
- 絕不覆寫既有事件。

所以這個檔案**只會變長，不會被重寫**，備份它永遠是安全的。
