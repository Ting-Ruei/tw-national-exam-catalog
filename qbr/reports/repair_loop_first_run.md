# Repair loop — 第一次跑，與它抓到的那個缺陷

`qbr/scripts/repair_loop.py` 實作的是使用者描述的那個迴圈，而且**只准單向**：

```
人類標 block ──► 既有偵測器能解釋嗎？
                  ├─ 能 ──► 不是缺口（是偵測結果沒在畫面上被看到）
                  └─ 不能 ─► 這才是要建規則的地方
                              ──► 新規則上線
                                    ──► 全庫重掃
                                          ──► 有人判斷過的 → reset_review（附加，不覆寫）
                                                沒人判斷過的 → 不動
```

## 為什麼迴圈不能反向跑

一條題目會被重開，**只因為某個偵測器在它上面觸發**。所以：

- 人的沉默不會被升格成「核准」；
- 人的核准不會在沒有可機檢理由的情況下被翻掉；
- `needs_review`（「我無法判斷」）**不是輸入**——無法從「我不確定」長出一條規則。

這是 `GOV-05` 的形狀：程式的產出是**建議**，寫入要另一個刻意的 `--apply`。
`repair_loop.py` 本身唯讀；測試 `test_rescan_changes_no_file_in_the_queue` 就是在釘住這件事。

## 第一次跑的結果（真實資料）

站上 347 筆人工紀錄，最新決定：accept 273 / block 16 / needs_review 1 / reset_review 9。

```
== 1. 收集 ==  16 題 block
== 2. 解釋 ==   1 題被既有偵測器解釋（substituted-ideograph）
== 3. 強化 ==  15 題沒有任何偵測器解釋
              集中在：111020:305 共 11 題、108030:305 共 2 題
```

**「11 題集中在同一卷」就是這個步驟存在的理由**：先看出它們是不是同一個原因，
再決定要不要寫規則。答案是同一個原因（見下），所以一條規則收掉 11 題的其中 3 題。

## 抓到的缺陷：`substituted-script`

那 11 題裡有 10 題（`111020_藥師(一)_藥劑學`）**讀起來完全正確**，那是陷阱。
它們的選項長這樣：

```
下列產品何者屬於吸收性基劑（absorption bases）？ћAquabase  ќEucerin  ѝPlastibase  ўAquaphor
  A. 僅ћў   B. 僅ќѝ   C. ћќў   D. ќѝў
```

紙本印的是 `①Aquabase ②Eucerin ③Plastibase ④Aquaphor`，也就是 `①②③④`；
文字層存的是西里爾字母 `ћќѝў`。**使用者把 q030 / q044 / q078 判為 block，是對的。**

### 先確認「是誰壞的」

便宜且決定性的一步：看 PDF 自己的文字層。

```
'2. 下列何者為通用動作程式（generalized motor program）中的不可變參數？\x83[...'
```

文字層裡是 `\x83[`（單一 byte 加括號），不是西里爾——**是字型的編碼映射壞了**，
管線把它解成西里爾。再以 300 dpi 回對紙本，紙本印的是 `①`。兩步都做完才動手。

### 規則是什麼，以及為什麼不是另一條更漂亮的規則

誘人的版本是「偏移律」：22 個字元剛好都是「印刷符號 − 0x2005」——
`ћ`U+045B→`①`U+2460、`Ә`U+04D8→`ⓝ`U+24DD，非常整齊。

**但那是巧合，蓋在它上面就是蓋在巧合上。** 實測 U+090B `ऋ`、U+0F4A `ཊ`、U+0E25 `ล`
等另外 11 個字元也插在中文詞裡，卻不符合任何偏移。所以規則命名的是它們**全部**共有的那件事：

> 一個字元，來自台灣考卷從不印刷的字母系統，而且它**夾在一個中文詞裡面**。

「夾在中文詞裡」是承重的：考卷合法地印英文與希臘文（希臘字母 6,653 次），
要求前後緊貼漢字，報的就是**錯字的形狀**——一個走錯位置、把中文字擠掉的字元。

判準只讀 Unicode 字元名稱裡的 script，**刻意不看 `category`**：實測命中的 475 個字元裡
有 385 個字母、64 個標點、26 個數字，而標點壞得一樣徹底
（`下࠻何種` 應讀 `下列何種`，`光߉` 應讀 `光量`）。所以 kind 叫 `substituted-script`，不叫 letter。

`substituted-letter` 這個名字在寫下的過程中改掉，因為它會描述錯自己會報的東西。

### 它是 `substituted-ideograph` 的兄弟，不是它的擴充

| | `substituted-ideograph` | `substituted-script` |
|---|---|---|
| 機制 | 字型映射到**另一個漢字** | 字型映射到**別的字母系統** |
| 證據 | 紙本印什麼**已知**（`RADICAL_SUPPLEMENT_MEANS`） | 紙本印什麼**未知** |
| 對審題者說 | 「⻑ 應為 長」 | 「這是 CYRILLIC，共 5 處」＋位址 |

差別在**證據**，所以是兩個 kind：一個能說出正確的字，一個只能說出位址與字母系統。
第二種因此能抓到沒有人編目過的字母系統——這正是它存在的理由。

## 量測

全庫 79,090 題：

| | 數量 |
|---|---|
| `substituted-script` 觸發 | **157 題** |
| 其中**已被人類接受**的 | **0 題** |
| 其中是人類 block 的 | 3 / 16 |

**那個 0 才是要紧的性質**：新規則不會把已經看過的題目攪動一遍。
`repair_loop.py --rescan` 會重新量這個數字，而不是相信這段話。

## 它怎麼到達審題者

偵測結果存在每個 run 的 `review-ui/candidates.jsonl` 的 `disputes` 欄位，
由 `review_queue.disputes_for_paper()` 算並寫入。原本只有 `crop_run_figures.py` 會呼叫它，
而那意味著「換一條偵測規則」得重切 3,500 張圖。

所以 `crop_run_figures.py` 多了 `--reannotate-only`：**只重算，不重切**。
`image_refs` 已經在列上，disputes 是從列＋那個欄位算出來的，不需要圖片。
989 卷 5 秒跑完（相對重切圖的 5 分鐘）。同一支腳本、同一個 annotator，不是第二個。

驗收（都是實際畫面，不是「API 有回」）：

```
站上 candidates.jsonl 含 substituted-script：157
/api/candidates 第 2 題： [review] 文字層存的是別國字元，讀者看到亂碼
                          detail: cyrillic（CYRILLIC 字母，共 5 處）
瀏覽器（headless Chrome，站上 8765）：
  第 2 題  系統無法判定（1）  以下由紙本量測，不是模型的意見
           需確認｜文字層存的是別國字元，讀者看到亂碼   cyrillic（CYRILLIC 字母，共 5 處）
```

## 人工紀錄的保護（順帶修掉的兩個洞）

跑這一輪時發現 `scripts/deploy_station.sh` 的 `rsync --delete` 有兩個會靜默吃掉東西的地方：

1. **只排除了 1 個事件流，但管線認得 6 個**。其餘五個（答案／AI 審核／AI 回饋／AI 學習／
   修正回饋）只要在常駐機上產生過，就會被無聲刪掉——rsync 刪掉「來源沒有的檔」不會有任何輸出。
   現在六個都在排除清單裡，**而且部署前會在常駐機上先備份一份帶時間戳的副本**。
2. **`.env` 被刪掉了，而且它只存在於常駐機**（筆電的 `.gitignore:31` 忽略它）。
   它記著站上的埠是 8765 而不是預設的 8774——它一不見，watchdog 下次重建容器就會換埠，
   使用者的書籤與已安裝的 PWA 就斷了。已重建並排除在刪除範圍外。

備份那段還有一個自己種的洞：`ssh -n` 把 stdin 接到 `/dev/null`，heredoc 根本沒送到常駐機，
**備份指令不會執行也不會報錯**。上一版就是這樣印了「先備份」四個字而什麼都沒做。
移掉 `-n` 之後實測：備份檔數 2 → 3。

## 未解釋的 12 題不是失敗

15 題未解釋裡，3 題被新規則收掉，剩下 12 題（含 10 題集中同一卷的那批中沒觸發的、以及
108030 的兩題、115090 的 `答案沒進去`）。它們**還沒有偵測器**，這是誠實的狀態：
下一步是逐題看紙本，不是給它們硬套一條規則。

`115090:308:0504:q041` 有唯一一句備註「答案沒進去」，而它的 `answer_payload` 是
`送分 / accepted=['A','B','C','D']`——值得單獨查，但那是下一次的事。

## 迴圈的第二圈：漢字鄰居條件是錯的

第一次跑之後剩下的 12 題未解釋裡，11 題集中在兩卷。逐題看過紙本後發現的是一個**我自己的規則
太窄**，不是新缺陷：`111020:305:33 q036` 的選項是 `ћќѝўџ` 對 `①②③④⑤`，而舊規則要求外國字母
「夾在一個中文詞裡面」，這一題的鄰居是另一個西里爾字母、或英文單字的第一個字母。

### 先確認當初的理由是不是真的

舊註解寫的理由是：「考卷合法地印英文與希臘文，所以要求漢字鄰居，報的才是錯字的形狀。」

實測：英文是 `LATIN`、希臘文是 `GREEK`，**兩者本來就在 `NATIVE_SCRIPT_PREFIXES` 裡**，
所以鄰居條件從來沒有擋掉過它們。它真正擋掉的是 1,042 處裡面的 567 處（54%）真缺陷：

| 情境 | 數量 | 例子 |
|---|---|---|
| 錯字在**拉丁字裡面** | 2 | `Waldenstrӧm's`、`Henoch-Schӧnlein` |
| 錯字**旁邊只有空白** | 1 | `（²²⁶Ra Г=8.25 R-cm²/mg-h）`（紙本 Γ） |
| **整串都是西里爾**的選項 | 555 | `ћќѝўџ`；其中 19 題的選項就是 `ћќѝ` |

那 555 處是整個題庫**壞得最徹底**的題目——選項整串都是雜訊——而條件把它們藏起來，只因為它們
長得不像「一個中文詞裡的一個錯字」。這正是 charter 警告的那個陷阱：**規則照著第一個例子的形狀
寫，就會拒絕第二個。**

### 改的是位置，不是字母系統

所以留著的是兩份字母系統清單（那才是規則之所以窄的原因），拿掉的是位置條件。量測：

| | 舊規則 | 新規則 |
|---|---|---|
| 觸發題數 | 157 | **164** |
| 全庫命中處數 | 475 | **1,042** |
| 其中**已被審核者接受**的 | 0 | **0** |
| 抓到的 16 個人類 block | 3 | **4** |

那個 `0` 仍然是最要緊的性質，而 `--rescan` 會重新量它，不是相信這段話。

函式也改名：`foreign_script_characters_in_chinese` → `foreign_script_characters`。
舊名字在漢字條件還在時是對的，條件一走它就變成一句謊；**照一個已經不存在的條件命名，是下一個
agent 把條件加回去的方式。**

### 順帶修掉的一個報表謊言

跑 `--reannotate-only` 時它印「更新候選列 **0**」，而它剛剛重寫了 989 個檔案裡的每一列——
因為那個計數器只有重切圖那條路徑會加。**「0 列更新」出現在一個剛上線的偵測器旁邊，是會讓人
再跑一次確認的數字。** 現在它從這條路徑自己算：改過的列數 + 每個 kind 的增減，而且只在有東西
動的卷才印那一行（989 卷的一趟因此讀起來就是它真的碰到的那幾卷）。

### 驗收（畫面上，不是 API 有回）

```
第 36 題   系統無法判定（1）   以下由紙本量測，不是模型的意見
          需確認｜文字層存的是別國字元，讀者看到亂碼   cyrillic（CYRILLIC 字母，共 25 處）
```
