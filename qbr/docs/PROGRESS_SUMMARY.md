## 1. 審題介面（Review UI）改了什麼

### 1.1 「看不到題目」的真正原因（不是介面壞了）

| 症狀 | 真正原因 | 修正 |
|---|---|---|
| 點進去看不到任何題目 | **文件寫的埠是 8769，實際服務在 8774**；而且服務只綁 `127.0.0.1` | 埠改成參數、移除文件裡的硬寫埠、加 `REVIEW_UI_HOST` |
| 服務「好像起來了」但畫面是空的 | 啟動腳本沒有檢查「這一輪有幾題」 | **0 題的 run 直接拒絕啟動** |
| 埠被佔用時靜默失敗 | 沒有檢查 | 啟動前檢查，並印出佔用者的 pid |

`review_run.sh` 現在會印出：實際 URL、題數、有圖題數、決策紀錄路徑。

### 1.2 介面本身的三個缺陷

| 缺陷 | 原因 | 修正 |
|---|---|---|
| 圖片顯示成「?」與 alt 文字 | 44 個裁切是 **JPEG 2000（`.jpx`）**，Chrome 不能渲染 | 寫檔時正規化容器（`extract.web_safe_image`）；伺服器**先嗅探位元組**再決定 MIME；44 個檔轉成 PNG |
| 圖片顯示「不完整」 | CSS 把選項圖限制在 220×200 | 放寬到 320×280，加 `cursor:zoom-in` 與點擊放大 |
| 換題時圖片延遲嚴重 | `go()` **每次按 W/S 都打一次 `/api/workflow`**（1.2 MB、0.72 秒、回傳 2000 筆），而回傳的 `S.data` **從來沒被讀取**；重繪 innerHTML 讓所有 `<img>` 重新下載解碼 | 從 `go()` 移除這個請求 |
| 「有些題沒有正確答案」 | 選項標記是從**顯示字串用逗號切**，但修正表寫的是 `A或D`（用「或」連接），所以**一個選項都沒被標記** | 改讀 `answer_payload.accepted_values`（32,350 題每一列都有） |

### 1.3 介面新增的兩個顯示（這一輪）

- **紙本自訂符號對照表**：有些題的選項是「題目自己子項的組合」
  （題幹寫 `\ue000砂粒病毒`，選項寫 `\ue18c\ue000\ue001`）。瀏覽器沒有私用區字型，
  以前畫面上是**一排豆腐**。現在介面顯示對照表並把符號換成紙本自己寫的字。
- **字形遺失的瑕疵註記（紅色）**：`轉氨\ue2c6` 是轉氨酶、`凝固\ue2c6` 是凝固酶 ——
  紙本印了字而文字層拼不出來。這是**已知位置的真缺陷**，介面把它標成紅色並給出位址
  （「第 39 個字元：凝固▢陰性」），**絕不猜字**。

### 1.4 題組（共同題幹）

- 新增 `src/qbr/groups.py`；**在打包時分組**（卷是單位），不是事後補。
- 目前 **433 組、881 題**（2 題組 826、3 題組 45）。
- `承上題` 不會跨卷黏到上一卷最後一題。

## 2. 圖片截圖：對不對，以及有沒有變成 skill

### 2.1 裁切驗收（用不是自己產生的標準）

| 項目 | 數字 |

### 2.2 這一輪修好的三類「看不到圖」

| 類 | 症狀 | 真正原因 | 量測 |
|---|---|---|---|
| A | 選項是豆腐 | 一卷有**兩套**私用區字型 | 主套每題一次、副套少數題 |
| B | 選項整列不見 | `_is_bullet_only` 把「只有標記的一列」當版型刪掉 | 328 列中只有 27 列是單一相異碼 |
| C | 選項是子項組合 | 子項與選項標記**都是 4 連號** | 逐家族試切，取切得對的 |
| D | 續行被當新題 | 「後繼號碼」沒排除**折行** | 89,463 個 anchor 中只有 2 個符合 |
| E | 裁切只有一條細線 | 一張圖被印成 **290 個 `xref=0` 的碎片**（不是向量圖） | 真圖 region 全部 ≥24 pt，碎片 1.4 pt |

**E 類的成果**：`1051_藥師(一)_藥劑學` Q68 的 region 從 1.4×34.6 → **87.8×77.8 pt**，
裁切 250×222 px，兩個軸、斜線、`1/V`、`1/C`、`X軸截距` 全部在畫面裡。

### 2.3 為什麼不叫模型判斷裁切好不好

**已證實模型不能仲裁裁切**：978 個選項裁切與 PDF 內嵌物件**位元組完全相同**
（來源 `image-object`），不可能被裁壞，而模型把 56 個判成「clipped」（誤報）。
同一個裁切重複問 131 次，**模型自我矛盾 39 次（30%）**。

所以「有沒有圖」的觸發器是**量測**（物件座標、墨跡、碎片密度），不是關鍵字、也不是模型。

## 4. 這一輪的七條規則

1. **「同一類」要先證明。** 10 卷掛同一個 `blocking`，其實是四類。
2. **驗收標準是兩個引擎一致，不是測試全綠。**
3. **量得到的不要問模型。** 問了只是把不確定引進來。
4. **修好的規則要問它會多裁進什麼。** 21 題裡有 1 題是空白。
5. **看不到的證據不是證據。** HTTP 200 不算，要用 PIL 真的解碼。
6. **假設要用 PDF 自己回答。** 「沒有 image object 所以是向量圖」是錯的（是碎片）。
7. **命名要跟著證據改。** 名字錯了，下一個讀者會往錯的方向找。
