# 模型能力探索計畫（第二輪）

**狀態：已規劃，未執行。等待 Qwen3.8-27B 部署完成後才動用任何模型。**

本計畫有兩個目標，合起來回答一個問題：

> **地端模型除了「做事」，能不能扮演「指揮與監督」？**

這不是同一個能力的加碼。會做事和會監督是兩種不同的工作：

- **做事**：讀一張圖、讀一份卷、把一段文字整理成結構化資料。有明確的輸入與輸出，錯了看得出來。
- **監督**：判斷別人的輸出對不對、決定下一步做什麼、知道什麼時候該停下來問人。錯了不一定看得出來，而且錯的方式是「看起來很合理」。

第一輪已經量過「做事」的邊界（§17、§20）。這一輪要量的是**監督**。

## 4. 第二輪要新增的測驗：監督能力

「做事」的測驗卷已經有了。**「監督」需要新的測驗卷，因為監督的難點不是產生答案，是判斷答案。**

每一格都必須有**負對照**（已知錯的輸入），否則「通過」可能只是因為每一題都說好。

### T1. 錯誤偵測（已知缺陷的植入與辨識）

**做法**：拿已驗證正確的 80 題，**人為植入已知種類的缺陷**，看模型能不能指出來。

| 缺陷種類 | 植入方式 | 正確的監督回答 |
|---|---|---|
| 題號跳號 | 刪掉 Q37 | 指出 37 缺、後續不位移 |
| 選項少一個 | 刪掉 Q50 的 C | 指出該題只有 3 個選項 |
| 答案與選項不符 | 把答案從 B 改成 E | 指出 E 不在字母表內 |
| 題幹被截斷 | 截掉 Q60 最後 10 字 | 指出不完整，不是「正常」 |
| 兩題合併 | 把 Q70/Q71 併成一題 | 指出題數少 1 |
| **負對照**：完全正確 | 不動 | **必須說「沒問題」** |

**判準**：`recall`（幾成的植入被抓到）與 `false_alarm`（正確的被誤報幾成）。**兩個都要看，只看 recall 會獎勵一個永遠說「有問題」的模型。**

### T2. 一致性檢查（兩個引擎的仲裁者）

**做法**：餵入「兩個引擎不一致」的真實案例（§20 已量過：429/429 一致，但歷史上有 32,721 個相鄰間隙的案例），問模型**哪一個對，或兩個都錯**。

**難點**：這是**監督的核心**。若模型只會選「看起來比較長／比較完整」的那個，它不是監督，是在猜。

**判準**：與人為判定的答案比對；並且**記錄它選錯時的理由**（理由是幻覺還是誤讀）。

### T3. 不確定性的表達（知道自己不知道）

**做法**：三類輸入各若干，**不告訴它是哪一類**：

- 清楚可讀的題目
- 模糊／缺字的題目（已知有失落字形的位置）
- 超出範圍的輸入（例如整頁都是圖，沒有文字層）

**判準**：模型說「不確定」的比例，是否與輸入的實際模糊程度**單調相關**。一個所有題目都說「我很確定」的模型不能當監督；一個所有題目都說「我不確定」的模型也不能。

### T4. 停止與升級（什麼時候該問人）

**做法**：給定一個情境與預算，問「下一步做什麼」。

| 情境 | 正確的監督回答 |
|---|---|
| 10 卷裡 1 卷不通過 | 處理那 1 卷，不是全部重跑（**不要用「再疊一層」回答不確定**） |
| 兩引擎一致且答案卷確認題數 | 直接採用，不必再問（**過度升級也是失敗**） |
| 缺陷在已知位置（失落字形） | 帶到受影響題目，不阻擋整卷 |
| 規則在兩個引擎上只有一個成立 | **拒絕採用該規則**（規則必須同時成立） |

**判準**：與「正確處置」比對；並統計**不必要的升級**（把簡單情況複雜化）。

### T5. 監督者能不能發現自己的錯

**做法**：讓模型對同一批題目跑兩次，**中間不換提示詞**；再拿兩次結果互比。

**判準**：自我一致率。**低自我一致率的模型不能當監督**，因為它的判決不可重現。

**這也是唯一一個不需要人為標註就能算的指標。**

### T6. 編排能力（直接模擬「新考題進來」的實際情境）

T1–T5 量的是**個別判斷**。實際自動化要的是**一連串判斷**，而且後面的判斷依賴前面的結果。

**做法**：給模型一個**從未見過的卷**（例如醫事放射師，或其他尚未進管線的類科），
只給它**工具清單**與**目標**，不給它步驟：

> 這是一份新的國考題 PDF（題目卷 + 答案卷）。請把它變成可審核的題庫，
> 並告訴我哪些地方你不確定。
> 可用的工具：`extract_cells_a`、`mask_chrome`、`cells_with_pages`、`skeleton`、
> `figure_questions`、`crop_figure`、`option_figures`、`describe_crop`、`compare_skeleton`。

**要觀察的四件事（依重要性排序）：**

| # | 觀察 | 為什麼重要 |
|---|---|---|
| 1 | **有沒有先量答案卷的題數** | 答案卷是題數的權威；跳過它就是跳過唯一的驗收依據 |
| 2 | **有沒有量兩個引擎是否一致** | 驗收標準是兩引擎一致，不是測試全綠 |
| 3 | **不確定時有沒有問人** | 這是「不做定位擷圖就用 LLM」的正確用法 |
| 4 | **有没有留下未經量測的預測規則** | 不能留下沒有量過的規則 |

**這三件事模型最可能做錯，而且錯了之後看起來仍然像完成了工作：**

| 失敗模式 | 看起來像 | 實際是 |
|---|---|---|
| 跳過答案卷 | 「題數我讀出來了 80 題」 | 用讀出來的題數證明讀出來的題數 |
| 只用一個引擎 | 「管線跑完了」 | 少了一個對照，雜訊變成資料 |
| 不確定時自己編 | 「選項 C 的文字是…」 | 幻覺，而且沒有標記為不確定 |

**判準**：把模型的編排記錄（呼叫了哪些工具、順序、為什麼）和**正確的管線順序**比對。

**這一項是「能不能自動化」的真正分界線。** T1–T5 通過但 T6 不通過的結論是：
**地端模型可以當每一站的檢查員，但不能當廠長。** 那就保留人在每個轉角做決定，
模型只負責它被量過做得到的那幾件事。

**T6 的輸入必須是一個真的沒進過管線的卷**，否則模型是在認得答案，不是在做事。
建議用 `醫事放射師`——它不在目前已量測的四個類科裡。

## 5. 執行順序（部署完成後）

```
1. 健檢          /v1/models、supports_vision、max_tokens、單次來回延遲
2. 控制組        用 ornith 跑一次，確認提示詞與輸入沒有壞（基準線要先站穩）
3. T1 錯誤偵測   植入缺陷 + 負對照         ← 這一項最優先，它決定能不能用
4. T5 自我一致   不需標註，最便宜，可先跑
5. T2 一致性仲裁
6. T3 不確定性
7. T4 停止與升級
8. T6 編排       未見過的卷 + 只給工具清單   ← 這一項決定能不能自動化
9. 視覺任務      只在 supports_vision 為真時跑；沿用 §17 的 216 題正負對照
10. 讀卷任務     沿用第一輪提示詞，比較與 ornith 的逐題差異
```

**先跑 T1 與 T5；通過了才跑 T6。** 如果一個模型在「指出已知錯誤」上不行，
它的編排能力不必測——**不能偵測錯誤的廠長會把錯的東西發包出去**。

## 7. 判準（先寫下來，避免事後調整）

| 問題 | 通過的定義 |
|---|---|
| 能做事嗎 | 與第一輪 ornith 的表現**不顯著較差**，且成本可接受 |
| 能監督嗎 | T1 `recall ≥ 0.8` 且 `false_alarm ≤ 0.1` |
| 能當仲裁者嗎 | T2 正確率高於**隨機選一個引擎**，且不是「永遠選長的」 |
| 知道自己不知道嗎 | T3 的「不確定」比例與模糊程度單調相關 |
| 能被信任自動化嗎 | T1 通過 **且** T5 自我一致率 ≥ 0.95 |
| **能當廠長嗎** | T6 的編排順序包含「先量答案卷題數」與「兩引擎一致」，且不確定時有停下來 |

**若 T1 不通過**：結論是「地端模型目前只能做事，不能監督」，自動化新考題的流程就必須保留人在迴圈，**這是可以接受的結論**，不是失敗。

**若 T1/T5 通過但 T6 不通過**：結論是「地端模型可以當每一站的檢查員，但不能當廠長」。
這時候正確的做法**不是**去調 T6 的提示詞讓它通過，而是把管線的**順序**寫成確定的步驟，
只把「每一站的判斷」交給模型。使用者對這件事的判斷（「沒有萬能腳本，題目是靈活的」）
和這件事不矛盾：**腳本負責順序，模型負責判斷，而順序本來就是可重複的。**

**不要為了讓模型通過而調提示詞。** 若需要改提示詞才能通過，那量到的是提示詞，不是模型——**換一組提示詞就要重跑對照組**。
