# 為什麼單一 PDF 引擎會導致 overfitting，以及該怎麼走

**日期**：2026-09-15
**範圍**：官方 PDF → 題庫 package 的文字抽取階段
**證據來源**：`1152_醫事檢驗師_生物化學與臨床生化學.pdf`（80 題）+ `_ANS.pdf`，以及本文件記錄的三次實際修錯過程

---

## 1. 問題陳述

過去多個版本的設計都遇到同一個迴圈：

```
模型（或人工）發現某題抽錯了
  → 修改抽取腳本
  → 那一題看起來對了
  → 換一份卷／換一台機器／換一個引擎版本
  → 同一類錯誤再次出現
```

這不是「修得不夠多」，而是**修的方式有結構性缺陷**：每一次修改都依賴了某個 PDF 引擎的實作細節，而不是紙本的性質。實作細節會變，紙本不會。

**量測結果（115090，80 題）**：同一份 PDF，兩個引擎各自解析，題幹 **10 題（12.5%）不一致**、選項 **7 題（8.8%）不一致**。

---

## 2. 三個實證

### 2.1 兩個引擎看到的不是同一份文件

同一頁、同一行，兩個引擎的回報完全不同：

| 面向 | 引擎 A (PyMuPDF) | 引擎 B (poppler) |
|---|---|---|
| **答案卷格子** | `答案ＤＢＡＡＣＢＣＤＣＡ...`（21 格黏成一行） | 21 段獨立，間隙 10pt 完整保留 |
| **上下標** | `size=5.51`（唯一能判別上下標的依據） | **`size=0.00`，完全沒有字級** |
| **文字切分** | 依 block；`C.[K` 被切成獨立片段 | 依 word，位置精確但更碎 |
| **跨 block 合併** | 上下標分散在**不同 block** | 同一 block 內 |

實例（Q45 選項 C，紙本 `[K⁺]－[PO₄³⁻]－[HCO₃⁻]`）：

```
A (PyMuPDF): 'C.[K⁺]－[PO₄³⁻]－[HCO₃⁻] '     ← 完整（因為有 size）
B (poppler): 'C.[K' / '+' / ']－[PO' / '4' / '3-' / ']－[HCO' / '3' / '-'
                                               ← 字元被拆散（因為沒有 size）
```

### 2.2 「兩個引擎一致就通過」這個判準不成立

因為不一致與一致都不代表正確：

- **不一致但其中一個是對的**：上下標問題上，A **永遠**和 B 不一致，而 A 是對的。若規則寫成「不一致就送 AI」，則**每一題含化學式的題目都會被送去**，AI 被問爆。
- **一致但都錯**：兩個引擎都在同一份簡體字表下誤判 `胜肽`（台灣標準寫法，語料中出現 366 次）時，一致並不能救它。

**關鍵**：B 引擎沒有 `size`，所以上下標問題上 A 與 B 的「不一致」是**引擎能力的差異**，不是「文件內容的爭議」。把這兩者混為一談，是過去版本卡住的核心。

### 2.3 同一個缺陷，我修了三次，每次都「看起來對了」

這份工作期間的實際紀錄：

| 次 | 我寫的規則 | 為什麼錯 | 我為什麼沒發現 |
|---|---|---|---|
| 1 | `size < 8` 判定上標 | 只抓上標、漏下標 → `B₂` 變 `B2` | 我只看了 Q45 |
| 2 | 用 `bbox y0` 判上下標方向 | 用了錯的幾何依據 → `[PO⁴³⁻]` 上下標顛倒、`v＝²⁰` 誤判 | 我只看了 Q45 |
| 3 | `size` + 同 `block` 分組 | B 沒有 size；A 的上下標**跨 block** → `[Na⁺]` 仍被截斷 | 我只驗證了引擎 A |

**這就是 overfitting 的機制**：規則依賴引擎的實作細節（`size` 是否存在、block 如何切分），而這些細節**不在紙本上**。每次修完只驗證「這一頁對了」，沒有驗證「這個假設對不對」。

## 3. 為什麼過去那些版本難行

| 版本方向 | 為什麼難行 |
|---|---|
| **單一引擎** | 依賴該引擎的實作細節；細節一變，規則失效，且**失效時不報錯** |
| **三引擎投票** | 三票不代表真相。若兩個引擎共用同一個 CMap 詮釋，它們會一起錯 |
| **OCR 作為主要來源** | 把「抽取問題」換成「辨識問題」：引入簡體字、異體字、字型校對。`胜肽` 實測 366 次 vs `勝肽` 0 次，簡體字表會誤報 |
| **一致就通過、不一致送 AI** | 不一致的量太大且**成因單一**（上下標），送 AI 是把幾何問題當語意問題問 |
| **三引擎 + OCR 全上** | 每加一個來源就多一組不一致，不是多一個真相。校對規則的數量爆炸 |

**共同的缺陷**：都假設「多數一致 = 真相」，而沒有區分**「引擎量的是不同的物理量」**。

## 4. 修正後的觀點

### 4.1 兩個引擎不是兩個投票者，是兩個量不同物理量的儀器

| 引擎 | 可靠於 | 不可靠於 |
|---|---|---|
| **A (PyMuPDF)** | 字級（`size`）→ 判定上下標 | 格子表的欄位間隙（答案卷黏成一行） |
| **B (poppler)** | 精確幾何位置 → 格子表、欄位、座標 | 無字級 → 上下標字元被拆散 |

**所以正解不是「投票」，是「分工」**：

- 上下標 → 用 A 的 `size`
- 格子間隙／欄位 → 用 B 的幾何
- 讀序、行分組 → 用**垂直重疊**（兩引擎都有的 bbox，不依賴任一引擎的 line 切法）

### 4.2 不一致要**分類**，不是全部送 AI

不一致有兩種，處理方式完全不同：

| 類型 | 例子 | 處理 |
|---|---|---|
| **幾何可解釋** | 上下標、格子間隙、行分組 | **寫規則修**（確定性、免費、可重現） |
| **幾何不可解釋** | 語意缺漏、選項對不上、疑似誤植 | **送模型判**（貴、慢、需人確認） |

實測：這份卷的 12.5% 不一致**全部落在「幾何可解釋」**。修好幾何規則後，真正需要模型判的可能只剩 1–2 題。

### 4.3 規則必須對兩個引擎都成立

**這是過去所有版本都沒有做的檢驗**：寫規則時，必須同時在 A 與 B 的讀數上驗證。若規則只在 A 上成立，它就是 overfitted。

## 5. 模型的分工（依能力分級）

模型的定位不是「取代抽取」，是**補規則的洞**。不同等級適合不同工作：

| 等級 | 適合的工作 | 理由 |
|---|---|---|
| **規則（無模型）** | 幾何問題：上下標、間隙、行分組、題號分段 | 確定性、可重現、零成本。**能寫規則就寫規則** |
| **小型本機模型** | 大規模初篩、明顯異常（亂碼、截斷、空格） | 快、便宜、可對整份語料跑 |
| **中型本機模型** | 語意層判斷（選項與題幹是否呼應、是否漏字） | 需理解力，但不需要世界知識 |
| **大型地端模型** | 難題仲裁、需要專業知識的判斷（醫學、化學式） | 慢、吃記憶體，只用在規則與小模型都無解時 |

**分級原則**：從最便宜的方法開始，只有前一個解決不了才升級。過去的版本常直接跳到最貴的方法（AI 判斷全部），這是 token 消耗的來源。

## 5.1 實測：MTPLX 9b 與 35b 的能力分級

**測試設計**：把 10 題「幾何規則無法解釋」的題目餵給兩個模型。
這 10 題的答案是**已知的**（全部是上下標問題，ground truth = `SUPERSCRIPT_FLATTENED`），
所以「模型答對」與「模型亂猜」可以區分。

| 題 | ground truth | 9b 判定 | 秒 | 35b 判定 | 秒 |
|---|---|---|---|---|---|
| 9 | SUPERSCRIPT_FLATTENED | ✓ | 14.0 | ✓ | 9.3 |
| 11 | SUPERSCRIPT_FLATTENED | ✓ | 18.7 | ✓ | 3.5 |
| 34 | SUPERSCRIPT_FLATTENED | ✗ `OPTION_MERGED_INTO_STEM` | 9.0 | ✓ | 8.4 |
| 37 | SUPERSCRIPT_FLATTENED | **未解析** | 20.7 | ✓ | 7.4 |
| 41 | SUPERSCRIPT_FLATTENED | ✓ | 8.9 | ✓ | 18.7 |
| 45 | SUPERSCRIPT_FLATTENED | **未解析** | 19.1 | ✓ | 5.8 |
| 52 | SUPERSCRIPT_FLATTENED | **未解析** | 16.5 | **未解析** | 24.7 |
| 53 | SUPERSCRIPT_FLATTENED | **未解析** | 18.7 | ✓ | 10.8 |
| 63 | SUPERSCRIPT_FLATTENED | ✓ | 7.7 | ✓ | 6.2 |

| | 9b | 35b |
|---|---|---|
| **正確** | 4 / 10 | **9 / 10** |

### 兩個關鍵發現

**發現 1：模型大小不直接決定速度。** 35b 比 9b **快且更省 token**。
原因是**推理失控**：9b 在 5 題上把預算全部耗在推理迴圈（`reasoning_tokens = 3000`，產出 0 字）。
大模型反而更早收斂。所以「用小模型省成本」在推理模型上不成立。

**發現 2：提示詞決定推理是否失控。** Q52 原始提示詞下，兩個模型都把 3000 token 燒在推理、完全不吐答案。
加入「**碎片 = 上下標被推出原位，不要試著解讀碎片**」這句後：

| | 原提示詞 | 優化提示詞 |
|---|---|---|
| 35b reasoning | 3000 tokens（失控） | **431 tokens** |
| 35b 耗時 | 24.3 s | **4.1 s** |
| 35b 判定 | 無 | **正確** |
| 9b | 3000 tokens（仍失控） | 3000 tokens（仍失控） |

**模型卡住的原因不是不會判，是它試圖「理解」碎片的語意**（`max m -5` 是什麼？）。
告訴它「這是位移，不需要解讀」，推理就從 3000 token 降到 431。

### 全卷驗證：35b 對引擎 B 的全部 80 題

刻意用**引擎 B**（最壞情況，碎片最多）當輸入，驗證模型的上限：

| 判定 | 題數 |
|---|---|
| OK | 66 |
| SUPERSCRIPT_FLATTENED | 11 |
| GLYPH_DAMAGE | 2 |
| 未解析 | 1 |

- 成本：prompt 70,256 + completion 51,110 tokens，**397 秒**（平均 5 s/題）
- **漏判 0 題**：幾何規則已知含碎片的題目，模型**全部**找出來
- **額外找出 3 題**：Q5、Q72（規則漏掉的上下標）、Q2/Q67（字形）

### 模型找出了規則與人都沒發現的真實缺陷

**Q2：紙本本身印錯。** 模型說 `xenon acr lamp` 的字元順序錯置。
用 PyMuPDF span 級核對，**紙本上就是 `acr`（正確應為 `arc`）**，不是抽取錯誤，是**原始試題的誤植**。

**Q67：`C-胜肽`。** 模型說 `胜` 是簡體字。但實測台灣語料 `胜肽` 出現 366 次、`勝肽` 0 次——
這是台灣標準寫法，**模型的判定是錯的**。這證明模型需要與語料統計交叉驗證，不能單獨採信。

### 分級結論

| 工作 | 該用什麼 | 實測依據 |
|---|---|---|
| 幾何問題（上下標、間隙） | **規則** | 確定性、零成本。已解決 67/77 筆不一致 |
| 規則無法解釋的殘餘 | **35b** | 9/10 正確、5 s/題、漏判 0 |
| 大規模初篩 | 9b 可用但**不划算** | 4/10 正確、15 s/題、推理易失控 |
| 字形／異體字 | **語料統計，非模型** | Q67 模型誤判 `胜肽` |
| 需要世界知識的判斷 | 規則與 35b 都無解時才升級 | 本卷未出現此類題目 |

**一句話**：這份卷子裡，**35b 是唯一值得用的模型等級**；9b 在這個工作上既不夠準也不夠快。
但**模型只用在規則做不到的地方**——規則已處理掉 87% 的不一致，模型只需要看剩下的 13%。

## 6. 建議的路（可再現）

### 階段 1：幾何規則（已實作並驗證）

1. **抽取層用垂直重疊分組視覺行**（`extract.group_visual_lines`）

   PyMuPDF 的 `line` 不是讀者的行。一個帶上標的 line 會因為 box 較高而被切成**下一行的開頭**，
   `PO₄³⁻` 因此變成三條 line，`y0` 相差五點。依 `y0` 排序會把它們與正文交錯，公式就毁了。

   兩 span 屬於同一視覺行，若它們的 box 垂直重疊至少「較短者的一半」。
   這正是讀者的眼睛做的事，它不在意位移的方向，而且它能把真正分開的行分開
   （Q46 的折行 `中毒現` / `象。` 垂直完全不重疊）。

   實作細節：**刻意不限定同一個 block**。PyMuPDF 把 `C.[K⁺]－[PO₄³⁻]－[HCO₃⁻]`
   的每個片段放在各自的 block（38 / 39 / 40），要求同 block 會讓公式依然斷開。

2. **上下標用 `size` + 中心位移判定**（`extract.read_spans`），轉成 Unicode 上下標
3. **答案卷用引擎 B**（`golden_path._answer_sheet_text`）

   答案卷是格子表。poppler 把每一格讀成獨立 word，**保留格與格之間十點的空白**，
   `答案 Ｄ Ｂ Ｃ` 所以是五格，能與題號行依位置 zip。

   PyMuPDF 把同一列讀成**一個字串** `答案ＢＤＣＣＢ...`，沒有東西可以切。

   **實測（115090）**：

   | 讀法 | `parse_answer_table` 得到的題數 |
   |---|---|
   | 引擎 B（poppler） | **80** |
   | 引擎 A（PyMuPDF） | **4** |

   這不是「偏好哪個引擎」，是**兩個引擎量不同東西**：poppler 報「每一格在哪」，
   PyMuPDF 報「每個字形多大」。各自用在它量得好的表。

   這個缺陷原本會讓 S3 gate 以 `answer-not-on-sheet` 擋下整份——
   **gate 的抱怨是對的，是讀法錯了**。

4. **每一條規則同時在 A 與 B 上驗證**——規則只在 A 成立就是不合格

### 階段 2：不一致偵測（不融合，先讓它可見）

產出 `engine_report.jsonl`，逐題記錄：

```
{question, field, engine_a_text, engine_b_text, 
 disagreement: "geometry" | "semantic" | "none", rule: 哪條規則處理}
```

**先讓不一致可見，才談得上誰對。** 不融合，因為融合是「機器決定誰對」。

### 階段 3：模型補洞（依分級）

- 只把「幾何不可解釋」的不一致送模型
- 先用小模型掃一遍，只有小模型不確定才升級到大模型
- 模型的輸出一律**advisory**：它說哪裡可疑，人寫規則修（GOV-05）

### 階段 4：驗收

- 同一份卷跑兩次，位元相同（冪等）
- 規則在 A 與 B 上皆通過
- 模型判定的題目全部有對應的規則或人工紀錄

## 8. 本輪實作的全部量測結果

### 8.1 規則的正確寫法：建立在紙本性質上

三個修正在同一份工作上，驗證了同一件事：**規則要說的是紙本「是什麼」，不是引擎「怎麼做」。**

#### 修正 1：視覺行用垂直重疊分組

PyMuPDF 的 `line` 不是讀者的行。帶上標的 line 因為 box 較高會成為下一行的開頭，`PO₄³⁻` 因此變成三條 line。
改用**垂直重疊**後，公式完整（`[Na⁺]＋[K⁺]－[Cl⁻]`、`[PO₄³⁻]`）。

**關鍵**：**不限定同一個 block**。PyMuPDF 把 `C.[K⁺]－[PO₄³⁻]－[HCO₃⁻]` 的每個片段放在各自的 block。

#### 修正 2：span 之間的空格由「欄間隙」決定，不是一律無空格

視覺行分組合併了**不同欄**的 span（雙欄排版的四個選項在同一列）。一律用 `""` 串接把
`田野研究` `大眾和專業評論` … 黏成一個字。

量測 14 份卷的 6,223 個 span 間隙，**兩個群完全分開**：

| 間隙／字級 | 意義 | 例 |
|---|---|---|
| 0.00–0.09 | 同一詞內 | `[Na` + `⁺`（0.0pt）、PUA 選項標號 + 其後的字（0.0pt）|
| 0.50–5.00 | 不同欄／不同選項 | 雙欄排版（58.0pt / 12pt）、第三四選項（24.5pt / 12pt）|

門檻設在 **0.5**，落在兩群之間的空位，不貼近任何一邊。

#### 修正 3：`bare_number_space` 的兩個缺點

這個樣式接受「數字 + 空白 + 內容」開頭的行，而**兩種不相關的東西有同樣的形狀**：

- 真題目：`20 下列…`、`16 在 DSM-5…`、`64 3 歲小兒…`
- 頁首年份：`100 年第一次專門…`

**缺點 A：頁首年份被當成題號 100。**

全語料 **8,327 份中有 140 份（1.7%）** 把頁首年份讀成題號，`first=100..108`。
它們全是頁首 `NNN 年第一次…`，而真題目**沒有一題**以「年」開頭（量測 1,500 份：頁首 973 份全是「年」，題目 0 份）。
年份值域 100–114 與題號値域 1–100 **完全不重疊**。

這裡同時碰到**相容表意文字**：紙本印的是 `年`（U+F98E）不是 `年`（U+5E74），兩者是不同的
codepoint，**只有 NFKC 能把它們拉到一起**。不先 NFKC 就寫不出這條規則。

修正後：**140 份 → 0 份**。

**缺點 B：lookahead 要求 `{2,}` 個字元，漏掉「單字元開頭」的題目。**

`16 在 DSM-5…`、`64 3 歲小兒…` 在第一個空白前只有一個字元。
量測 300 份同型卷：**40 個錨點**的開頭正好是一個字元。改成 `{1,}` 後，

## 9. 這次工作的真正教訓

三次修錯都是同一個形狀：

| 次 | 規則依據 | 為什麼錯 |
|---|---|---|
| 1 | `size < 8` | 依賴「引擎 A 有 size」。引擎 B 沒有 → 規則在 B 上失效 |
| 2 | `bbox y0` | 用了錯的幾何依據（該用 baseline 中心） |
| 3 | 同 `block` 分組 | 依賴「引擎 A 如何切 block」。A 把公式片段分到不同 block → 公式仍斷開 |

而正確的三條規則，依據全都是**紙本的性質**：

| 規則 | 依據 |
|---|---|
| 垂直重疊 | 讀者的眼睛就是這樣分行的 |
| 欄間隙 > 0.5 字級 | 紙本的欄距就是比詞距寬，兩個群在 14 份卷上完全分開 |
| 題號後不接「年」 | 紙本的年份與題號値域不重疊（100–114 vs 1–100）|

**驗證方法也變了**：不是「這一頁看起來對了」，而是「**同一條規則在兩份引擎、在 8,327 份卷上各是什麼結果**」。
140 份的頁首年份就是這樣找出來的——它在單一案例上完全看不出來。

## 10. 版本代差與路由機制

### 10.1 代差確實存在，而且界線在 102 年

量測醫事檢驗師全部 192 份題目卷的題號樣式：

| 年份 | 主要樣式 | 份數 |
|---|---|---|
| 100–101 | `bare_number_space` | 12 + 12 |
| **102** | **混合 `bare_number_space` 6 + `number_dot` 6** | 12 |
| 103–115 | `number_dot` | 每年 12 |

再看兩代的物理特徵：

| 世代 | 年份 | 題號後 | 選項標記 | PUA 字元 | 抽取行數 |
|---|---|---|---|---|---|
| **Gen 1** | 100–102 | 空白 | **私用區繪製** | **~323** | 240–277 |
| **Gen 2** | 103–115 | 句點 | ASCII 字母 | **0** | 413–430 |

**102 年是轉換年**：同一年的 12 份卷，兩種都有，各 6 份。
一條寫給某一代的規則，對那一年的另一半是錯的。

### 10.2 藥師的代差界線不同

| 科目 | Gen1 | 轉換年 | Gen2 |
|---|---|---|---|
| 醫事檢驗師 | 100–102 | 102（6+6）| 103–115 |
| **藥師** | 100 | **101（6+6）** | 102–107 |

**這是路由必須依「紙本特徵」而非年份的實證**：兩個科目的代差年份不同。

### 10.3 路由實作（`src/qbr/generation.py`）

判斷順序是**紙本的性質優先，年份最後**：

1. PUA 字元數 ≥ 50 → `gen1_pua_space`（實測 ~323 vs 0，中間沒有模糊地帶）
2. PUA = 0 且行數 ≥ 340 → `gen2_dot_letter`
3. 以上不成立 → 用分段器選出的樣式
4. 最後才用年份

驗證結果（全語料、**全部 high confidence**）：

| 科目 | gen1_pua_space | gen2_dot_letter |
|---|---|---|
| 醫事檢驗師 (192) | 30 | 162 |
| 藥師 (90) | 18 | 72 |

**路由只回報，不用來拒絕。** 無法分類的卷仍然走預設規則，且「無法分類」這件事被記錄下來——
一個會安靜丟掉不認識東西的路由，比沒有路由更糟。

### 10.4 批次驅動器（`scripts/batch_run.py`）

三個刻意的設計：

- **不因第一個失敗而停止**。批次有用的產出是失敗的「形狀」，停下來就看不到
- **不寫入語料庫**。輸出到工作目錄，每卷一個資料夾
- **不判斷任何題目**。它只量測、只回報

首次執行結果：

| 科目 | 卷數 | clean | 題數 | 耗時 |
|---|---|---|---|---|
| 醫事檢驗師 | 192 | 189 | **15,376** | 8.5s |
| 藥師 | 90 | 87 | **6,771** | 4.0s |

合計 **22,147 題**，13 秒。

### 10.5 六個失敗的診斷，以及「不寫規則」的決定

6 份 not-clean 全部被 gate 標記（**0 份安靜通過**）：

| 卷 | gate 說法 | 實際內容 |
|---|---|---|
| 1021_醫檢師_臨床生理學與病理學 | `duplicate-anchors-4` | 心電圖**座標軸數字**（`5 4 3 2 1 0 容積（L）`）、**多選題標號**（`③`）|
| 1001_藥師_藥物治療學 | `duplicate-anchors-3` | 題幹中的**數值**（`28 天`、`40 mg/dL`、`40 mg bid`）|
| 1091_醫檢師_臨床血液學 | `gaps-9-in-1..90` | 檢驗報告**數值**（`1 fL、reticulocyte 0.7%`）|
| 1092_醫檢師_臨床血液學 | `duplicate-anchors-2` | 同上 |
| 1002_藥師_藥劑學 | `duplicate-anchors-2` | 同上 |
| 1032_藥師_藥劑學 | `duplicate-anchors-2` | 同上 |

**這正是該停下來、不要寫規則的時刻。** 三類誤判（座標軸、選項標號、題幹數值）成因不同，
而它們唯一的共同點是「行首是數字」——那正是題號規則的定義。

**在規則層再加特例，就是把 overfitting 換一個地方發生。** 依既定原則，這裡請本地模型判斷。

## 11. 本地模型的工作型態：拆題，不要問大問題

### 11.1 實測：同一個模型，兩種問法，差距 12 倍

| 問法 | 耗時 | reasoning tokens | 結果 |
|---|---|---|---|
| **大問題**（「這些到底是什麼？如何修？風險？」5 個子問題的 JSON） | 31.0s | **4000（吃滿）** | **無輸出** |
| **拆題**（每個只問一件事，要求一行結論） | **2.2–2.7s** | **163–298** | **全部正確** |

### 11.2 三種問題型態的實測成本

| 型態 | 例 | 耗時 | reasoning |
|---|---|---|---|
| **事實辨識** | 「行 `40 mg/dL…` 的 40 是題號還是數值？」 | 1.5s | 163 |
| **事實辨識** | 「行 `5 4 3 2 1 0 容積（L）` 是題目文字還是圖表？」 | 2.6s | 298 |
| **分類判斷** | 「這三類是同一種問題還是三種？」 | **23.5s** | **3000（吃滿）** |

**判準**：**問「這是什麼」（事實）便宜；問「這該怎麼辦」（判斷）爆炸。**

模型對事實的辨識精準且便宜——三個案例全部正確：
- 座標軸 → 「圖表的一部分（座標軸刻度與軸標籤），非題號」
- 題幹數值 → 「40 是數值（mg/dL 濃度），非題號」
- 選項標號 → 正確識別為多選題的圓圈數字

### 11.3 因此的工作型態

1. **拆成一題一問**，每個問題只要一行結論，`max_tokens` 給 1500–2000（足夠推理但不失控）
2. **問事實，不問判斷**。判斷由主模型做，本地模型只提供「這行是什麼」的辨識
3. **不要一次要 JSON 多欄位**。多欄位會讓它試圖規劃，然後失控
4. `reasoning_content` 可用（實測 1,656 字元且合理），但**不要依賴它**——它是推理的副產品，不是輸出

### 11.4 模型分工（本輪確立）

| 工作 | 用什麼 | 依據 |
|---|---|---|
| 幾何問題（上下標、間隙、行分組）| **規則** | 確定性、零成本 |
| 題號誤判辨識（「這行是什麼」）| **35b 拆題** | 2.5s/題、正確 |
| 幾何無法解釋的題目品質判斷 | **35b 完整包** | 9/10 正確、5s/題 |
| 代差路由、批次彙整、規則撰寫 | **主模型** | 需要跨卷推理 |
| 字形／異體字 | **語料統計，非模型** | Q67 `胜肽` 模型誤判 |
| 需專業知識的仲裁 | 地端大模型（**非恆常**）| 只做一次性任務 |

**9b 不用於此事**：4/10 正確、推理易失控、比 35b 慢（實測 15.2s vs 10.0s/題）。

## 12. 更正卷（MOD）與「距離規則」之誤刪（本輪）

### 12.1 更正卷不是附註，是重新發布的答案表

考選部的 MOD 檔（`測驗題標準答案更正`）有兩個部分，且**兩者都要讀**：

1. **重新發布的答案表**，變更的格子印 `＃`
2. **`備註`**，說明 `＃` 的意思

只讀備註 → 其餘 78 題仍來自較舊的 ANS 卷。實測 115090 兩者一致，這正是錯誤不會被察覺的原因。

### 12.2 五種備註句型（全語料 1,375 份 MOD 計數）

| 句型 | 筆數 | 意義 |
|---|---|---|
| `一律給分` | 677 | 送分 |
| `答Ａ、Ｂ給分` | ~663 | 接受集 |
| `答Ｂ或Ｄ或BD者均給分` | ~663 | 接受集＋組合 |
| `除未作答者不給分外，其餘均給分` | 47 | **送分**（未作答不給） |
| `答Ａ給分` | ~41 | 接受集 |

**`除未作答者不給分外，其餘均給分` 一開始漏了**。它與 `一律給分` 同義（差別只在空白卷不計分），答案是四個選項全收。少了這條，**750 → 699 筆送分**、23 份卷的 `＃` 看起來毫無解釋。

### 12.3 三個真正的 bug（皆已修，皆有量測）

**(a) 全形逗號。** `parse_corrections` 先做 NFKC，`，` 變成 `,`。只用 `，` 寫的樣式在 NFKC 之後什麼都匹配不到。

**(b) 從「第一個」備註讀起。** 某些卷的答案表標頭是 `第1題第2題…`，於是內文出現 `…第10題答案…`，而第一個 `備註` 在表格自己的標籤裡（`備註。題號第1題…`）。從那裡起搜，`第10題` 會開始一段跨過整張表、結束於 `第14題答B給分` 的匹配——**吞掉第 14 題，並替第 10 題捏造一筆更正**。改為從**最後一個** `備註` 讀，並先剝掉標籤。

**(c) 組合答案被當成選項標籤。** `答Ｂ或Ｃ或BC者均給分` 裡，`B`、`C` 是選項標籤，`BC` 是「同時劃記 B 和 C」的組合。本語料 282 份卷**全是單選**，組合永遠不可能對上任何選項。混在一起時，gate 的 `answer-not-on-sheet` 在 1152 醫檢師 **6/6 份**都告警，指稱 `BC`、`BD` 是卷上沒有的答案——**告警對它拿到的資料正確，對那份卷錯誤**。分開成 `labels` 與 `combinations` 後，mismatch 6 → 0。

修正後全語料：**1,375 份 MOD、2,390 筆更正、每一個 `＃` 都有對應備註、0 缺失**（用 `canon.parse_answer_table` 自己的題號解析器驗證，不用自寫正則——自寫的 `\d{1,3}` 會把 `0102030405` 讀成 `010, 203, 040`）。

### 12.4 `collapse_repeated_draws`：一個為舊架構寫的規則，誤刪了 192 組選項

**這是本輪最重要的發現**，也是「不要用再疊一層回答不確定」的實例。

```python
def collapse_repeated_draws(lines, window=12):
    """刪掉前 12 行內出現過相同內容的行。"""
```

它存在的理由是：印刷檔每頁重畫表頭數次，兩個引擎交錯方式不同。**但那是 `mask_chrome` 出現之前的事。** 一旦 chrome 改用「在其他頁的同一個垂直位置重複出現」——一個**文件的性質**，不是**距離**——距離規則就只剩破壞可做。

**症狀**：Q59 選項全空。抽取層明明是對的：

```
page=4 y0=112.13 '\ue18cApo A-I  \ue18dApo B-100  \ue18eApo B-48  \ue18fApo C-II '
```

`normalize_pretty` 之後消失。因為**第 3 頁底部 Q11 的選項行與它逐字相同**，相距 9 行。

**量測（282 份，醫檢師＋藥師）**：

| | collapse=True | collapse=False |
|---|---|---|
| clean 卷 | 276 | 276 |
| 題數 | 22,147 | 22,147 |
| **選項<4** | **293** | **101** |
| 空題幹 | 0 | 0 |
| 殘行 | 1,460 | 1,460 |

唯一差異就是**修好 192 組選項**（+3,600 字元＝原本被誤刪的選項文字）。其餘每一項完全相同。

**移除後的連鎖效果**（醫檢師 192 份）：

| | 之前 | 之後 |
|---|---|---|
| 選項<4 | 161 | **61** |
| 答案與選項不符 | 100 題 / 53 份 | **61 題 / 22 份** |
| gen2 選項<4 | 105 | **10** |

而且**「答案與選項不符」現在與「選項<4」在 192/192 份卷上完全相同的題號集合**。訊號從雜訊變成了事實：每一個不符都真的是「選項在圖裡」。藥師同樣 40 = 40。

### 12.5 這條規則的教訓

三條正確的規則是：**垂直重疊**（讀者的規則）、**間隙 > 0.5 × 字級**（紙張的欄距）、**題號後不接 `年`**（民國年 100–114 vs 題號 1–100）——全部是**紙張的性質**。

`collapse_repeated_draws` 是**抽取層的性質**（引擎怎麼交錯表頭）。它在抽取層修好之後，就從「補償」變成「傷害」。**規則要建立在紙張上，不是建立在引擎上。**

## 13. `mask_chrome` 的門檻也是一種 overfitting（本輪）

### 13.1 症頭：五份卷各丟掉 3–6 組選項

golden path 路徑（`mask_chrome` → `text_from_rows` → `segment_mixed`）比 batch 路徑多出 20 組「選項<4」：

```
1062_醫事檢驗師_生物化學與臨床生化學      Q14,21,43,50,65,72
1062_醫事檢驗師_臨床血清免疫學與臨床病毒學   Q13,41,48,77
1062_醫事檢驗師_微生物學與臨床微生物學      Q13,35,42,64
1022_醫事檢驗師_臨床血清免疫學與臨床病毒學   Q31,44,55
1062_醫事檢驗師_醫學分子檢驗學與臨床鏡檢學   Q28,56,70
```

### 13.2 根因：這份卷的選項在頁底被切斷

Q14 的選項 `A.` 落在頁面最底，其餘選項文字跑到下一頁，所以該頁只剩下 `A.` 這一小段。而 **`A.`／`C.`／`D.` 每次都落在 `y=805.6`** —— 那正是印刷檔印頁腳的位置。

```
page 2 y0=805.60 x0=38.9 'A.'      ← Q14 的選項標籤
page 3 y0=805.60 x0=38.9 'C.'      ← Q21 的選項標籤
page 4 y0=805.60 x0=38.9 'D.'      ← Q28 的選項標籤
```

舊規則「在 ≥3 頁的同一個 y 重複出現即為 chrome」，12 頁裡出現 3 次就成立 → **選項標籤被當成頁腳刪掉**。

### 13.3 這是標準的 overfitting

規則建立在**版面座標**上，而不是**紙張的性質**。真正的頁腳與被切斷的選項標籤在**同一個位置、不同的頁**，沒有任何距離或次數門檻能分開它們。

### 13.4 正確的規則：頁眉頁腳印在「每一頁，封面除外」

**這就是紙張的性質**：一個印刷表單重複它的頁眉頁腳時，會在**它適用的每一頁**都重複；封面印的是標題。

量測 282 份卷、所有「固定位置重複」的候選：

| 出現頁數 | 數量 | 是什麼 |
|---|---|---|
| 恰好 `pages[1:]` | **48** | `代號：NNNN` 等真 chrome |

## 14. 分界的重新劃定（本輪，第 4 次轉向）

### 14.1 使用者的診斷，與它為什麼是對的

使用者指出：這個流程一直在「制定規則 → 寫成 Python → 遇到反例 → 再制定規則」。這正是第 9 節
早已記下的教訓，只是這一輪又重演了一次——`option_alphabet`（第 13 節之後的那個修補）之所以存在，
是因為某個扁平上標碎片剛好落在選項標記前面，於是標記被誤判為缺字。**那條規則問的是引擎的輸出，
不是紙張的性質。** 問引擎輸出的規則永遠會有下一個反例。

### 14.2 新的分界：以「問題的種類」劃分，不是以「方便」劃分

| 腳本量測（紙張的性質） | 模型判讀（對文字的解讀） |
|---|---|
| 頁數、頁碼、座標、字型、字級、基線 | 題幹在哪裡結束 |
| 題號 `1..N` 唯一且有序 | 上下標屬於哪個字 |
| 選項標記碼（連續且等計數的四個） | 哪裡是圖、哪裡是表 |
| 答案卷印出的題數 | 一段文字是選項還是內文 |
| 每個 span 的欄間隙（> 0.5×字級） | 失去映射的字元該如何處理 |

**判準**：如果一個問題的答案可以由「紙上某個可量測的量」回答，就留在腳本；如果它需要「讀懂
文字」，就交給模型。`repair.py` 不再新增內容規則。

### 14.3 讓單一提示詞足夠的關鍵：可查核的「重新分配」

模型不重寫文字，只做**指派**：哪些格是題幹、哪些格是哪個選項、哪些格是頁面雜訊；另外可對
**單一格**給出該格字元的重排（`perm`，用來把被推出去的上下標放回原位）。

於是只需要**兩條與題型無關**的查核，`reflow.verify()`：

1. **containment** — `perm` 可以刪字，**不可以增字**。幻覺字元過不了這一關。
2. **coverage** — 每一格恰好被指派一次。漏題過不了這一關。

這兩條對化學題、表格題、圖片題是同一條，因為它們問的不是「內容對不對」，而是「有沒有無中生有
或遺漏」。**這就是「只能整理不能推演語意」從一句叮嚀變成可執行檢查的方式。**

> 本輪抓到一個真實的漏洞：第一版 `verify()` 只檢查「掛在 slot 上的 perm」，**沒有檢查頂層
> `perm` 字典**，而 `_compose()` 也完全忽略它。實測：`下列何者為水解酶？` 對一格印著
> `下列何者為酯解酶？` 的 perm，被判為 admissible。已修正，並補上 3 個測試。

### 14.4 但 containment + coverage 還不夠：模型可以「系統性位移」

`1152_醫事檢驗師_生物化學與臨床生化學` 的實測（35b，1,651 秒，115,628 tokens，其中
111,182 是思考）：

* 421 格中 420 格被指派、80 題、**0 個幻覺字元、0 個重複、0 個遺漏**。
* 但**第 55 題開始每一題都位移一格**：Q55 的題幹印在兩格上，模型只把第一格放進題幹，
  第二格 `少而延長藥效時間？` 被放進選項 `A`，於是此後每個標籤都對錯了正文。
* **coverage 看不出來**——每一格都被指派了，只是被**貼錯標籤**。

這是 containment/coverage 這組查核的極限，也是本輪最重要的發現。補救辦法不是再加一條內容規則，
而是**把紙張已經印出來的骨架讀出來**。

### 14.5 `reflow.skeleton()`：紙張自己聲明的結構

兩個標記都是**印出來的**，所以都可以直接讀，不該用推論的：

* **題號**（唯一、依序）→ 每個題目的起點格
* **選項標記**（`opt:X` 提示，或 ASCII `A.`）→ 每個選項的格

實測（醫事檢驗師 101–115，162 卷可讀）：

| 指標 | 修正前 | 修正後 |
|---|---|---|
| 骨架完整（1..N 且四標籤齊全） | 36.1% | **95.7%** |
| 骨架題數 = 答案卷題數 | 86.7% | **98.8%** |

藥師（78 卷可讀）：骨架完整 **89.7%**、題數相符 **94.1%**。

**這改變了整個架構的重量分配**：絕大多數卷子的結構是**讀出來的**，不是**推論出來的**。
模型因此只需要負責骨架做不到的三件事：上下標、圖、以及骨架不完整的那 4–10% 卷子。

### 14.6 兩個獨立讀法的比對（`compare_skeleton.py`）

骨架與幾何讀法都是同一批格的讀法，所以可以直接比對，**不需要模型、每卷可跑、成本為零**。

醫事檢驗師 101–115：可比對 12,400 題，**完全一致 11,981 題（96.6%）**；每年 94.3%–99.8%。
`absent-from-skeleton = 0`、`absent-from-geometry = 0`（**兩邊都沒有漏題**）。

這是本專案第一次有一個**與題型無關、對每一題都成立**的品質指標。

### 14.7 本輪修好的四個真實缺陷（全部在抽取層，且全部是先量測再修改）

**1. `group_visual_lines` 從未排序自己的輸出。**
分組（哪些 span 屬於同一行）是對的；**行的順序**從來沒有排過，靠 PyMuPDF 的自然順序碰運氣。
實測 `1062_醫事檢驗師_生物化學與臨床生化學` 第 2 頁：**8 處逆序**。Q21 的選項印成兩欄，
引擎先報右欄，於是 `B.β-胰島細胞` 排在 `A.α-胰島細胞` 前面，標籤順序被破壞。
修正：`lines.sort(key=top, bottom)`。既有的 86 個測試全過（它們原本只是剛好沒踩到）。

**2. 零寬 span（`ZWAdobeF` 字型）跨越欄間隙，把三個選項黏成一格。**
`_spans_of_page` 現在丟棄 `x0 == x1` 的 span。實測：3 個年度 90 個零寬 span，
**全部**是 `ZWAdobeF` 字型，內容全是 `B`/`P`/`PB`（Adobe 字形命名慣例，不是內文）。
`1012_醫事檢驗師_生物化學與臨床生化學` Q34：x=91.6 與 x=183.1 兩個零寬 span 讓 87 點的
欄間隙讀成「沒有間隙」，A/B/C 三選項變成同一格。

**3. `small` 逃生門（任一邊是小型字就合併）本身也是 overfitting。**
已改為**基線偏移**判準：小字要相對於前一個 span 抬高/降低才算上下標。
實測兩年兩類：**4,172 次**小字合併在間隙 0–4 點（上下標），**928 次**在 10 點以上（欄）。
`_SUPERSCRIPT_GAP_RATIO = 0.9`。

**4. 題號格的三種印法。** 新卷 `56.有關血清…` 一格；舊卷題號**單獨一格**（`13: '1'`）；
還有整格就是數字者。另外改成**依序期待下一個號碼**，避免把年號、頁碼當題號。

### 14.8 圖片題的精確觸發條件（不需要新的啟發式）

比對中發現：`1152_醫事檢驗師_臨床血液學與血庫學` Q16 的選項印成 `A.` `B.` `C.` `D.`
**後面什麼都沒有**——選項是血液抹片照片。兩個讀法都同意「結構是四個選項」，也都沒有文字，
因為**紙上本來就沒有文字**。

實測已打包題庫 21,150 題中：

* **四個選項都空（圖片題）= 88 題（0.4%），涉及 38 卷**
* 部分選項空 = 53 題

這是圖片題的觸發條件：**不是關鍵詞，是「標記存在但文字為空」這個量測結果**。
`vision.py` 負責把該區域裁切出來交給同一個 35b（它有 vision）判讀。

### 14.9 成本實測（本機，成本可不計，但時間要計）

| 工作 | 時間 | tokens | 備註 |
|---|---|---|---|
| 單題事實詢問（Q45） | 5.4 s | 1,651 | 思考 630 |
| 整卷重排（1152，35b） | 1,651 s | 115,628 | 思考 111,182；**建議 24k 起跳的預算** |
| 整卷重排，第一次（預算 90/行） | 209.9 s | 22,950 | **全部花在思考，一個字都沒輸出** |
| 視覺裁切判讀（心電圖區） | 595 s | 937 | 與重排同時跑，數字受競爭影響 |
| 骨架量測（180 卷，純腳本） | ~200 s | — | 無模型 |

教訓：**推理模型的思考佔用 `max_tokens`，預算必須按「每題」給**，不能按「每行」給。
`COMPLETION_TOKENS_PER_QUESTION = 900`、下限 `MIN_COMPLETION_TOKENS = 24000`。

### 14.10 這一節要回答的一句話

> **舊做法**：遇到一種題型就加一條規則，規則永遠追不上題型。
> **新做法**：紙張能量測的留在腳本（骨架、座標、標記），需要讀懂的交給模型（提示詞），
> 而模型的輸出用**與題型無關**的兩條查核（不增字、不漏格）與**紙張自己印出的骨架**交叉驗證。
> 規則不再是內容規則，而是**查核規則**；查核規則的數量不隨題型成長。

## 15. 本機模型做事的三個平衡點（本輪實測）

### 15.1 結論先寫

| 工作 | 思考 | 時間 | 輸出 tokens | 正確性 | 決定 |
|---|---|---|---|---|---|
| 看圖（90 次判讀，含正負對照） | 開 | 4.4 s | 23,702 | **45/45** | 都可以 |
| 看圖 | 關 | **2.1 s** | 9,589 | **45/45** | **用關** |
| 讀整卷文字（易卷） | 開 | 280 s | 33,025 | 79/80 | 用開 |
| 讀整卷文字（易卷） | 關 | 50 s | 5,059 | 69/80 | 不夠 |
| 讀整卷文字（難卷） | 開 | 197 s | 21,551 | **80/80** | 用開 |
| 讀整卷文字（難卷） | 關 | 48 s | 5,146 | **13/80** | **不可用** |

一句話：**「看圖」關掉思考完全沒有損失；「讀整卷文字」關掉思考會崩**，而且在難卷上崩到
13/80——但**不會漏題**（12 卷、960 題，`漏題合計 0`）。失敗的形式是「整題位移」，不是「消失」。

### 15.2 為什麼看圖可以關、讀卷不行

看圖的任務是**一次判一個局部**：這格裡是圖還是字。答案短、判準在圖上、不需要記住前面 79 題。
讀卷的任務是**維持一個跨 421 格的計數**：第 3 格屬於第 3 題、第 4 格是它的選項 B……一旦某題的
題幹跨兩格而模型只放了第一格，此後**每一題都位移一格**。這個位移不會被 coverage 抓到（每格都
被指派了），只能靠**紙張自己印出的骨架**抓——而實測正是這樣被抓到的。

**所以思考不是「品質旋鈕」，是「能不能維持長距離一致」的能力。**

### 15.3 最貴的失敗：預算被思考吃光

實測 `1152_醫事檢驗師_臨床血液學與血庫學`（難卷，思考開）：

```
2,370.7 s   輸出 156,400 tokens   其中 156,398 是思考   讀出 0 題
```

**156,400 正好等於當時給的預算**——不是模型停不下來，是**天花板就是綁住它的東西**，答案一個字都
沒寫。這是本專案最貴的一次失敗（40 分鐘換 0 題）。

修正：**答案與思考分開估，相加後才送出**。

```python
answer_budget(count, lines)      # 隨卷子大小成長；實測 80 題 ≈ 5,000 tokens
reasoning_budget(lines)          # 天花板；實測 41 / 264 tokens per cell，故取 500
completion_budget = answer + reasoning   # 思考關時不加
```

> **教訓**：推理模型的 `max_tokens` 是**思考與答案共用**的。任何「按卷子長度給預算」的做法都會
> 在難卷上把預算全餵給思考。**天花板必須是有限的，而且必須與答案分開算。**

### 15.4 圖片觸發條件：把「提到圖」換成「量到圖」

舊的觸發是題幹含「圖」：醫檢師範圍內有 **523 題**提到圖，其中絕大多數不需要裁切。
新的觸發是兩個**量測**：

| 觸發 | 判準 | 醫檢師 101–115 命中 |
|---|---|---|
| `embedded-image` | PDF 內嵌圖物件與題目所在區域重疊 | 287 |
| `options-without-text` | 選項標記印了，後面**什麼都沒有** | 4 |

合計 **291 題**（全 162 卷、12,923 題）。門檻 `min_image_area=400 pt²` 不是隨意訂的：
整卷 162 卷共有 7,853 個圖物件，其中 **4,323 個高度為 0**（200×0 的分隔線），另有大量 13×46 的
小標記。加上門檻後剩 780 個，正是人會指的那種圖。

**三次修正，每次都是被「對照組」抓到的，不是看出來的：**

1. **同一題在兩頁各被裁一次。** 題幹在第 3 頁、四個選項在第 4 頁，於是兩頁都觸發、都裁切，
   第 3 頁那張只有題幹，模型說 `text` 且**它是對的**——錯的是觸發條件。改成**每題只回一個候選頁**。
2. **空選項的標記與圖「剛好相鄰」。** Q16 的 `A.` 結束在 x=50、血液抹片開始於 x=50，
   重疊面積 = 0，於是裁切只框到四個字母。改成**空選項認領同一垂直帶的圖**。
3. **`options-without-text` 掛在錯的頁。** 它被掛到題目出現的每一頁，而它其實只關於選項。
   19 題空選項中有 **6 題的標記跨頁**（Q35 的 `A.` 在第 4 頁頁尾、`B./C./D.` 在第 5 頁頁首），
   這種題目**無法用單一矩形誠實裁切**，因此回報 `split=True` 而不是硬裁。

### 15.5 對照組的設計（為什麼 90/90 有意義）

只測「圖片題 → 說是圖」是沒有意義的，因為**全部答 `figure` 的模型也會滿分**。所以測資同時包含：

* **正對照**：被量到有內嵌圖的題目（血液抹片、心電圖、結晶、蟲卵）→ 必須答 `figure`
* **負對照**：**沒有**觸發任何圖片條件的題目 → 必須**不**答 `figure`

結果：**figure 42/42、text 48/48，合計 90/90**。兩側都對，模型才真的在判別。

模型描述也確實可用（非僅標籤），例如 Q16 思考關閉時輸出：

> 四張標號 A、B、C、D 的周邊血液抹片顯微照片…A 為多顆紅血球黏聚成團（凝集）；
> B 為稜形/紡錘形細胞（裂紅血球 schistocyte）…

### 15.6 推理控制只有一個拼法有效

實測同一張圖、同一提示詞，四種寫法：

| 寫法 | 時間 | 輸出 | 思考 tokens |
|---|---|---|---|
| 預設 | 4.4 s | 465 | 345 |
| `reasoning_effort: none` | 3.9 s | 465 | 345 |
| `reasoning_effort: low` | 4.0 s | 465 | 345 |
| `reasoning.{effort: low}` | 3.9 s | 465 | 345 |
| `thinking_budget: 0` | 3.9 s | 465 | 345 |
| **`chat_template_kwargs: {enable_thinking: false}`** | **1.7 s** | **173** | **0** |

前四種**完全被忽略**（輸出與預設一字不差）。只有最後一種有效。這是量出來的，不是文件寫的。

（54 對 80）。

### 16.2 這推翻了我自己在前一節的架構假設

我原本的設計是「**腳本量測紙張的性質、模型讀懂文字**」，並預期模型接手「組題」這件事。
量測結果不是這樣：

> **組題（哪一格屬於哪一題、哪一格是哪個選項）是幾何就能做到的事，而且做得比模型好。**
> 骨架讀的是紙張印出來的兩個記號——題號與選項標記——這件事**不需要理解語意**，
> 所以它落在「腳本能量測」那一側，不在「模型要讀懂」那一側。

我先前把「模型的輸出用兩條查核把關」當成主要防線（§14.3）。但一條**免費、精確、96.6% 一致**的
讀法存在時，正確的做法不是「用模型讀、再用骨架檢查」，而是 **「用骨架讀，模型只做骨架做不到的事」**。

### 16.3 模型真正該做的三件事（其餘都不要）

從本輪全部量測反推，模型**唯一**被證明有價值的地方：

| 工作 | 為什麼骨架做不到 | 實測 |
|---|---|---|
| **上下標重排（`perm`）** | 骨架只指派格，不重排格內字元 | 1152_生化：模型正確指出所有上下標已在文字層，**無需 perm** |
| **看圖** | 圖的像素不會產生文字格 | **90/90**（42 圖 + 48 字，含正負對照） |
| **骨架不完整的那 4.3%** | 紙張的記號沒描述它自己 | 7/162 卷 |

**其餘（組題、分選項、判斷題幹在哪裡結束）一律用骨架，不用模型。**

### 16.4 一個意外發現：提示詞的「無害欄位」會劇烈改變結果

同一卷、同一提示詞、`temperature=0`，**只改「年度」這一個欄位的寫法**：

| `年度` 的值 | 與骨架不同的題數 |
|---|---|
| `'115'` | 3 |
| `'115 年第 2 次'` | **1** |
| `'1152'` | **60** |
| `''`（空） | 52 |

**同一份輸入、同一個溫度，一個自由文字的欄位讓正確率從 1 題差變成 60 題差。**
（同一欄位值重複四次則完全一致：60/60/60/60——所以它不是隨機，是**對提示詞措辭的敏感**。）

修正：**科目與年度從提示詞移除**。它們對「排版還原」這個任務沒有任何用處，只提供了一個讓模型
分心的自由度。移除後，傳任何值結果都一樣（Δ=14/60/12 三次全部相同）。

> **教訓**：提示詞裡**任何模型不需要的欄位都是一個風險來源**。能用骨架回答的問題，
> 不要把資訊餵給模型讓它「參考」——那只是給它一個出錯的機會。

### 16.5 這一節要回答的一句話

> **骨架免費、精確、免模型，而且在組題上比 35b 準。**
> 所以流程應該是：**骨架先讀（免費）→ 只把骨架做不到的（上下標、圖、不完整卷）交給模型 →
> 模型的產出仍然用不增字／不漏格查核。**
> 模型不再是主要讀者，是**補件者**。

### 16.6 一個具體例子：表格題

`1122_醫事檢驗師_臨床血液學與血庫學` Q65 是「下列表中病患血型抗體普檢結果之判讀」，
紙上是一張 **17 格的表**（`Cell` / `IS` / `37°C` / `AHG (poly)` / `SC I` / `2+` / `0` / …）：

* **骨架**：17 格全部歸給 Q65 的題幹 → 與紙張一致
* **模型**：只把第一格當題幹，**整張表掉出題目之外**

那些 `2+`、`1+`、`3+` 曾被我的啟發式誤認為「被推出去的上標」（它們是 `small` 格、短、含 `+`），
但裁出原圖一看，**它們是表格的格子**，不是上標。骨架不需要知道這件事——它只問「這格有沒有
選項標記、有沒有題號」，兩者都沒有，於是它繼續屬於同一題。**這正是「紙張的記號」勝過
「對內容的猜測」的地方。**

## 18. 骨架的通用性：逐年、逐類科證明（本輪）

第 16 節說「骨架比模型準」。那句話當時只在**一個類科、六卷**上量過。這一輪把它推到
**四個類科、429 卷、101–115 年（100 年已放棄）**，而且要求**每一年都成立**，不是
平均起來好看。

### 18.1 這一輪之前，失敗是「整卷消失」，不是「差幾題」

量測方式：對每一卷，比對「紙張自己印的骨架」與「官方答案卷的題數」。

修前（第 1 次全庫量測，3,199 卷可判）：

| | 骨架完整 | 題數相符 |
|---|---|---|
| 全庫 | 2,458 / 3,199 = **76.8%** | 2,831 / 3,199 = **88.5%** |

這不是「差不多的及格」。看逐年就看得出來，失敗的卷是**整卷被判死**：

| 類科 | 年 | 修前完整 |
|---|---|---|
| 醫事檢驗師 | 101 | **6/12** |
| 藥師(一) | 104–115 幾乎每年 | **5/6**（每年固定死一卷） |
| 臨床心理師 | 101–115 | **29.8%** |
| 諮商心理師 | 101–115 | **31.2%** |
| 營養師 | 101–115 | **52.5%** |
| 社會工作師 | 101–115 | **58.1%** |

「藥師(一) 每年固定死一卷」是這一段最重要的線索：**同一個規則在 12 個年份上、
以同樣的方式失敗**，表示這是紙張的性質，不是某一卷的意外。

### 18.2 三個缺陷，每一個都是「一個規則修好一整個類科」

**(a) 左邊界（leftmost）— 修好 藥師(一) 10/12 年**

`1151_藥師(一)_藥學(三)(包括藥劑學與生物藥劑學)` 第 65 題的題幹內含一張表，
劑量欄的值是 `100`、`40`、`50`、`25`。骨架按閱讀順序找題號，看到 `65` 之後下一個
是 `100`，就把它當成第 100 題（規則允許「往前跳」代表紙張跳號），於是第 65 題的
窗口在表格處結束，**第 66–80 題全部遺失（15 題）**，而答案卷說 80 題。

判別方式：**真正的題號是它那一行的最左格**；表格裡的數字左邊還有格線或欄位。

> 量測：1,045 卷 / 76,120 題、10 個科目 —— 題目起點格是該行最左格的比例
> **76,116 / 76,120 = 99.995%**。

修後：藥師(一) 88.0% → **98.7%**，且**連續 10 個年份**從 5/6 變成 6/6。
社會工作師 58.1% → 82.7%、營養師 52.5% → 72.9%、臨床心理師 29.8% → 51.1%。

**(b) 邊界（margin）— 修好 2 卷「整卷消失」，其中一卷只讀到 4 題**

`1142_藥師(一)_藥學(二)(包括藥物分析與生藥學(含中藥學))` 第 3 題問溶解度積，
算式 `1.23×10⁻⁸` 折行，折下來的那一行是 `234.8）`。閱讀順序把它當成第 234 題，
第 3 題的窗口在選項前就結束 —— **80 題只讀到 4 題**。
`1091_醫事檢驗師_臨床血液學與血庫學` 以同樣方式在 `90.1 fL、reticulocyte 0.7`
上只讀到 24 題。

左邊界規則救不了它：那一格**自己單獨佔一行**，左邊沒有東西。

判別方式：**題號從紙張的本文邊界開始，折行從選項欄開始**。邊界由紙張自己量出來
（第 1 題的起點格就是左邊界）。

> 量測：被骨架**拒絕**的候選題號，全部落在邊界右側 **≥ 10.4 pt**；
> **0 卷**有任何被拒候選落在邊界 2 pt 之內。容忍值 4 pt 吸收字體左側 bearing 的零頭，
> 不是對失敗案例擬合出來的。

關鍵的收窄：邊界規則**只對「會被當成跳號」的數字生效**。恰好等於下一個期待值的格
一律接受 ——> 量測：**864 個題目起點坐在 x=31，而該卷第 1 題在 x=22**（第 1 頁之後
紙張改排版縮排）。對所有數字一體套用邊界規則會把它們全部丟掉。

**(c) 身分（identity）— 6 卷被併成同一把 registry key**

合併佇列時擋下：`duplicate candidate_key ... in 1052_藥師(一)_藥劑學(包括生物藥劑學)
and 1051_藥師(一)_藥劑學(包括生物藥劑學)`。

根因有兩層，都真的：

1. `resolve()` 的 catalog 比對**只比對年 + 科目，不比對場次**。1051 和 1052 因此
   解析到同一把 `moex:105020:305:33:1`。
2. `catalog_by_key()` 用**精確類科名**過濾，而 catalog 在不同年度把同一類科寫成
   `藥師（一）`（全形）與 `藥師(一)`（半形）。精確過濾讓 103/104 的列**根本沒被看到**，
   21 卷因此完全拿不到 key（12 卷 藥師(一)、9 卷 藥師(二)）。

> 量測：這四個類科的 429 列中，`(年, 場次, 類科, 科目)` **唯一**；
> `(年, 科目)` **不唯一**（45 組衝突）。
> 場次取自 catalog 自己的 `exam_label`（`105年第二次…`），與 registry 的 `exam_ordinal` 一致。

修後：429 卷全部解析成功、**0 衝突、0 缺 key**。

### 18.3 修後結果：逐年、逐類科

| 類科 | 卷數 | 骨架完整 | 題數相符答案卷 |
|---|---|---|---|
| 醫事檢驗師 | 180 | 174 (96.7%) | **180 / 180 = 100%** |
| 藥師 | 78 | 76 (97.4%) | **78 / 78 = 100%** |
| 藥師(一) | 75 | **75 / 75 = 100%** | **75 / 75 = 100%** |
| 藥師(二) | 72 | 71 (98.6%) | **72 / 72 = 100%** |
| **合計** | **405** | **396 / 405 = 97.8%** | **405 / 405 = 100.0%** |

**題數相符 100.0%** —— 這是「紙張自己印的題號」與「官方答案卷」兩份獨立文件互相印證，
所以 100% 是有意義的，不是同一份資料自己對自己。

剩下 9 卷不完整，全部是**已知的圖片題類**（`question-N-labels`：選項印在圖裡，
或 `①②③④` 子項目），而且**題數全部相符** —— 骨架知道有 80 題、知道每題在哪，
只是認不出圖裡的選項字母。這正是下一節要交棒給模型的地方。

### 18.4 這一節的方法論

- **逐年的數字比總平均重要**。「藥師(一) 每年固定死一卷」在總平均裡只是一格，
  在逐年表裡是 12 個同樣的失敗。
- **失敗要分類，不是全部送模型**。這一輪的 3 個缺陷，2 個是幾何、1 個是身分，
  **沒有一個需要模型**。
- **規則建立在紙張的性質上**：左邊界、本文邊界、場次，都是紙張或官方文件說了算，
  不是引擎內部狀態。
- **修完要重量，不要只跑測試**。測試 122 → 135 全過，但真正的證據是
  **題數相符從 88.5% 到 100.0%**。
- **規則要收窄到它該管的範圍**。邊界規則若一體套用會丟掉 864 個真題目起點；
  收窄成「只對跳號生效」之後才成立。

## 19. 審題介面：分類、可驗證的裁切（本輪交付）

使用者提出兩件事，都是「看不到就等於沒有」：

> 「**圖片的裁切我沒有辦法驗證**」——助手說裁了圖，但審題介面上看不到，所以對不對無法檢查。
> 「**審題介面需要分類**」——要按年 / 類科 / 科目系統性地審。

### 19.1 圖片裁切必須顯示，否則「讀了圖」是無法查核的宣稱

圖片題抽出來是**四個空選項**。在這之前，審題者看到的就是題幹 + 四行空白，
沒有辦法分辨「抽取把選項弄丟了」和「選項本來就是圖」。裁切就是分辨這兩者的量測，
而它**一直被寫到磁碟上、卻從來沒有顯示出來**。

修法：

1. `scripts/crop_run_figures.py`（新）—— 對每一個已打包的 run，把每一題的裁切存進
   run 自己的 `review-ui/crops/`，並記在候選列的 `image_refs`。
2. `review_ui/v2.html` 新增 `figureHtml()` —— 在選項下方顯示裁切 + 說明。
3. `build_review_queue.py` **把裁切複製進合併後的佇列**，並改寫路徑。

第 3 點是關鍵。裁切的路徑原本指向 243 個原始打包目錄，而審題伺服器只服務已註冊的
根目錄，所以每一個裁切都會 404：

> 量測：`GET /file` → **HTTP 404**，`exists: None`。
> 修後（複製進佇列）：**HTTP 200, 132,764 bytes, image/png**，`exists: True`。

複製 991 個檔案 / 251 MB，換來**佇列自足**：複製到哪、就在哪服務，圖跟著走。

> **順序也是一個缺陷**：第一次合併在裁切之前跑，佇列裡 `image_refs` 是 **0 / 30,440**。
> 合併必須在裁切之後。

### 19.2 圖片觸發器的第三、第四個缺陷（每個都被對照組抓到）

**(a) 每個選項要對到「自己的」圖，不是整題對到整頁的圖**

`1112_藥師(一)_藥理學與藥物化學` 第 80 題：四個選項標記在 x=45–58，四個化學結構在
x=57–332 —— 標記和它的圖**只差 1 pt**，而整題的標記聯集散在整頁（選項一頁三分之一），
聯集沒有垂直高度可以比對。舊的 `_claim_band` 用「所有格」對「所有圖」，什麼都認不到，
裁出來是四個光禿禿的字母 —— 模型照實說 `text`，**它是對的，錯的是觸發器**。

修法：**每一個格對自己的圖**（起點在標記右緣 `reach=8 pt` 內、垂直重疊、且不在標記左側）。

**(b) 跨頁的題目，續頁的最上方屬於這一題**

同一卷第 80 題：`A.` 是第 18 頁的最後一行，它的結構是**第 19 頁的第一件事**
（y=29–223），而 `B.` 從 y=232 才開始。只按標記畫框會從 y=229 起，把結構切掉。

修法：**續頁（不是題目的第一頁）從 y=0 起算** —— 續頁不可能知道這一題的內容從哪開始。

**(c) 選頁要選「內容最多」的那一頁，不是有題號的那一頁**

原本偏好「有原生圖片物件的頁」，但評分發生在 `_claim_band` **之前**，所以第 18 頁
（有題號、沒有圖）贏過第 19 頁（四張結構全在）。修法：先擴框再評分，
並以**框的高度**比較 —— 標記旁邊有圖的頁，框和圖一樣高；只有標記的頁，框只有一行高。

### 19.3 回應「到了但形狀不對」不再是「沒有回應」

`_json_of` 原本只回 `None`，於是**三種不同的失敗長得一模一樣**：

| 情況 | 修前 | 修後 |
|---|---|---|
| 請求沒到 | `contains: null`，無錯誤 | `request-failed: ...` |
| 回應被截斷 | `contains: null`，無錯誤 | `truncated-json` |
| JSON 沒有 `contains` | `contains: null`，無錯誤 | `verdict-missing-contains` |
| 空回應 | `contains: null`，無錯誤 | `empty-response` |

實際案例：`1092_藥師(二)_調劑學與臨床藥學` 第 22 題。引擎吐出**完整正確的判讀**
（三張清淨室圖、含甲/乙/丙與各部位名稱），但在最後一個陣列中途用完 token，
fenced JSON 沒有收尾。舊紀錄顯示 `contains: null`、沒有錯誤 —— **裁切是對的，預算錯了，
而報告說不出來**。

修法：`_json_of` 回 `(parsed, complaint)`；`describe_crop` 把 `complaint` 放進 `error`；
描述預算 4,000 → 8,000。重跑：`figure`，信心 0.95。

### 19.5 審題介面的分類

`build_review_queue.py` 產生 `queue_index.json`，內含 `taxonomy`：

```
類科 → 年 → 考次 → 科目 → [卷]
```

**樹狀，不是三個獨立的篩選器**。這一點是刻意的：類科與科目不獨立 ——
選了 115 年的醫事檢驗師之後，再列出藥師(一) 的科目會得到空清單，
而**一個會導向空清單的控制項比沒有控制項更糟**。

介面上：
- 三個下拉（類科 / 年 / 科目），依序連動。
- 麵包屑顯示目前範圍。
- 進度條算的是**目前範圍**（這一卷讀了多少），不是整個佇列 ——
  30,440 會讓每一場審題看起來都是零。
- 只有一個類科時直接開在該類科，不開在「全部」（「全部」是只會誤選的選項）。
- 從**目前範圍中第一題未審**開始，所以第二次審題是接續而不是從第 1 題重來。

伺服器新增 `GET /api/queue_index` 讀取佇列旁的 `queue_index.json`。
沒有這個檔的舊 run 回 404，介面**自己從題目重建同一棵樹**（`treeFrom()`），
所以舊 run 不會失去導覽。

## 20. 一條規則要在兩個引擎上成立（本輪，第 5 次轉向）

第 18 節的三個缺陷，我是在**紙張幾何層**（`reflow.skeleton`）修的 —— 骨架立刻變成
97.8% 完整、100% 題數相符。但打包管線用的是**另一個引擎**（`three_way` →
`repair.segment_mixed`），而它**完全沒有被修到**：

> `1142_藥師(一)_藥學(二)(包括藥物分析與生藥學(含中藥學))`
> 骨架：完整、80 題。`three_way`：**items=81**，其中一題編號 **234**。
> 第 3 題的算式 `1.23×10⁻⁸` 折行，折下來那行 `234.8）` 被當成第 234 題，
> **第 3 題在選項前結束，80 題只讀到 4 題**。

這正是專案裡早就寫下、我卻沒有執行的規則：

> **規則必須同時在兩個引擎上成立。**

### 20.1 為什麼第 18 節的邊界規則在這裡不能用

`reflow` 有幾何（每一格的 x0/y0/y1），`repair` 只有**文字行**。邊界規則需要 x0，
所以在文字層無從套用。

也就是說：**同一個缺陷，在兩層有不同的成因，因此需要兩條不同的規則 ——
但兩條都必須是紙張的性質。**

- 幾何層：題號從**本文邊界**開始，折行從**選項欄**開始（第 18.2b 節）。
- 文字層：**題目編號是連續的**。

### 20.2 文字層的規則：編號必須是「後繼」，不是「距離門檻」

第一版我寫的是距離門檻（`value > last + 3` 就當成折行值）。它修好了 `234` 和 `90`
—— 然後在 `1101_醫事檢驗師_臨床血液學與血庫學` 上失敗：

```
2.某病人40歲…其CBC數據：MCV 67 fL，Hb 11.8 g/dL，Hct 34%，RBC 5.8 ×10¹²/L，Hb A₂
4.8%。以鐵劑治療三星期無改善，則最有可能罹患下列何種疾病？
A.Iron deficiency anemia
```

`4.8%。` 是 `Hb A₂` 的折行值，離 `2` 只差 2 —— **門檻抓不到它**，
而它偷走了第 2 題的四個選項，於是第 2 題變成 `options-not-four`。

**門檻是錯的方向。** 距離 2 和距離 200 用距離分不開；分開它們的是
**「不是後繼」**這件事本身。

> 量測：429 卷、32,721 個相鄰題號差 —— **每一個都恰好是 1**。
> 全庫沒有任何一卷的編號有跳號。

所以規則就是：**編號必須是 `last + 1`，否則這一行是值，不是題目。**
沒有門檻、沒有容忍值、沒有擬合。

| `1091_醫事檢驗師_臨床血液學與血庫學` | `90.1 fL、reticulocyte 0.7` 當成第 90 題 | **24 題** | 80 題 |
| `1101_醫事檢驗師_臨床血液學與血庫學` | `4.8%。以鐵劑…` 當成第 4 題，偷走第 2 題的選項 | `options-not-four` | 80 題 |

測試 138 個全綠，但真正的證據是**兩個獨立引擎在全部 429 卷上給出相同的題數**。

### 20.6 這一節的方法論

- **修好一層不等於修好管線**。第 18 節的修法讓骨架 100%，但管線用的是另一個引擎。
- **規則必須同時在兩個引擎上成立** —— 這是專案裡已有的規則，這一輪才真的執行它。
- **同一個缺陷在兩層有不同的成因**，所以需要兩條規則；但兩條都必須是紙張的性質
  （本文邊界 / 編號連續），不是引擎的內部狀態。
- **不要用門檻代替結構**。距離門檻讓 `4.8%` 通過，因為距離分不開「值」和「跳號」；
  「不是後繼」分得開。
- **驗收標準是兩個引擎一致，不是測試全綠**。
- **失敗要分類**：剩下的 10 卷全部是同一類（圖片題），所以它們是一個工作項，不是十個。

## 21. 收尾：兩個「同一件事有兩個名字」的缺陷（本輪）

### 21.1 類科名的全形/半形：審題介面會多出兩個空殼類科

catalog 有些年度寫 `藥師（一）`（全形），有些寫 `藥師(一)`（半形），而目錄一律是半形。
結果審題介面**列出六個類科，而實際只有四個**：

```
藥師(一)  63 卷   藥師（一） 12 卷     ← 同一類科，被拆成兩個
藥師(二)  62 卷   藥師（二）  9 卷
```

因為審題者不會知道還有另外 12 卷。

修後：**四個類科**，藥師(一) 75 卷（63 + 12）、藥師(二) 71 卷。

類科名（用來找檔案），這裡折的是**輸出**的類科名（用來分類）。
兩處都要折，只折一處就會在另一處冒出同樣的幽靈。

## 22. 審題介面的四個缺陷：介面說它顯示的東西，與它真正顯示的東西

第 19 節把分類與裁切做進介面，第 21 節把隊列做成四個類科。這一輪使用者回報
**「我在 review UI 還是看不到圖」**。追下去，這不是一個缺陷，是**四個**，而且四個都不在
裁切、不在模型、不在資料——**在「介面說的」與「介面做的」之間的落差**。

診斷的順序本身就是結論：**每一次「我以為是 X」都先量一次**，量完發現是另一個地方。

### 22.1 缺陷一：`/api/candidates` 的 1,000 上限，被當成「全部」

`filtered_candidate_payloads` 寫死 `limit = max(1, min(int(params.get("limit") or "500"), 1000))`。
介面開機時抓一次 `/api/candidates`（500 筆），然後**在瀏覽器裡**依類科/年/科目篩選。

量到的後果：

| | |
|---|---|
| 隊列 | **32,350 題 / 419 卷** |
| `/api/candidates` 實際回傳 | **500 題**（全部是 115 年；其中只有 **19 題**有裁切） |
| 分類下拉選單的來源 | `/api/queue_index`（**完整 419 卷**） |
| 結果 | 選單列出 419 卷，資料只裝得下 6 卷 → **大部分範圍都是「這個範圍沒有題目」** |

**這是「兩份資料來源不一致」的典型**：導覽用完整的樹，內容用被截斷的清單。
只要兩者來自不同的地方，就一定會漂移。

### 22.2 缺陷二：`全部` 這個選項**永遠選不到**（`''` 與 `null` 混用）

`resolveLevel` 之前長這樣（四個層級各寫一次，共四份）：

```js
if (!years.includes(S.scope.year)) S.scope.year = years[0] || '';
```

`null`（還沒選）與 `''`（**選了「全部」**）被當成同一種東西。於是：

1. 使用者選「全部年度」→ 值變成 `''`
2. 下一次重畫 → `''` 不在 `years` 裡 → **被換成 `years[0]`（最新的一年）**
3. 選單彈回 115 年

**「全部」是一個真實的選項，不是「無效值」。** 修法是把它寫成一個函式，三種狀態分開：

```js
function resolveLevel(value, offered) {
  if (value === null || value === undefined) return offered[0] ?? '';   // 還沒選 → 用預設
  if (value === '') return offered.length > 1 ? '' : (offered[0] ?? ''); // 選了「全部」→ 保留
  return offered.includes(value) ? value : (offered[0] ?? '');           // 失效 → 換掉
}
```

### 22.3 缺陷三：`全部年度` 會讓**考次與科目下拉變空**

原本的寫法直接讀**當前層級的單一 bucket**：

```js
const yearBucket = bucket.years[S.scope.year];   // S.scope.year === '' 時，這是 undefined
const sittings = yearBucket ? Object.keys(yearBucket.sittings) : [];   // → []
```

選擇「全部年度」時 `years['']` 是 `undefined`，於是考次清單是空的，科目清單也是空的
（顯示 `—`）。**上一層選「全部」，下一層就必須列出「所有分支的聯集」**，不是「某一個分支」。

修法：`walkSittings()` 走訪所選子樹的每一個分支，`availableSittings()` /
`availableSubjects()` 取聯集，`countPapers()` / `countQuestions()` 算同一子樹的大小。

### 22.4 缺陷四：網址上的範圍被**自己覆寫掉**

這一條最隱蔽。`scopeFromHash()` 讀 `#類科/年/次/科目/q41`，驗證用：

```js
if (wanted && categories.includes(wanted.category)) { ... }
```

但 **`全部類科` 的 category 是 `''`**，`categories.includes('')` 是 `false`
→ **整個連結被丟棄** → 套用預設範圍。而 `applyScope()` 一開頭就呼叫 `scopeToHash()`
把預設值寫回網址。

量到的證據（在真實 origin 上注入探針）：

```
雜湊: #藥師(一)/115/1/藥學(一)(...)/q1     ← 我開的是 /115/2/，被改寫成 /115/1/
wanted: {category:"藥師(一)", year:"115", sitting:"1", ...}
scope : {category:"藥師(一)", year:"115", sitting:"1", ...}
```

**網址是輸入，不是輸出。** 修法：

```js
if (wanted && (wanted.category === '' || categories.includes(wanted.category))) { ... }
```

### 22.5 缺陷五（順手量到的）：清單把六卷題目**交錯**排

原本排序只依題號：

```js
.sort((a, b) => Number(a.question_number) - Number(b.question_number));
```

一個考次（例如 115 第2次 藥師(一)）有 3 卷、240 題，於是清單是
「每卷的第 1 題、每卷的第 2 題、…」。**審題者是一次讀完一卷的人**，主鍵應該是卷：

```js
.sort((a, b) => (a.paper < b.paper ? -1 : a.paper > b.paper ? 1
  : Number(a.question_number) - Number(b.question_number)));
```

## 23. 圖片的觸發器漏掉了「題目下方的圖」：一個測試在保護一個錯的規則

| 題幹末行（`圖2），此致病菌…`） | p12 y=616–627 |

| **圖2（KOH 鏡檢）** | **p12 y=700–812** |
| 四個選項 | **p13 y=43–135** |

題幹自己寫了「（如圖1）」「（如圖2）」，`is_visual_question` 也是 `True`——
但 `image_refs` 是**空的**。

### 23.2 原因：觸發器只找「重疊」，但圖在題目**下面**

`vision.figure_questions` 的兩個觸發器是：

1. `embedded-image` — 內嵌圖與題目的 cell **重疊**（`_overlap(box, candidate) > 0`）
2. `options-without-text` — 選項標記後面沒有文字

第 68 題的 cell 到 **y=627** 為止，圖片從 **y=629** 開始。
**差 2 pt，沒有重疊 → 沒有觸發 → 沒有圖。**

但這張圖不是「在題目旁邊」，是「在題目**後面**」。而且它的選項在**下一頁**。

### 23.3 修法：題目擁有「自己的題號到下一個題號」這一段

紙張的性質是：**一題從它的題號開始，到下一個題號結束**。圖印在題幹下面，仍然是這一題的。

```python
def _next_start(starts, top, *, tolerance=1.0):
    for value in starts:
        if value > top + tolerance:
            return value
    return float("inf")
```

```python
band = (box[0], box[1], box[2], _next_start(starts_on_page.get(page, ()), box[1]))
images_here = [c for c in by_page.get(page, ()) if _overlap(band, c) > 0]
```

`starts_on_page` 是**每一頁上每個題號的 y**，由題號 cell 建出來（讀紙張自己宣告的結構
`cells.stem[0]`，不是讀最小的 cell id——id 是抽取順序，跨頁的題目會有更小的 id）。

### 23.4 有一個測試在保護一個錯的規則

修完之後，`tests/test_reflow.py::test_a_picture_that_belongs_to_another_option_is_not_claimed`
失敗了：

```python
def test_a_picture_that_belongs_to_another_option_is_not_claimed():
    """The band test is vertical, so a figure below the whole question is not swept in."""
    ...
    far = [{"page": 1, "x0": 50, "y0": 700, "x1": 400, "y1": 900}]
    assert found[0]["box"][3] <= 300          # the far picture is not included
```

**這個斷言是錯的，而且它的 docstring 說明了為什麼會錯**：
「The band test is vertical, so a figure below the whole question is not swept in.」
—— 它是**從程式的形狀**寫的（「區域是一個矩形，所以外面的東西不在裡面」），
**不是從紙張寫的**。而紙張說：題目下方的圖就是這一題的圖。

**這是這一輪最重要的一個教訓**：
> **一個綠的測試不代表一個對的規則。測試也可能在保護一個沒有人量過的假設。**

修法不是刪掉測試，是**把規則換成量出來的規則**，並保留真正的護欄：

- `test_a_picture_after_the_last_question_on_a_page_is_claimed` — 圖在題目下方**是**這一題的
- `test_the_next_question_on_the_page_ends_the_band` — **下一個題號才是邊界**（結構，不是距離）

## 24. 裁切把圖切掉：樂隊的「寬度」不是文字的寬度

使用者的回報有兩句，第二句比第一句嚴重：

> 你都是把整題截圖下來，但是我原本的設計是只截取題目的圖以及答案的圖
> **你現有的擷圖常常把最下面的圖截不完整，這是很嚴重的定位錯誤**

### 24.1 先量「切掉」有幾題

「切掉」是可以量的，不需要模型：

> 裁切框所在的頁面上，有沒有高圖**與框相交、但不被框包含**？

全庫 1,102 題：

| | |
|---|---|
| 圖完全在框內 | **1,062** |
| **有圖被框切過** | **33**（被切的圖物件 41 個） |

33 題全部是**藥理學與藥物化學**——**化學結構圖**。這正是使用者說「藥學系題目有大量這類問題」的地方。

最慘的幾題，框內只剩原圖的 **8.8%**：`1041_藥師_藥理學與藥物化學` Q71、`1091_藥師(一)_藥理學與藥物化學` Q46、
`1052_藥師_藥理學與藥物化學` Q45、`1032_藥師_藥理學與藥物化學` Q79。

### 24.2 原因：樂隊的寬度取自「文字」，但圖比文字寬

`1042_藥師_藥理學與藥物化學` Q68（tolmetin 的主要代謝物）：

| 元素 | 位置 |
|---|---|
| 題號 cell | p8 y=588 |
| `A.` / `B.` | p8 y=603 / y=731 |
| `C.` / `D.` 標記 | p9 y=140 / y=250 |
| 結構 1 | p9 x=**49.1**–298.8 y=28–137 |
| 結構 2 | p9 x=**49.6**–284.3 y=139–248 |
| 結構 3 | p9 x=**49.6**–285.1 y=250–**367.9** |

p9 上，這一題的**文字**只有 `C.` 和 `D.` 兩個標記，x 範圍 **40.6–49.5**。

- 結構 1 起點 x=49.1 → 與 40.6–49.5 **相交 → 被認領**
- 結構 2、3 起點 x=**49.6** → **差 0.1 pt，不相交 → 沒被認領**

所以框只長到 y=263.2，**第三個結構從 250.1 跑到 367.9，被切在 263.2**。

**樂隊原本是「文字所在的矩形」，但一題擁有的是這一頁的一個水平切片。**
圖排在切片裡，不會和上面的文字對齊。

1. **樂隊要跨頁量（閱讀順序）**，不是逐頁量。

## 26. 用手工題庫當外部標準：一個不是自己寫的測試

### 26.1 這個測試抓到的第一件事：圖被切成 73 條 2 pt 的掃描線

**第一次量測：recall 91.0%（41 題漏掉）。** 41 題全部集中在**血液學**。

查 `1041_醫事檢驗師_臨床血液學與血庫學`：

```

p3: images=73   tall=0   ← 73 個圖物件，沒有一個 ≥24 pt
    每一個都是 199.9 pt 寬 × 2.0 pt 高，xref 全部相同
```

**一張點陣圖被生產程式切成 73 條掃描線。** 我的 `MIN_FIGURE_HEIGHT = 24.0`
把每一條都丟掉，所以整張圖消失，而題幹明明白白寫著「圖中箭頭所指」。

同一個現象在 p4 是 **249 條 0.7 pt**，`1032` p2 是 **308 個物件**。

**修法**：量測之前先把碎片**拼回去**（`vision.picture_boxes`）。
`1041` 那一卷：**743 個物件 → 14 張圖**。

**結果：recall 91.0% → 97.1%，漏掉 41 → 13 題。**

### 26.2 拼回去不可以只看「相鄰」——兩種錯各修一次

拼接需要一個判準，而**只靠相鄰會併錯**：

| 併錯的案例 | 量測 | 後果 |
|---|---|---|
| `1102` Q77 四條電泳線 | `xref` 21/22/25/26，寬 78–84 pt，間隔只有 20.7 pt | 四條併成一張 135×480，兩個選項共用一張圖 |
| `1022` p2 `xref` 24 | **同一個物件被放置兩次**（y=393.9-462.9 與 y=750.3-818.8，相距 287 pt） | 併成一張 425 pt 高的圖，**中間 5 題全部被誤判為圖題** |

**兩個訊號必須同時成立**：

1. **先相鄰**，然後
2. **同一個 `xref`**（檔案說它們是同一張圖）**或同一寬度**（生產程式重新編碼每一條時，身分在幾何裡）

「只看相鄰」會把四條電泳線變成一條；「只看 xref」會把一個物件和它自己的另一個位置黏起來。
**兩個都要，各自排除一種錯。**

誤報：**45 → 7**。

### 26.3 有圖物件在頁面上，不代表頁面畫了它

剩下的 7 個誤報，其中 `1022` 的 5 題來自 `xref=24`。
把那個物件取出來看：

```

```

**但頁面在 y=393.9-462.9 這裡渲染出來是純白**，而 Q15 的選項（A/B/C/D 缺鐵性貧血…）
**在文字層裡，位置是 y=359.4–400.8**——這個 bitmap 蓋在**別題的選項和下一題的題幹**上面，
而且它自己沒有被畫出來。

**「圖清單裡有這個物件」和「讀者看得到圖」是兩件事。**

修法：**渲染一次，量墨水的比例**（`vision.rendered_ink`、`MIN_INK = 0.002`）。
一題的裁切如果真的渲染出空白，就不是圖。量到的墨水比例：真的圖 0.10–0.35，空白 **0.000**。

**而且這個檢查也解釋了為什麼不能只看浮水印式的啟發**：那張 bitmap 的像素內容
確實寫著「(A) AML M0」，**它是文字，不是圖**，只是它被蓋在別題上面且沒有被繪製。

### 26.5 選項綁定的 reach 是用外部標準調出來的，不是想的

實測差距 **0.1–8.2 pt**，無法推導。所以**掃一遍**：

| reach | 正確 | 完全沒綁到 | 綁錯 |
|---|---|---|---|
| 4.0 | 16 | 3 | 5 |
| 6.0 | 17 | 3 | 4 |
| **10.0** | **20** | **3** | **1** |
| 12.0+ | 20 | 3 | 1 |

**10 pt 是停止改善的最小值**，所以取 10——在「開始吃掉前一個選項的圖」之前留下最多餘裕。
選項綁定：**17 正確 / 5 錯 → 20 正確 / 2 錯**。

剩下 2 個：
- `1052` 微生物 Q7 —— 四個培養試管是**一張**圖（`p1 y573.8-774.7`），**紙張本身就是這樣印的**，
  所以「四個選項四張圖」在這裡不成立。**題庫的分法是題庫的，紙張的分法才是規則。**
- `1102` 醫學分子 Q77 —— 四條電泳線的最後一條跨頁（`p14 y29.0-97.0`），reach 差一點。

### 26.8 第 26 節的規則

1. **驗收要用不是自己產生的資料。** 手工題庫是這個 workspace 裡唯一的這種東西，
   它的價值不在「數量」而在「不是受測程式寫的」。
2. **外部標準的「漏掉」是錯，「沒收錄」不是錯。** 分不清這兩者，就會為了數字好看而刪掉真的圖。
3. **同一種東西可以有兩種身分**（`xref` 相同、或寬度相同），**兩個訊號要各自排除一種錯**，
   不能只留一個。
4. **「有一個物件」不等於「畫面看得到東西」。** 量測要量到**輸出**，不是量到清單。
5. **自由參數要掃描，不要推導。** reach 從 4 掃到 30，選的是「停止改善的最小值」，
   因為最小值在下一種版面出現之前留的餘裕最多。
6. **修好一層要重跑，因為上一層的錯誤會藏在下一層的輸出裡。** 拼接修好之後，
   才看得到「渲染是空白」這件事。
7. **紙張的分法才是規則**，題庫的分法是題庫的（Q7 的四個試管是一張圖）。

## 27. 「全部通過」不是通過，是「還沒測到」：429/429 與 33,150 題（本輪）

第 26 節結束時，管線的狀態是 **419 卷打包、10 卷被擋、32,350 題**。那 10 卷全部屬於
「圖片題」類（`options-not-four` / `answer-not-on-sheet`），而當時的判斷是「這是同一類，
先擱著」。本輪把那 10 卷做完，過程中發現它們**不是一類，是四類**，而且每一類都需要一條
不同的、關於紙張的規則。

### 27.1 10 卷不是一類，是四類

| 類 | 症狀 | 卷 | 真正的原因 |
|---|---|---|---|
| A | 選項標記辨識不出來 | 藥師×6、醫檢×2 | 一卷有**兩套**私用區字型家族 |
| B | 選項整列被當成雜訊刪掉 | 血清免疫 Q49 | `_is_bullet_only` 把「只有標記的一列」當版型 |
| C | 選項是「子項的組合」 | 生理 Q65/Q68 | 子項標記與選項標記都是 4 連號 |
| D | 續行被當成新題 | 藥劑學 Q1、藥學(四) Q53 | 「後繼號碼」規則沒有排除**折行** |

### 27.2 規則 A：一卷可以有兩套標記家族，而「等次數」不是判準

`option_alphabet()` 原本回傳「最長的等次數連號」，並假設這是一卷的唯一一套。實測
`1001_醫事檢驗師_臨床血清免疫學與臨床病毒學`：

```
0xe000: 2  0xe001: 2  0xe002: 2  0xe003: 1     ← 第二套，次數 2,2,2,1
0xe18c: 78 0xe18d: 78 0xe18e: 78 0xe18f: 78    ← 主套，每題一次
```

第二套被「等次數」排除（因為 `\ue003` 只印一次），於是 Q71 的第四個標記不被承認，
選項留在題幹裡，關卡就說這題沒有選項。**修正不是放寬次數，是改判準**：一個字形家族
的**長度等於選項數**，它就是選項字母表。這是同一件紙張事實（一個標籤一個字形）的
另一種說法，而且不取決於「剛好有幾題用到這套」。

### 27.3 規則 C（同一節的下一層）：兩套家族各做各的事

`1001_醫事檢驗師_臨床生理學與病理學` Q65：

```
泌尿系統感染的尿液分析以下列那些物質的增加為主？
\ue000細菌  \ue001白血球  \ue002紅血球  \ue003葡萄糖     ← 子項（題目問的四個東西）
\ue18c僅\ue000\ue001\ue002  \ue18d僅\ue002\ue003  …        ← 選項（考生選的四個組合）
```

兩套都是 4 連號，用**整卷**的字母表分不開。分得開的是**用途**：選項標記每題印一次，
子項標記只在少數題印。所以 `option_alphabet_families()` 回傳**家族清單**（用得多的在前），
分段時**逐家族試切**，取「切出來剛好等於宣告選項數」的那一個。拒絕仍然是預設值。

修好之後 `臨床生理學` 從「80 題、2 題無選項」變成「80 題、1 題無選項」——而那一題
（Q18）是真的圖片題，關卡現在放行它。

### 27.4 規則 B：`_is_bullet_only` 刪掉的是選項，不是版型

Q49 的選項列長這樣：

```
\ue18c\ue000\ue001   \ue18d\ue000\ue002   \ue18e\ue001\ue002   \ue18f\ue000\ue001\ue002
```

這一列**一個字母、一個數字、一個漢字都沒有**——每個字元都是標記——所以
`_is_bullet_only` 把它當成「只有標點的一列」刪掉。分得出真假的是**這一列用了幾個相異標記**：
版型是單一圖形重複，選項列則一個選項一個標記，至少兩個。全庫量測：328 列純標記列，
其中 27 列只用一個相異碼（版型：`\uf073`、`\ue12a`、單獨的 `\ue18d`），其餘都用兩個以上。

**先量「另一條規則會丟掉什麼」再採用**：抽樣 60 卷，規則 B 改善 1 卷、退步 0 卷。

### 27.5 規則 D：折行不是新題——而這條規則必須量到「只有一個」

`1001_藥師_藥劑學` Q1 的題幹結尾是 `…反應速率常數為1.0 mg/mL/hr，經過`，紙本把它折行成
`2 天後，藥物濃度為何？`。讀成第 2 題，它就拿走了第 1 題的四個選項，而**真正的第 2 題**
被它吞掉——整卷變成「一題，選項寫著 48 mg/mL」這種荒謬結果。

這條規則不能靠**距離**寫。`2 天後` 跟續行的縮排一模一樣（x≈72），跟真題號（x≈47–52）
不同——但量測顯示 89,463 個真 anchor 裡有 26 個 x 差超過 8，距離不是邊界。
真正分得開的是**句子有沒有結束**，加上三個結構條件：

1. **已經在讀某一題**（排除卷首導言「請依上文回答第1題至第2題」）；
2. **該題還沒出現任何選項標記**（出現了就代表題幹講完了）；
3. **下一行有 ≥2 個選項標記**（折行的後面就是它所屬的選項）；
4. **前一行沒有結束句子**（沒有 `？。！：；` 結尾）；
5. **本行文字 ≤14 字**（折行的尾巴是一個詞組，題首是一個子句）。

全庫量測：**89,463 個後繼 anchor，五個條件全中的只有 2 個**——一個是上面那個真缺陷，
一個是排序假象（`15 115 119`，一張表的數字列）。也就是說**這條規則的代價是 0 個真題**。
這才叫做「規則建立在紙張的性質上」。

### 27.6 修正的結果

| | 修正前 | 修正後 |
|---|---|---|
| 打包 | 419 | **429** |
| 被擋 | 10 | **0** |
| 題數 | 32,350 | **33,150** |
| 兩引擎一致 | 429 / 429 | **3,516 / 3,516（全庫，100.0%）** |
| 測試 | 140 | **168** |

**逐卷比對舊佇列**：題數或無選項數改變的只有 4 卷，**退步 0 卷**。

「全部通過不是通過，是還沒測到」——10 卷被擋的時候，「同一類」是錯的判斷；
把它們打開之後才看到它們是四類，而每一類都是一條可以寫下來的紙張規則。

### 27.7 這一節的規則

1. **「同一類」要先證明。** 10 卷都掛同一個 `blocking` 不代表同一個原因；
   分類要分到「修一條規則能修好幾卷」為止。
2. **等次數不是判準，長度等於選項數才是。** 判準要說出紙張的事實，
   不是「剛好觀察到的統計」。
3. **同一卷可以有兩套標記家族**，而分辨它們的是**用途的次數**，不是位置。
4. **逐家族試切，取切得對的那一個。** 拒絕仍然是預設值。
5. **「只有標記的一列」要看它用了幾個相異標記。** 一個是版型，兩個以上是選項。
6. **折行不是新題。** 規則要寫成「句子有沒有結束」，不是「距離多遠」。
7. **一條新規則要在全庫上量出「會誤殺幾個真 anchor」。** 這條是 2 / 89,463，
   而且其中一個還是假象——這才是可以採用的數字。

## 28. 第三類「看不到圖」：一張圖被印成幾百個小碎片（本輪）

第 27 節之後，管線是 429/429、33,150 題。這一節處理的是**在使用者的清單上但還沒做**的那一項：
向量圖。做完之後發現它不是向量圖。

### 28.1 極小裁切：先量，再猜

驗收時量到 **20 個裁切小於 40px**（涉及 14 題）。當時的假設是「這是向量圖，
PDF 用 path 畫的，所以沒有 image object」。**這個假設是錯的**，而錯得很具體：

```
1051_藥師(一)_藥劑學 Q68
  page.get_images(full=True)   → 0        ← 真的沒有影像物件
  page.get_drawings()          → 2        ← 兩個都是頁框矩形
  page.get_text("rawdict")     → 290 個 image block，bbox 全部 1–5 pt，xref 全部 0
```

那一張 Lineweaver-Burk 圖**是用 290 個「一個字型一個 bitmap」的小影像物件印出來的**。
不是 path、不是單一影像，是**碎片**。所以「向量圖」這個名字從一開始就下錯了。

### 28.2 規則不是「有沒有圖物件」，是「碎片的密度」

| | 值 |
|---|---|
| 真圖形的 region 寬度（250 卷、183 個） | **全部 ≥24 pt**（最小 26.6） |
| 這個碎片的 region 寬度 | **1.4 pt** |

兩群相差一個數量級，所以門檻不是「調出來的」：

- `MIN_FIGURE_WIDTH = 24.0`：region 比這窄就不是圖 → 去同一題的 band 裡找碎片叢集。
- `MIN_FRAGMENT_COUNT = 25`：少於 25 個碎片不算圖（避免單一壞字被裁成圖）。
- 碎片的定義是**形狀**：`xref` 為 0、任一邊 ≤12 pt。

修好之後 Q68 的 region 從 **1.4×34.6 pt 變成 87.8×77.8 pt**，裁切 250×222 px，
**圖完整**（兩軸、斜線、`1/V`、`1/C`、`X軸截距` 箭頭都在）。

### 28.3 兩條規則會疊，而且方向是對的

碎片規則讓裁切變大，所以必須問「它會不會把空白也裁進來」。實測 21 題觸發：

- 20 題 region 變大且**有內容**（`ink` 0.02–0.15）。
- 1 題（`1072_呼吸治療師_呼吸治療儀器設備學` Q52）**`ink = 0.00000`** ——
  第 26 節的**空白渲染檢查**把它丟掉了。

**「修好一層不等於修好管線」**：碎片規則給出更大的框，空白檢查負責判斷框裡有沒有東西。
兩條規則各自排除一種錯，缺一條就會把空白當成圖送給審題者。

### 28.4 這一節的規則

1. **假設要用 PDF 自己回答。** 「沒有 image object 所以是向量圖」是推論；
   `get_images` 回 0 而 `rawdict` 回 290 個 image block，才是事實。
2. **自由參數要掃描，不要推導。** 24 pt 是量出來的（183 個真 region 的最小值 26.6）。
3. **門檻要離兩群都遠。** 1.4 對 26.6，取 24；不是取中間值，是取「兩群都不碰」。
4. **形狀勝過大小。** 「碎片」= `xref` 0 且任一邊 ≤12 pt；一個大字不是碎片。
5. **修好的規則要問它會多裁進什麼。** 21 題裡有 1 題是空白，靠上一層的墨跡檢查擋掉。
6. **命名要跟著證據改。** 這一類不是「向量圖」，是「碎片圖」；名字錯了，
   下一個讀者就會往錯的方向找。

## §29 一張圖被印成幾條「同寬且相接」的切片，而選項只拿到第一條

### 29.1 使用者回報

> 第 41、46、51 題 · 藥師(一) · 115年第1次 · 藥學(一) 圖片沒有截取對。
> 還有很多圖都沒有截對，你的設計有很嚴重的缺陷。

### 29.2 真正的原因

紙本把**一個結構**印成一整個圖，但 PDF 把它存成**好幾條同寬、上下相接的影像物件**。
`option_figures` 讀的是原始物件清單，然後寫了這一行：

```python
got = got[:1]   # 「一個選項就是一張圖」
```

所以一個選項只拿到**最上面那一條**。量測 `1151_藥師(一)_藥學(一)`：

| 選項 | 物件 | x 範圍 | 相接於 | 服務出去的裁切 |
|---|---|---|---|---|
| C | `xref` 16, **17** | 50.4-225.4（相同） | y=392.4 | 只有 16（**少了 `Cytotoxic drug` 橢圓**） |
| D | `xref` 18, **19, 20** | 50.4-388.1（相同） | y=489.6, 529.9 | 只有 18（**少了左邊的抗體**） |

**為什麼所有自動檢查都通過**：裁切出來的位元組**真的是**一個被放在頁面上的物件，
HTTP 200、PIL 解得開、檔案存在、`source=image-object`。每一道檢查問的都是
「這是不是一個真的物件」，而答案是「是」。**沒有一道檢查問「這是不是整個圖」。**

### 29.3 修法：綁定用原始物件，合併只在該選項的 band 內

第一個修法（整頁先合併）是**錯的**，而且錯得更有價值：整頁的「同寬且相接」會把
`1051_醫事檢驗師_臨床血清免疫學與臨床病毒學` Q20 的**四個選項**（四張圖直接印在彼此下面、
寬度相同）融合成一張 70-471 pt 的圖，**每個選項都失去自己的圖**。48 個選項的裁切消失。

所以正確的順序是：

1. **用原始物件做 band 綁定**（一個選項的 band 是它的 marker 到下一個 marker）。
2. **只在这个 band 之內**把同寬、相接的切片合併成一張圖。
3. `min_image_height` 只用在**挑選**（哪一張才是這個選項的圖），**不修剪**已選中的圖
   ——`1081_藥師(一)_藥理學與藥物化學` Q63 B 的分子底部兩條是 13.7 與 13.8 pt，
   用門檻修剪就正好切掉分子的下半部。
4. 合併後若只有一個物件 → 直接服務該物件；**多個物件 → 沒有單一 `xref`，改用 render
   該區域**（服務其中一條再謊稱它是那個物件，就是這次的缺陷）。
5. 裁切要從**圖所在的頁**切，不是 marker 所在的頁（Q63 的 A、B marker 在第 11 頁、
   圖在第 12 頁）。

### 29.4 逐卷比對：只有 16 卷改變，退步 0 卷

| | 舊 | 新 |
|---|---|---|
| option-image | 1047 | **1047**（新增 0、消失 0） |
| 內容改變 | — | **116**（放大 107、縮小 9） |
| figure-crop | 966 | 958 |

9 個「縮小」的全部是改善：舊裁切含**一整欄別題的結構式**，新裁切只有該選項自己的分子。
減少的 8 個 figure-crop 是「四個選項圖加起來就是整張圖」的題，選項修好之後
`options_cover_the_figure` 才終於成立，冗餘的全題裁切被正確移除。

**驗證重構無副作用**：把舊版 `picture_boxes` 逐字重寫一份對全庫比對，
**3,516 卷、0 卷不同**——骨架與視覺層的輸出沒有被動到。

### 29.5 使用者要求「每張圖都要用模型確認」：做了，而且量測結果是模型做不到

| 實驗 | 結果 |
|---|---|
| 40 組已知壞（舊裁切）＋ 40 組已知好（新裁切），模型逐張比對紙本原區域 | **80/80 全部回答 `same=true`**：召回 0%、誤報 0% |
| 正對照：把結構只留**最上面 8 pt 的細條** | 模型仍然 **7/8 回答 `same=true`** |
| 先前量測 | 978 個選項裁切與內嵌物件**位元組完全相同**，模型判 56 個為 clipped；同圖問 131 次，自我矛盾 39 次 |

**「模型說沒問題」不是證據**：對照組證明它對「幾乎什麼都沒有的細條」也說沒問題。
單張圖沒有參照點，模型只能憑印象。

所以這一關改由**紙張自己回答**，而它答得出來，因為「同一張圖的其它切片」寫在檔案裡：

> **規則**：框的下緣（或上緣）緊接著一個**同寬**（±0.5 pt）、**相接**（±1 pt）、
> **高度 ≥ 12 pt**、且**落在同一選項 band 內**的物件 → 這個框只是一張圖的一部份。

| 驗收 | 結果 |
|---|---|
| 召回（19 個已知「多片」選項，用人為單片框重測） | **19/19** |
| 誤報（隨機 400 張已服務裁切） | **0/400** |
| 全庫（2,007 張） | **0 張不完整、0 張無法判定** |

### 29.6 這條規則被「量到錯」三次，每次都改窄

| 訊號 | 量測結果 | 處置 |
|---|---|---|
| 框外墨跡（`rendered_ink`） | `1012_藥師_藥理學與藥物化學` Q46 D 的框下墨跡 0.18，**全部是下一題的題幹文字**；`1072_醫事檢驗師_臨床血清免疫學與臨床病毒學` Q8 的框下 0.99 是**下一個選項的圖**。120 張樣本擋下 13 張，**沒有一張是真缺陷** | **預設關閉**（`MIN_RING_INK = None`） |
| 排除文字後的墨跡 | 仍無法分辨「同一張圖的下半」與「下一個選項的圖」 | 只作為選用訊號 |
| 同寬相接（不分 band） | 40 張樣本誤報 5 張：`1091_藥師(一)_藥劑學與生物藥劑學` Q53 C 的下方是 **D 選項的公式**；`1071_藥師(一)_藥理學與藥物化學` Q76 B 的下方是 **C 選項的結構** | 加 **band 條件** → 0/400 |
| 加上 band 後仍誤報 | 0.8 pt 的物件（產生器吐出的線）被當成切片 | 加 **高度 ≥ 12 pt** |

**規則不是想出來的，是每次量到它錯就改窄一次。**

### 29.7 三條新規則

1. **「一個選項一張圖」是綁定的假設，不是圖的性質。** 綁定要用原始物件，
   但合併要在該選項的 band 內做——兩個層次混用就會一次錯兩邊。
2. **門檻用來選，不用來切。** 高度門檻決定「哪一張是這個選項的圖」，
   一旦選定就不該再拿它修剪那張圖。
3. **對照組要包含「幾乎什麼都沒有」。** 只測已知好／已知壞，模型 80/80 說好；
   加上「只剩 8 pt 細條」才看出它根本沒在分辨。

## §30 裁切的標準只有一個：選項就是選項，不是它的圖

**使用者回報**：「有的選項裁切有 A/B/C/D 編號，有的沒有，標準要一致；而且我要包含編號。」
同時回報 `1152_藥學(一)` Q53 的裁切只有結構圖、**沒有藥名**。

### §30.1 量到的分裂

| 來源 | 張數 | 含編號 | 含選項文字 |
|---|---|---|---|
| `source=image-object`（原始 `xref` 位元組） | 866 | **否** | **否** |
| `source=page-region`（渲染該框） | 183 | 是 | 是 |

「服務原始物件」看起來是對的——那是圖自己的邊界，不會夾到隔壁一行字——但它
**默默丟掉編號與選項文字**。於是同一題往下看，有的選項有標籤、有的沒有，這就是
使用者說的「標準不一致」。

### §30.2 兩個修法，兩件都要做

1. **`option_figures` 回傳「選項的框」，不是「圖的框」。** 骨架分給這個選項的每一列
   ——標記**和**它的內容——都併進框裡；但只併**圖片所在頁**的列，因為換一頁 y 就是
   另一套座標。圖自己的框仍以 `picture_box` 回傳，給需要邊界的呼叫者。
2. **裁切一律是該框的渲染**（`source=page-region`），不再服務物件位元組。渲染同時是
   較安全的選擇：44 張 JPEG 2000 選項圖在服務物件時需要 `extract.web_safe_image()`，
   渲染沒有這個問題。

量測：**1,049/1,049** 選項裁切都是 `page-region`，0 張是物件位元組。

### §30.3 `1152_藥師(一)_藥學(一)` Q53：選項標記自己一行時，下一行是它的內容

`repair.segment_mixed` 是純文字、無幾何，所以內容那行掉進了題幹：

```
53.下列quinazoline 類α₁-adrenergic antagonists，何者之親脂性最高…？   ← 題幹
  A.        ← 標記，內容空的
  alfuzosin ← 這行進了題幹
  B.
  doxazosin
  …
```

結果四個選項全是 `""`，題目讀成 `…最長？ alfuzosin doxazosin prazosin terazosin`，
沒有任何可選項；也因為選項文字不見了，裁切當然沒有藥名可以包含。

**規則**：標記的內容為空時，**下一行是它的內容**——而且只有下一行，因為
一排只有標記的列（`A.` `B.` `C.` `D.` 後面沒有文字）是版型，不是四個等待內容的選項。
新的題號錨點要清掉待接的標記。

量測：**56 題變動、23 卷**，每一次都是純位置搬移——每個變動題的
`stem + options` 字元多重集合**完全相同**，沒有掉字也沒有造字。
空選項文字 `1,153 → 1,069`（−84）。

### §30.4 `1141_藥師(一)_藥學(一)` Q41：圖裁切把四個選項再放一次

`options_cover_the_figure` 問的是「這一題的圖是不是全部都是選項圖」，答是就丟掉整題裁切。
Q41 有五張圖——題幹的環狀圖，加每個選項一張結構——所以它答否、做了裁切，
而那張裁切**把四個選項又放了一次**，包含答案。使用者回報成「裁切截到答案」。

**判準沒錯，是裁切的內容錯了。** 修法是加 `exclude`：把選項圖的框從圖區域移除，
裁切只剩題幹的圖。兩個誘人的捷徑都是錯的，值得寫下來：

- **不要把 `options_cover_the_figure` 改窄。** 把題幹的圖當成「已被涵蓋」會答是，
  於是題幹的圖從整套裡消失。量測：這個改法新增 98 張裁切，內容是別題的選項圖。
- **`figure_region` 回 `None` 時不可以退回整題。** 所有圖都被排除時沒有東西可切；
  退回 `entry["box"]` 會切到文字和選項圖，那正是要移除的重複。`crop_figure` 現在回
  `no-figure`，呼叫端把它當成「選項裁切已涵蓋圖」，不是錯誤。

量測：圖裁切 **958 → 956**，選項裁切 **1,049 → 1,049**，`verify_crops` 全庫 **0 張不完整**。

### §30.5 上下標：比例是底線，基線位移才是判準

整條線逐 span 讀，就是為了不讓 `B2` 和 `B₂` 讀成一樣。但這個保護對大部分語料是關掉的，
因為閘門是**在一種風格上量到的比例**：`_OFFSET_MAX_SIZE_RATIO = 0.75`，來自 5.5pt 對 11pt。

這批紙把化學下標印在母體的 **0.82–0.85**，所以 `CH3(CH2)11OR` 抽出來數字全在基線上。
量測四個考科：145,639 個 span 小於該行母體，其中比例 ≥ 0.78 的，
**68,431 個在 dcy 0 或 −1**（一般小字），**10,684 個在 +2 到 +4**（化學式）。

**兩種風格，所以要兩組門檻。** 單一組一定失掉一種：

| 風格 | 字級 | 比例 | 量到的位移 | 例子 |
|---|---|---|---|---|
| 緊 | 5.5pt / 11pt | 0.50 | `³⁻` −3.87、`₄` +1.66 | `[K⁺]－[PO₄³⁻]－[HCO₃⁻]` |
| 鬆 | 7.4pt / 9pt | 0.82 | `₃` +2.0、`₂` +3.8 | `CH₃(CH₂)₁₁OR` |

`0.75/±1.0` 把鬆風格壓平；`0.90/±2.0` 把緊風格壓平。判準是兩者的**聯集**，而且
母體自己的比例（`_BODY_SIZE_RATIO = 0.75`）要和收錄底線（`_OFFSET_MAX_SIZE_RATIO = 0.90`）
**分開**——把一個常數拿去做兩件事，會讓 0.82 比例的下標把基線拉向自己，
反而把要找的 span 藏起來。

**要求「每個字元都可對應」，不是「至少一個」。** `any()` 會壞：混了可對應與不可對應字元的
span 會被**轉一半**，全庫量到把普通數字的位數變成上標——`41.` → `⁴¹.`、`1c` → `₁c`、
`-0.2t` → `⁻⁰.²t`，共 **240 個 span**。用 `all()`，**4,546** 個會轉、**4,550** 個不轉；
不轉的是選項標記（`A.`/`B.`/`C.`/`D.`，本來就不該轉）、`®`，以及沒有下標形的符號
（`max`、`p`、`M`、`Cr`）。放著不動是誠實，轉一半不是。

驗收：全庫 **4,035 個下標、2,249 個上標**字元，**0** 個「數字後接 `.` 被轉」，
**3,516/3,516** 卷兩引擎一致。

### §30.6 重建佇列不可以弄丟審題者的決定

這是**無聲的資料遺失**。審核事件由 UI 寫進**佇列目錄**的
`review-ui/question_review_events.jsonl`，而重建佇列到新目錄會在 33,150 筆新資料旁
寫一個全新的空檔。審題者的 51 個決定消失，而且不會報錯——佇列只是回到未審狀態。

`review_run.sh` 把 run 目錄描述為「自足」，這是真的，也正是陷阱：
自足的意思就是**重建會丟掉它**。舊佇列（`qbr-live-final`、`-stripfix`、`-stripfix2`）
**根本沒有事件檔**，所以遺失早就反覆發生過，看起來卻像「沒有人審過」。

修法在 `build_review_queue.py`：

- **六條事件流都要帶**，不只 question 那一條。
- **`--carry-from` 預設就是 `--out` 自己**，所以在原地重建不可能弄丟，即使沒人記得這個旗標。
  把**舊**佇列也傳進去就會合併——這就是重建到新目錄時保住上一版歷史的方法。
- **去重，並回報 `carried` 與 `orphaned`。** `candidate_key` 不在新佇列裡的記錄要回報，
  不能默默丟掉；orphaned 不等於錯。
- **用截斷（`"w"`），不要附加（`"a"`）。** 第一版用附加，於是原地重建把檔案讀進來又接在自己
  後面：**45 筆變成 90 筆**。這個 bug 會讓修法看起來有效，卻在每次重建時翻倍。
- **改進的 UI 取代上一版。** `v2.html` 原地修改，不開分支，因為審題者的決定以
  `candidate_key` 為鍵，第二個 UI 就是第二個會分岐的地方。

驗收：原地重建**幂等**——51 筆連續 3 次重建都穩定；來源每一筆都在 carried 集合裡。
